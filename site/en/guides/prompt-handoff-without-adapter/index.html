WATCH TECHNICAL GUIDE / SESSION HANDOFF

Using watch prompt When There Is No Adapter

When the target tool has no adapter or its native format just changed, run watch prompt <session-id> to build a read-only Markdown handoff. It writes no session files and starts no CLI; trimming counts and degradations go into the document and the --json findings, and the target must treat it as a summary, not a native session.

watch prompt turns local native session records into a Markdown summary handoff without writing any file or launching the target CLI. The target does not inherit native resume, and every trim and source state is written into the document and findings.

Published: 2026-11-18 Modified: 2026-11-18 Applies to: Watch v0.1.162
When to use this path

The three native handoff paths (launcher, chained handoff and official Codex import) require an adapter and a verifiable target format. When the target CLI has no adapter yet, its native format just changed, or you only need to hand context to a web assistant, use watch prompt to produce a read-only summary. It is not a native session, only copyable and reviewable handoff material.

watch prompt reads only the source assistant local session record and renders turns, tool events and a work manifest into Markdown. The header names the source assistant, session ID, source file, working directory, worktree type and current branch; the body states how many turns were trimmed, what was omitted and whether usage may be undercounted. The command writes no session files, opens no database and launches no CLI.

  1. Step 1: Identify the source session and directory

    Pass the session ID explicitly, or pass --cwd and omit the ID. Without an ID, Watch picks the newest readable session in the current directory and marks it as auto-picked in the header; when unsure, name the ID so another session is not mistaken for the source.

  2. Step 2: Choose a profile and window

    --profile minimal|standard|verbose|full controls how much text and how many tool events are expanded. --last N keeps only the newest N user turns and drops the original task description, which the document states. --since-compact starts at the latest compaction summary; when no usable summary exists it does not trim and says so.

  3. Step 3: Review findings and source state

    With --json the result includes markdown, findings and warnings. degraded means the downgrade was disclosed, skipped means content was omitted by your options. The source state, bad lines, usage and branch lines in the document tell you whether it is safe to hand over. An unavailable source working directory is returned as sourceCwd: { state } (missing, not-directory, denied or unknown, with reason for unknown); a healthy directory emits no such field. A normal repository root returns a structured sourceBranch ({ branch, repoRoot }; a detached HEAD returns { detached: true, repoRoot }) and a linked worktree returns sourceWorktree ({ mainWorktree, branch }). If the source file size or modification time changes between checks, sourceDrift ({ from, to, growth }) reports byte counts and growth direction. This does not establish which records made it into the document. Explicitly failed tool calls are returned as failedAttempts (tool, path or command and count, never tool output), with the 失败与中断 (Failures and interruptions) section in the document.

  4. Step 4: State that it is a summary handoff

    Paste the Markdown or save it as a file and tell the target assistant in the first turn that this is a summary handoff, not a native session. The target cannot resume natively, and tool calls, reasoning and attachments may have been trimmed; anything omitted cannot be recovered from the document.

# 1. Auto-pick the newest session in the current directory at the standard profile npm run watch -- prompt --cwd /abs/project # 2. Name the session and keep only the newest 5 user turns npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. Emit JSON to review findings with the document npm run watch -- prompt <session-id> --cwd /abs/project --json
Boundaries

1. Read-only: it writes no session files, opens no local database and launches no target CLI; you decide how to deliver the Markdown. 2. A summary is not a native session: tool calls, reasoning and attachments may be trimmed, and omitted parts cannot be recovered from the document. 3. Trimming is counted: profile, --last and --since-compact omissions go into the body and findings; when no summary exists it does not trim and says so. 4. A 0-turn or damaged source is not reported as success: the body states an empty source or bad lines, and unreadable usage or bad-line counts are marked as possibly undercounted or unconfirmed.

Frequently Asked Questions

Does watch prompt write into the target tool session?

No. It only reads the source record and prints Markdown; it writes no target session file, opens no database and launches no CLI. When you need native resume in the target, use the launcher or chained path for that adapter; the only official import path is Claude Code to Codex desktop.

Why does the document say the first task description was not kept?

With --last N, Watch starts at the Nth user turn from the end, so earlier turns, including the original task description, are omitted. Drop --last for full background, or use --since-compact with a larger profile; the body lists each trim that actually happened.

Can the target assistant continue exactly like a native session?

No. It receives a summary document without native resume and cannot see trimmed tool execution detail. Ask it in the first turn to restate the task goal and current branch, and only then assign edits.
