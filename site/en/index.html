UNDER THE HOOD
Core Mechanisms
Protection is route-specific. A narrow check is not a universal safety guarantee. The desktop app has four views (session handoff, handoff history, supported routes, settings) with light, dark and system appearance.
01
Locate the source and cwd
Find stored records by native session ID and preserve the actual cwd. Existing worktrees are not silently replaced with the repository root.
02
Confirm official imports
The Codex route binds the target directory and configuration, with an execution journal and persistent lock. Uncertain outcomes are queried, not blindly resubmitted.
03
Expose format limitations
Transfer recorded messages and events into the target format. Preservation varies; an internal round-trip is not proof of native continuation.
04
Separate import from opening
If opening fails after import, retry opening only. A failed terminal launch falls back to copying the command without another transfer.

DEVELOPER WORKFLOW
Run From Source
Run the CLI from the repository or build the desktop app. Repository access is required. No global npm package is published.
Node ≥ 22.13 · Desktop builds also require Rust / Tauri
$git clone https://github.com/can4hou6joeng4/Watch.git
$cd Watch && npm install
$npm run watch -- status --json
$npm run watch -- import-codex prepare <claude-id> --cwd /abs/project --desktop-project --experimental --json
$npm --prefix desktop install
$npm run desktop:dev
$cd desktop && npx tauri build
Missing tsx? Run npm install first. A node:sqlite error requires checking the Node version.

QUESTIONS & BOUNDARIES
Questions
Claude Code hit its limit mid-task. How do I continue?
Enter the source session ID in Watch, check the detected working directory and pick a target agent. Claude → Codex shows the official project-first import preview and writes only after you confirm, then opens the target separately; other targets use the existing CLI adapters. Watch does not bypass usage limits and does not move code; it transfers the saved session record.
How do I switch from Claude Code to Codex and resume the same session?
Two entry points: in the desktop app select the source session and click the OpenAI Codex card (official single-session import: prepare → confirm → open), or run watch import-codex prepare <claude-id> --cwd <project> --desktop-project --experimental followed by confirm. The project must already exist in Codex Desktop. Tool records may become text on the Codex side and model continuation is outside the validated scope.
My Claude Code context window is full. Does Watch compact it?
No. Compacting or clearing context is Claude Code's own /compact and /clear. Watch moves the saved session record as a whole into another agent; the target session starts from that record and the original session is untouched. Whether it fits depends on the target tool's context window.
Where are Claude Code, Codex and OpenCode session files, and how do I resume a previous conversation?
Claude Code: ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl, resume with claude --resume <id>. Codex: ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl, resume with codex resume <id>. OpenCode: ~/.local/share/opencode/opencode.db, resume with opencode -s <id>. Watch looks these up by session ID, shows the owning working directory, and lists chained handoffs for that directory under Handoff History.
I use both Claude Code and Codex. How do I move between them without losing context?
Watch does not rank the two. With both installed and authenticated, hand sessions across: Claude → Codex uses the official import preview, Codex → Claude uses the CLI adapter conversion; both keep the working directory. Some events may be degraded between formats, and the result lists what was degraded.
Does history pass through a Watch cloud server?
Watch has no relay server of its own. Some native session creation routes invoke the target CLI and may access its network services. Model continuation also follows that service’s privacy and model rules. Local conversion does not mean an entirely offline workflow.
Is conversion lossless or risk-free?
No. New files and whole-file replacements have atomic writes and parse-back checks, while some append paths have different protections. Official Codex imports use their own journal, target lock and read-back verification. See the architecture for exact boundaries.

      
OFFICIAL ENTRY / NOT INTEGRATED
Antigravity CLI: same-product resume and import
Official entry points reviewed; not integrated into Watch. These are Antigravity operations, not Watch conversion commands.
Officially documented / Not Watch-validated
01
Resume a specific CLI conversation
agy --conversation <conversation-id>
Resumes an existing Antigravity CLI conversation ID. It is not an importer for Claude, Codex or desktop conversations.
02
Continue the latest workspace conversation
agy -c
Looks up the latest conversation for the current working directory. Missing or deleted history can start a new conversation, so this is not a side-effect-free status check.
03
Import from Antigravity 2.0
/resume
Switch to the Antigravity tab in the CLI session picker, select a desktop conversation and confirm the import. Official documentation describes cloned history, context and tool trajectories. Watch has not natively validated it and has no external-agent import contract.
