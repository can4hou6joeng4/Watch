UNDER THE HOOD
Mekanisme Inti
Perlindungan bersifat per rute. Pemeriksaan sempit bukan jaminan keamanan universal. Aplikasi desktop memiliki empat tampilan (serah terima sesi, riwayat serah terima, rute yang didukung, pengaturan) dengan tampilan terang, gelap, dan sistem.
01
Temukan sumber dan cwd
Temukan catatan tersimpan berdasarkan ID sesi native dan pertahankan cwd yang sebenarnya. Worktree yang ada tidak diam-diam diganti dengan akar repositori.
02
Konfirmasi impor resmi
Rute Codex mengikat direktori dan konfigurasi target, dengan jurnal eksekusi dan kunci persisten. Hasil yang tidak pasti ditanyakan, bukan dikirim ulang secara buta.
03
Tampilkan batasan format
Pindahkan pesan dan peristiwa yang tercatat ke format target. Tingkat pelestarian berbeda-beda; round-trip internal bukan bukti kelanjutan native.
04
Pisahkan impor dari pembukaan
Jika pembukaan gagal setelah impor, coba ulang hanya pembukaannya. Peluncuran terminal yang gagal kembali ke penyalinan perintah setelah memeriksa karakter kontrol tanpa transfer lain.

ANSWERS FIRST
Panduan
Setiap panduan dibuka dengan jawaban yang berdiri sendiri, lalu langkah-langkahnya. Watch tidak melewati batas dan tidak memeringkat model.
Melanjutkan di Codex Setelah Claude Code Mencapai Batas Penggunaan
Saat Claude Code melaporkan batas lima jam atau mingguan, /compact tidak memulihkan kuota. Watch hanya membaca ~/.claude/projects/<encoded-cwd>/<session>.jsonl lokal, memeriksa direktori kerja, dan menyalin catatan itu ke Codex. Berkas asli tetap tidak berubah. Peristiwa alat dapat menjadi teks.
Baca panduan
Panduan Serah Terima Sesi Dua Arah OpenCode, Claude & Codex
OpenCode menyimpan sesi di ~/.local/share/opencode/opencode.db. WATCH_OPENCODE_DB mengarahkan Watch ke berkas lain. Watch menulis sesi, pesan, dan bagian dalam satu transaksi SQLite dan mengembalikan jika gagal. Bidang alat yang tidak didukung menjadi teks. Balasan berikutnya bergantung pada model yang Anda konfigurasikan.
Baca panduan
Jendela Konteks Penuh vs Batas Penggunaan di Claude Code: Panduan Praktis
Jendela konteks penuh berarti percakapan ini terlalu panjang: jalankan /compact atau /clear di dalam Claude Code. Batas akun menyebut waktu pengaturan ulang, dan /compact tidak berpengaruh saat itu. Watch tidak memperbesar jendela maupun memulihkan kuota. Ia menyalin sesi tersimpan ke agen lain yang masih dapat berjalan.
Baca panduan
Apa yang diubah Claude Opus 5.5 pada batas lima jam, dan apa yang dilakukan saat Anda masih terbatas
Opus 5.5 menaikkan batas lima jam pada Pro, Max, Team, dan Enterprise berbasis kursi, serta menambahkan satu pengaturan ulang yang dapat Anda simpan. Ia tidak menghapus batas. Watch tidak membaca atau menaikkan kuota Claude. Serahkan sesi tersimpan ke Codex hanya setelah pengaturan ulang resmi itu masih belum cukup.
Baca panduan
Mengapa resume membuka sesi kosong: mendeteksi dan memulihkan sesi 0 giliran
Sesi kosong setelah resume biasanya berarti berkas tidak lagi punya giliran: sesi kosong sah buatan watch new, konten yang dihapus menyisakan header pengganti, atau berkas 0 byte. Periksa jumlah giliran pada baris ujung rantai di watch status. Watch tidak membangun ulang riwayat untuk Anda; pulihkan berkas dari cadangan, ikat ulang ke sesi lain, atau mulai rantai baru.
Baca panduan
Memakai watch prompt saat tidak ada adaptor
Bila alat tujuan belum punya adaptor atau format native-nya baru berubah, jalankan watch prompt <session-id> untuk menyusun serah terima Markdown hanya-baca. Perintah ini tidak menulis berkas sesi dan tidak memulai CLI; jumlah pemotongan dan degradasi masuk ke dokumen dan findings --json, dan tujuan harus memperlakukannya sebagai ringkasan, bukan sesi native.
Baca panduan
Sesi Codex tersisa sebagai .jsonl.zst: batas baca dan pemulihan di Watch
Setelah Codex memadatkan thread lokal, rollout hanya tersisa sebagai .jsonl.zst; Watch tidak membaca format terpadatkan, sehingga sesinya tidak muncul di daftar mana pun. Gunakan watch doctor untuk melihat jumlah tak teratribusi dan lanjutkan thread di Codex untuk memicu pemekaran ulang. Salinan 0 byte telah kehilangan isinya; pulihkan dari cadangan. Jangan menghapus atau mengganti nama berkas .zst.

QUESTIONS & BOUNDARIES
Pertanyaan
Claude Code mencapai batasnya di tengah tugas. Bagaimana saya melanjutkan?
Masukkan ID sesi sumber di Watch, periksa direktori kerja yang terdeteksi, lalu pilih agen target. Claude → Codex menampilkan pratinjau impor resmi proyek-dahulu dan menulis hanya setelah Anda mengonfirmasi, lalu membuka target secara terpisah; target lain memakai adaptor CLI yang ada. Watch tidak melewati batas penggunaan dan tidak memindahkan kode; ia mentransfer catatan sesi tersimpan.
Bagaimana saya beralih dari Claude Code ke Codex dan melanjutkan sesi yang sama?
Dua titik masuk: di aplikasi desktop pilih sesi sumber dan klik kartu OpenAI Codex (impor resmi satu sesi: prepare → confirm → open), atau jalankan watch import-codex prepare <claude-id> --cwd <project> --desktop-project --experimental lalu confirm. Proyek harus sudah ada di Codex Desktop. Catatan alat dapat menjadi teks di sisi Codex, dan kelanjutan model berada di luar lingkup yang divalidasi.
Jendela konteks Claude Code saya penuh. Apakah Watch memadatkannya?
Tidak. Memadatkan atau mengosongkan konteks adalah /compact dan /clear milik Claude Code sendiri. Watch memindahkan catatan sesi tersimpan secara utuh ke agen lain; sesi target dimulai dari catatan itu dan sesi asli tidak disentuh. Apakah muat bergantung pada jendela konteks alat target.
Di mana berkas sesi Claude Code, Codex, dan OpenCode, dan bagaimana saya melanjutkan percakapan sebelumnya?
Claude Code: ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl, lanjutkan dengan claude --resume <id>. Codex: ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl, lanjutkan dengan codex resume <id>. OpenCode: ~/.local/share/opencode/opencode.db, lanjutkan dengan opencode -s <id>. Watch mencarinya berdasarkan ID sesi, menampilkan direktori kerja pemilik, dan mencantumkan serah terima berantai untuk direktori itu di Handoff History.
Mengapa sesi yang tercantum di watch status terbuka kosong setelah resume?
resume hanya membuka sesi yang sudah ada. Sesi kosong biasanya tidak punya giliran tersisa: sesi kosong sah yang dibuat oleh watch new, konten yang dihapus menyisakan header pengganti, atau berkas 0 byte. Periksa jumlah giliran ujung rantai di watch status; Watch menyebutkan alasannya saat bernilai 0. Watch tidak membangun ulang riwayat: pulihkan berkas dari cadangan, ikat ulang ke sesi lain dengan watch adopt, atau mulai rantai baru dengan watch chain new.
Apakah peringatan watch doctor tentang risiko pembersihan Claude Code pasti?
Ini adalah perkiraan dari waktu modifikasi berkas ujung rantai dan cleanupPeriodDays yang ditentukan oleh prioritas pengaturan, bukan bukti penghapusan. Peringatan muncul hanya untuk ujung rantai Claude Code ketika nilai eksplisit berada di bawah standar resmi 30 hari. Nilai pendek yang ditimpa pengaturan berprioritas lebih tinggi tidak lagi dilaporkan, dan bila berkas berprioritas lebih tinggi tidak dapat dibaca, nilai yang lebih rendah tidak dipakai untuk menebak. Worktree dan submodule tidak membaca pengaturan akar repositori dari checkout utama, sehingga perkiraan bisa konservatif. Nilai efektif tetap bergantung pada semua pengaturan yang dimuat Claude Code; --settings dan pengaturan terkelola di luar cakupan. Cadangkan berkas ujung rantai, naikkan retensi, atau ikat ulang dengan watch switch; --strict memperlakukan peringatan sebagai kegagalan.
Saya memakai Claude Code dan Codex. Bagaimana saya berpindah di antara keduanya tanpa kehilangan konteks?
Watch tidak memeringkat keduanya. Jika keduanya terpasang dan terautentikasi, serahkan sesi antar keduanya: Claude → Codex memakai pratinjau impor resmi, Codex → Claude memakai konversi adaptor CLI; keduanya mempertahankan direktori kerja. Sebagian peristiwa dapat terdegradasi antar format, dan hasilnya mencantumkan apa yang terdegradasi.
Apakah riwayat melewati server cloud Watch?
Watch tidak memiliki server relay sendiri. Beberapa rute pembuatan sesi native memanggil CLI target dan dapat mengakses layanan jaringannya. Kelanjutan model juga mengikuti aturan privasi dan model layanan itu. Konversi lokal tidak berarti alur kerja yang sepenuhnya offline.
Apakah konversi tanpa kehilangan atau bebas risiko?
Tidak. Berkas baru dan penggantian seluruh berkas memiliki penulisan atomik dan pemeriksaan parse-ulang, sementara beberapa jalur penambahan memiliki perlindungan berbeda. Impor Codex resmi memakai jurnal, kunci target, dan verifikasi baca-ulang sendiri. Lihat arsitektur untuk batas yang tepat.
