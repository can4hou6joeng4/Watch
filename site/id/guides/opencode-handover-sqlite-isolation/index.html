Panduan Serah Terima Sesi Dua Arah OpenCode, Claude & Codex

OpenCode menyimpan sesi di ~/.local/share/opencode/opencode.db. WATCH_OPENCODE_DB mengarahkan Watch ke berkas lain. Watch menulis sesi, pesan, dan bagian dalam satu transaksi SQLite dan mengembalikan jika gagal. Bidang alat yang tidak didukung menjadi teks. Balasan berikutnya bergantung pada model yang Anda konfigurasikan.

Saat beralih dari agen cloud komersial ke model sumber terbuka lokal di OpenCode (atau menyerahkan kembali ke agen cloud), panduan ini menjelaskan cara memakai Watch untuk serah terima dua arah dengan isolasi data transaksional SQLite.

Diterbitkan: 2026-09-21 Diperbarui: 2026-10-14 Berlaku untuk: Watch v0.1.432
Batas Operasional Utama

OpenCode memakai satu basis data SQLite relasional (bawaan ~/.local/share/opencode/opencode.db) untuk penyimpanan sesi, dengan integritas transaksional ACID dan kueri terstruktur. Saat Anda ingin memindahkan tugas sensitif ke model sumber terbuka yang dihosting lokal (melalui Ollama atau vLLM di OpenCode) atau menyerahkan kembali ke model cloud terdepan (Claude/Codex), Watch menyediakan jembatan dua arah yang telah diverifikasi.

Berbeda dari alat yang hanya mengandalkan berkas JSONL append-only, OpenCode menata sesi di tabel relasional ternormalisasi termasuk sessions, messages, dan parts. Perubahan eksternal langsung dapat merusak batasan foreign key. Watch memetakan abstraksi UnifiedTurn secara bersih ke skema relasional OpenCode sambil mempertahankan konteks direktori yang tepat (cwd) dan stempel waktu.

  1. Langkah 1: Identifikasi ID sesi sumber dan direktori kerja

    Temukan ID sesi aktif Anda. Claude Code menyimpan berkas di ~/.claude/projects/; Codex di ~/.codex/sessions/; OpenCode mengindeks sesi melalui ID unik global. Pastikan direktori kerja adalah jalur absolut agar batas proyek tetap selaras.

  2. Langkah 2: Periksa status basis data target (Check)

    Jalankan --check untuk melihat pratinjau tujuan dan giliran yang tertunda, lalu periksa writable, blocked, dan warnings. Bila ada giliran tertunda, pra-periksa OpenCode memeriksa tata letak penyimpanan dan status pembalikan target yang ada; tata letak 2.x bersifat hanya-baca. Perintah ini tidak menulis ke sesi tujuan, tidak menguji izin tulis, dan tidak mengambil kunci tulis SQLite, sehingga tidak dapat menjamin penulisan berikutnya bebas dari perubahan bersamaan.

  3. Langkah 3: Jalankan serah terima dua arah (Handoff)

    Pilih sesi sumber di Watch Desktop dan targetkan OpenCode, atau jalankan perintah CLI open. Watch mengekstrak giliran inkremental, menjalankan transaksi SQLite atomik pada sessions, messages, dan parts, lalu mengeluarkan ID sesi tujuan.

  4. Langkah 4: Lanjutkan sesi secara native di OpenCode (Resume)

    Setelah konversi, jalankan opencode -s <session-id> di direktori kerja atau gunakan tombol luncurkan di Watch Desktop. OpenCode memuat percakapan yang tercatat di direktori itu.

# 1. Pratinjau tujuan dan giliran tertunda; periksa penjaga tata letak dan pembalikan npm run watch -- open <claude-session-id> --to opencode --check --json # 2. Serah terima: kirim sesi ke basis data SQLite OpenCode npm run watch -- open <claude-session-id> --to opencode --json # 3. Serah terima balik: dari OpenCode kembali ke Claude atau Codex npm run watch -- open <opencode-session-id> --to claude --json
Skema relasional OpenCode dan isolasi transaksi SQLite

Penyimpanan sesi OpenCode (~/.local/share/opencode/opencode.db) tersusun atas tiga tabel relasional inti: • session: ID sesi, judul, direktori kerja absolut, dan stempel waktu • message: memetakan session_id, role (user / assistant), dan waktu pembuatan • part (pada tata letak 2.x, session_v2, session_message, session_part): menyimpan potongan teks, blok kode, dan representasi terstruktur pemanggilan alat WATCH_OPENCODE_DB=/tmp/isolated.db mengarahkan penulisan ke basis data SQLite terpisah. Transfer berjalan dalam transaksi SQLite atomik dan dibatalkan sepenuhnya bila terputus.

Batasan Keamanan & Pernyataan

1. Isolasi basis data dan cadangan: Watch secara bawaan beroperasi pada ~/.local/share/opencode/opencode.db dan memakai WATCH_OPENCODE_DB untuk lingkungan pengujian. Penulisan adalah satu transaksi SQLite dan di-rollback jika gagal. 2. Representasi panggilan alat: catatan dipetakan antar skema; parameter proprietari yang tidak didukung menjadi teks terstruktur. 3. Kelanjutan model: Watch menulis catatan sesi yang sudah tersimpan dan direktori kerja. Watch tidak menjamin setiap peristiwa alat tetap utuh. Balasan berikutnya bergantung pada model yang dikonfigurasi.

Pertanyaan umum

Apa keunggulan penyimpanan SQLite OpenCode dibanding JSONL?

Transaksi SQLite mencatat penulisan sesi sebagai satu kesatuan dan membatalkannya bila gagal. SQLite tidak menyediakan kunci tulis tingkat baris; penulis bersamaan masih dapat berebut basis data. WATCH_OPENCODE_DB mengalihkan baca dan tulis Watch ke basis data uji terpisah; ia tidak otomatis mengganti basis data yang dipakai klien OpenCode native.

Apakah pemikiran penalaran model khusus dipertahankan saat diserahkan keluar dari OpenCode?

Watch menyalin prompt pengguna, teks asisten, jejak pemikiran, dan keluaran alat yang dapat dipetakan. Bidang alat yang tidak didukung menjadi teks, jadi salinan ini bukan replika utuh dari baris OpenCode.

Bagaimana Watch mencegah ketidakcocokan direktori kerja?

Watch mencatat cwd absolut yang dipilih dan mengembalikan perintah resume lengkap yang berpindah direktori sebelum menjalankan opencode -s <session-id>. Periksa direktori kerja dan pakai perintah lengkap itu; opencode -s saja tidak menyertakan perpindahan direktori dari Watch. Catatan cwd bukan sandbox akses berkas, jadi periksa juga jalur dan izin di alat tujuan.
