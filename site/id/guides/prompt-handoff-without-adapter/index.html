Memakai watch prompt saat tidak ada adaptor

Bila alat tujuan belum punya adaptor atau format native-nya baru berubah, jalankan watch prompt <session-id> untuk menyusun serah terima Markdown hanya-baca. Perintah ini tidak menulis berkas sesi dan tidak memulai CLI; jumlah pemotongan dan degradasi masuk ke dokumen dan findings --json, dan tujuan harus memperlakukannya sebagai ringkasan, bukan sesi native.

watch prompt mengubah catatan sesi native lokal menjadi serah terima Markdown ringkasan tanpa menulis berkas atau meluncurkan CLI tujuan. Tujuan tidak mewarisi resume native, dan setiap pemotongan serta keadaan sumber dicatat di dokumen dan findings.

Diterbitkan: 2026-11-18 Diperbarui: 2026-11-18 Berlaku untuk: Watch v0.1.492
Kapan memakai jalur ini

Tiga jalur serah terima native (launcher, serah terima berantai, dan impor resmi Codex) memerlukan adaptor dan format tujuan yang dapat diverifikasi. Bila CLI tujuan belum punya adaptor, format native-nya baru berubah, atau Anda hanya perlu menyerahkan konteks ke asisten web, gunakan watch prompt untuk menghasilkan ringkasan hanya-baca. Itu bukan sesi native, melainkan materi serah terima yang dapat disalin dan ditinjau.

watch prompt hanya membaca catatan sesi lokal asisten sumber dan merender giliran, peristiwa alat, serta manifes pekerjaan menjadi Markdown. Header menyebut asisten sumber, ID sesi, berkas sumber, direktori kerja, jenis worktree, dan branch saat ini; isi menyatakan berapa giliran dipotong, apa yang dihilangkan, dan apakah pemakaian mungkin kurang terhitung. Perintah ini tidak menulis berkas sesi, tidak membuka basis data, dan tidak meluncurkan CLI.

  1. Langkah 1: identifikasi sesi sumber dan direktorinya

    Berikan ID sesi secara eksplisit, atau berikan --cwd tanpa ID. Tanpa ID, Watch memilih sesi terbaca terbaru di direktori saat ini dan menandainya sebagai dipilih otomatis di header; bila ragu, sebutkan ID-nya agar sesi lain tidak disalahartikan sebagai sumber.

  2. Langkah 2: pilih profil dan jendela

    --profile minimal|standard|verbose|full mengatur seberapa banyak teks dan peristiwa alat yang dibentangkan. --last N hanya menyimpan N giliran pengguna terbaru dan membuang deskripsi tugas awal, dan dokumen menyatakannya. --since-compact mulai dari ringkasan pemadatan terbaru; bila tidak ada ringkasan yang berguna, ia tidak memotong dan mengatakannya.

  3. Langkah 3: tinjau findings dan keadaan sumber

    --json menyertakan markdown, findings, dan warnings dalam hasil. degraded berarti degradasi telah diungkapkan, skipped berarti konten dihilangkan oleh opsi Anda. Baris keadaan sumber, baris rusak, pemakaian, dan branch di dokumen menunjukkan apakah aman untuk diserahterimakan. Direktori kerja sumber yang tidak tersedia dikembalikan sebagai sourceCwd: { state } (missing, not-directory, denied, atau unknown, dengan reason untuk unknown); direktori yang sehat tidak memunculkan bidang itu. Akar repositori normal mengembalikan sourceBranch ({ branch, repoRoot }; HEAD terlepas mengembalikan { detached: true, repoRoot }), dan worktree tertaut mengembalikan sourceWorktree ({ mainWorktree, branch }). Bila ukuran atau waktu modifikasi berkas sumber berubah di antara pemeriksaan, sourceDrift ({ from, to, growth }) melaporkan jumlah byte dan arah pertumbuhan. Itu tidak membuktikan catatan mana yang masuk ke dokumen. Pemanggilan alat yang gagal secara eksplisit dikembalikan sebagai failedAttempts (alat, jalur atau perintah dan jumlahnya, tidak pernah keluaran alat), dengan bagian 「Kegagalan dan interupsi (Failures and interruptions)」 di dokumen. Saat render, ikhtisar perubahan juga memeriksa apakah berkas yang didaftar masih ada di direktori sesi: berkas yang terkonfirmasi hilang ditandai tidak lagi di disk, yang tidak dapat dipastikan ditandai belum diverifikasi, berkas yang dihapus atau dipindah oleh patch sesi diberi label demikian, dan jalur di luar direktori sesi dihitung terpisah; judul bagian menyebutkan berapa yang diperiksa, atau mengapa pemeriksaan tidak berjalan. --json menambahkan manifestDisk (checked, missing, unverified, outside, removed) agar skrip tidak pernah membaca bidang yang tidak ada sebagai 「semua hadir」. Panggilan alat yang belum selesai dan akhir sesi yang menggantung dilaporkan sebagai stats.danglingToolCalls, stats.unansweredTail, dan finding yang sesuai; yang pertama menghitung seluruh sesi, yang kedua hanya bila giliran pengguna terakhir berisi teks nyata. Keduanya dijelaskan di metadata dokumen dan bagian Continue working, dengan kolom yang sama di --json.

  4. Langkah 4: nyatakan bahwa ini serah terima ringkasan

    Tempel Markdown atau simpan sebagai berkas dan beri tahu asisten tujuan pada giliran pertama bahwa ini serah terima ringkasan, bukan sesi native. Tujuan tidak dapat melanjutkan secara native, dan pemanggilan alat, penalaran, serta lampiran mungkin telah dipotong; yang dihilangkan tidak dapat dipulihkan dari dokumen.

# 1. Pilih otomatis sesi terbaru di direktori saat ini dengan profil standard npm run watch -- prompt --cwd /abs/project # 2. Sebutkan sesinya dan simpan hanya 5 giliran pengguna terbaru npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. Keluarkan JSON untuk meninjau findings bersama dokumen npm run watch -- prompt <session-id> --cwd /abs/project --json
Batas

1. Hanya-baca: tidak menulis berkas sesi, tidak membuka basis data lokal, dan tidak meluncurkan CLI tujuan; Anda yang memutuskan cara menyerahkan Markdown. 2. Ringkasan bukan sesi native: pemanggilan alat, penalaran, dan lampiran mungkin dipotong, dan bagian yang dihilangkan tidak dapat dipulihkan dari dokumen. 3. Pemotongan dihitung: penghilangan oleh profil, --last, dan --since-compact masuk ke isi dan findings; bila tidak ada ringkasan, ia tidak memotong dan mengatakannya. 4. Sumber 0 giliran atau rusak tidak dilaporkan sebagai sukses: isi menyatakan sumber kosong atau baris rusak, dan pemakaian atau jumlah baris yang tidak terbaca ditandai mungkin kurang terhitung atau belum dipastikan.

Pertanyaan umum

Apakah watch prompt menulis ke sesi alat tujuan?

Tidak. Ia hanya membaca catatan sumber dan mencetak Markdown; tidak menulis berkas sesi tujuan, tidak membuka basis data, dan tidak meluncurkan CLI. Bila Anda membutuhkan resume native di tujuan, gunakan launcher atau jalur berantai untuk adaptor itu; satu-satunya jalur impor resmi adalah Claude Code ke Codex Desktop.

Mengapa dokumen menyatakan deskripsi tugas awal tidak dipertahankan?

Dengan --last N, Watch mulai dari giliran pengguna ke-N dari akhir, sehingga giliran sebelumnya, termasuk deskripsi tugas awal, dihilangkan. Hapus --last untuk latar belakang penuh, atau pakai --since-compact dengan profil lebih besar; isi mendaftar setiap pemotongan yang benar-benar terjadi.

Bisakah asisten tujuan melanjutkan persis seperti sesi native?

Tidak. Ia menerima dokumen ringkasan tanpa resume native dan tidak melihat detail eksekusi alat yang dipotong. Minta ia pada giliran pertama mengulang tujuan tugas dan branch saat ini, baru setelah itu berikan tugas penyuntingan.
