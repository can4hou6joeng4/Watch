UNDER THE HOOD
Mécanismes essentiels
La protection dépend du parcours. Un contrôle étroit n’est pas une garantie de sûreté universelle. L’application Desktop a quatre vues (relais de session, historique des relais, parcours pris en charge, réglages) avec apparence claire, sombre et système.
01
Localiser la source et le cwd
Retrouvez les enregistrements par ID de session natif et conservez le cwd réel. Les worktrees existants ne sont pas remplacés silencieusement par la racine du dépôt.
02
Confirmer les importations officielles
Le parcours Codex lie le répertoire cible et la configuration, avec un journal d’exécution et un verrou persistant. Les résultats incertains sont interrogés, pas resoumis à l’aveugle.
03
Exposer les limites de format
Transférez les messages et événements enregistrés vers le format cible. La conservation varie ; un aller-retour interne ne prouve pas une poursuite native.
04
Séparer l’importation de l’ouverture
Si l’ouverture échoue après l’importation, ne réessayez que l’ouverture. Un lancement de terminal échoué se rabat sur la copie d’une commande après vérification des caractères de contrôle, sans nouveau transfert.

ANSWERS FIRST
Guides
Chaque guide s’ouvre sur une réponse autonome, puis détaille les étapes. Watch ne contourne pas les limites et ne classe pas les modèles.
Continuer dans Codex après qu’Claude Code a atteint sa limite d’usage
Quand Claude Code signale une limite de cinq heures ou hebdomadaire, /compact ne restaure pas le quota. Watch ne lit que le fichier local ~/.claude/projects/<encoded-cwd>/<session>.jsonl, vérifie le répertoire de travail et copie cet enregistrement dans Codex. Le fichier d’origine reste inchangé. Les événements d’outils peuvent devenir du texte.
Lire le guide
Guide de relais de session bidirectionnel OpenCode, Claude et Codex
OpenCode conserve les sessions dans ~/.local/share/opencode/opencode.db. WATCH_OPENCODE_DB oriente Watch vers un autre fichier. Watch écrit sessions, messages et parts dans une seule transaction SQLite et annule en cas d’échec. Les champs d’outils non pris en charge deviennent du texte. Les réponses ultérieures dépendent du modèle que vous configurez.
Lire le guide
Fenêtre de contexte pleine et limites d’usage dans Claude Code : guide pratique
Une fenêtre de contexte pleine signifie que cette conversation est trop longue : lancez /compact ou /clear dans Claude Code. Une limite de compte indique une heure de réinitialisation, et /compact n’y change rien. Watch n’agrandit pas la fenêtre et ne restaure pas le quota. Il copie la session enregistrée vers un autre agent qui peut encore s’exécuter.
Lire le guide
Ce que Claude Opus 5.5 change pour les limites de cinq heures, et que faire si vous êtes encore plafonné
Opus 5.5 relève la limite de cinq heures sur Pro, Max, Team et Enterprise par siège, et ajoute une réinitialisation que vous pouvez conserver. Il ne supprime pas la limite. Watch ne lit ni ne relève le quota Claude. Ne relayer la session enregistrée vers Codex qu’une fois que cette réinitialisation officielle ne suffit toujours pas.
Lire le guide
Pourquoi la reprise ouvre une session vide : détecter et récupérer les sessions à 0 tour
Une session vide après la reprise signifie généralement que le fichier n'a plus de tours : une session vide légitime créée par watch new, un contenu effacé ne laissant qu'un en-tête factice, ou un fichier de 0 octet. Vérifiez le nombre de tours sur la ligne de pointe de chaîne dans watch status. Watch ne reconstruit pas l'historique à votre place ; restaurez le fichier depuis une sauvegarde, rattachez une autre session, ou démarrez une nouvelle chaîne.
Lire le guide
Utiliser watch prompt sans adaptateur
Lorsque l'outil cible n'a pas d'adaptateur ou que son format natif vient de changer, exécutez watch prompt <session-id> pour construire une passation Markdown en lecture seule. Il n'écrit aucun fichier de session et ne démarre aucune CLI ; le nombre de troncatures et les dégradations figurent dans le document et les findings --json, et la cible doit le traiter comme un résumé, pas comme une session native.
Lire le guide
Sessions Codex réduites à un .jsonl.zst : limites de lecture et récupération dans Watch
Après que Codex a compressé un thread local, le rollout ne subsiste que sous forme de .jsonl.zst ; Watch ne lit pas le format compressé, la session n'apparaît donc dans aucune liste. Utilisez watch doctor pour voir le nombre de fichiers non attribuables et poursuivez le thread dans Codex pour déclencher le redéploiement. Une copie de 0 octet a perdu son contenu ; restaurez-la depuis une sauvegarde. Ne supprimez pas et ne renommez pas le fichier .zst.
Lire le guide

QUESTIONS & BOUNDARIES
Questions
Claude Code a atteint sa limite en cours de tâche. Comment continuer ?
Saisissez l’ID de session source dans Watch, vérifiez le répertoire de travail détecté et choisissez un agent cible. Claude → Codex affiche l’aperçu officiel d’importation projet d’abord et n’écrit qu’après votre confirmation, puis ouvre la cible séparément ; les autres cibles utilisent les adaptateurs CLI existants. Watch ne contourne pas les limites d’usage et ne déplace pas le code ; il transfère l’enregistrement de session sauvegardé.
Comment passer de Claude Code à Codex et reprendre la même session ?
Deux points d’entrée : dans l’application Desktop, sélectionnez la session source et cliquez sur la carte OpenAI Codex (importation officielle d’une seule session : prepare → confirm → open), ou lancez watch import-codex prepare <claude-id> --cwd <project> --desktop-project --experimental puis confirm. Le projet doit déjà exister dans Codex Desktop. Les enregistrements d’outils peuvent devenir du texte côté Codex et la poursuite par le modèle est hors du périmètre validé.
Ma fenêtre de contexte Claude Code est pleine. Watch la compacte-t-il ?
Non. Compacter ou effacer le contexte relève de /compact et /clear, propres à Claude Code. Watch déplace l’enregistrement de session sauvegardé dans son ensemble vers un autre agent ; la session cible part de cet enregistrement et la session d’origine n’est pas modifiée. Qu’il tienne dépend de la fenêtre de contexte de l’outil cible.
Où sont les fichiers de session Claude Code, Codex et OpenCode, et comment reprendre une conversation précédente ?
Claude Code : ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl, reprise avec claude --resume <id>. Codex : ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl, reprise avec codex resume <id>. OpenCode : ~/.local/share/opencode/opencode.db, reprise avec opencode -s <id>. Watch les retrouve par ID de session, affiche le répertoire de travail propriétaire et liste les relais enchaînés de ce répertoire sous Historique des relais.
Pourquoi une session listée par watch status s'ouvre-t-elle vide après la reprise ?
resume ouvre seulement une session existante. Une session vide n'a généralement plus de tours : une session vide légitime créée par watch new, un contenu effacé ne laissant qu'un en-tête factice, ou un fichier de 0 octet. Vérifiez le nombre de tours de la pointe de chaîne dans watch status ; Watch indique la raison lorsqu'il est de 0. Watch ne reconstruit pas l'historique : restaurez le fichier depuis une sauvegarde, rattachez une autre session avec watch adopt, ou démarrez une nouvelle chaîne avec watch chain new.
L'avertissement de watch doctor sur le risque de nettoyage de Claude Code est-il certain ?
C'est une estimation calculée à partir de la date de modification du fichier de pointe de chaîne et de cleanupPeriodDays déterminé par la priorité des réglages, pas une preuve de suppression. Elle n'apparaît que pour les pointes de chaîne Claude Code lorsque la valeur explicite est inférieure à la valeur officielle de 30 jours. Une valeur courte écrasée par un réglage de priorité supérieure n'est plus signalée, et lorsqu'un fichier de priorité supérieure est illisible, aucune valeur inférieure n'est utilisée pour deviner. Les worktrees et sous-modules ne lisent pas les réglages à la racine du dépôt du checkout principal, l'estimation peut donc être prudente. La valeur effective dépend encore de tous les réglages chargés par Claude Code ; --settings et les réglages gérés sont hors périmètre. Sauvegardez le fichier de pointe de chaîne, augmentez la rétention, ou rattachez avec watch switch ; --strict traite les avertissements comme des échecs.
J’utilise Claude Code et Codex. Comment passer de l’un à l’autre sans perdre le contexte ?
Watch ne classe pas les deux. Une fois les deux installés et authentifiés, relayer les sessions : Claude → Codex utilise l’aperçu d’importation officiel, Codex → Claude utilise la conversion de l’adaptateur CLI ; les deux conservent le répertoire de travail. Certains événements peuvent être dégradés entre les formats, et le résultat indique ce qui a été dégradé.
L’historique passe-t-il par un serveur cloud Watch ?
Watch n’a pas de serveur relais propre. Certains parcours de création de session native invoquent le CLI cible et peuvent accéder à ses services réseau. La poursuite par le modèle suit aussi les règles de confidentialité et de modèle de ce service. Une conversion locale ne signifie pas un flux entièrement hors ligne.
La conversion est-elle sans perte ni risque ?
Non. Les nouveaux fichiers et les remplacements de fichier entier ont des écritures atomiques et des contrôles de relecture, tandis que certains chemins d’ajout ont des protections différentes. Les importations Codex officielles utilisent leur propre journal, un verrou de cible et une vérification de relecture. Voir l’architecture pour les limites exactes.
