Utiliser watch prompt sans adaptateur

Lorsque l'outil cible n'a pas d'adaptateur ou que son format natif vient de changer, exécutez watch prompt <session-id> pour construire une passation Markdown en lecture seule. Il n'écrit aucun fichier de session et ne démarre aucune CLI ; le nombre de troncatures et les dégradations figurent dans le document et les findings --json, et la cible doit le traiter comme un résumé, pas comme une session native.

watch prompt transforme les enregistrements de session natifs locaux en une passation Markdown récapitulative, sans écrire de fichier ni lancer la CLI cible. La cible n'hérite pas de la reprise native, et chaque troncature et état de source est consigné dans le document et les findings.

Publié: 2026-11-18 Modifié: 2026-11-18 S’applique à: Watch v0.1.409
Quand utiliser cette route

Les trois routes de passation natives (lanceur, passation en chaîne et import officiel Codex) exigent un adaptateur et un format cible vérifiable. Lorsque la CLI cible n'a pas encore d'adaptateur, que son format natif vient de changer, ou que vous voulez seulement confier le contexte à un assistant web, utilisez watch prompt pour produire un résumé en lecture seule. Ce n'est pas une session native, seulement un support de passation copiable et vérifiable.

watch prompt ne lit que l'enregistrement de session local de l'assistant source et rend les tours, événements d'outils et un manifeste de travail en Markdown. L'en-tête nomme l'assistant source, l'identifiant de session, le fichier source, le répertoire de travail, le type de worktree et la branche courante ; le corps indique combien de tours ont été tronqués, ce qui a été omis et si l'usage peut être sous-compté. La commande n'écrit aucun fichier de session, n'ouvre aucune base et ne lance aucune CLI.

  1. Étape 1 : identifier la session source et le répertoire

    Passez l'identifiant de session explicitement, ou passez --cwd en omettant l'identifiant. Sans identifiant, Watch choisit la session lisible la plus récente du répertoire courant et la marque comme choisie automatiquement dans l'en-tête ; en cas de doute, nommez l'identifiant pour qu'une autre session ne soit pas prise pour la source.

  2. Étape 2 : choisir un profil et une fenêtre

    --profile minimal|standard|verbose|full contrôle l'ampleur du texte et des événements d'outils déployés. --last N ne garde que les N derniers tours utilisateur et abandonne la description initiale de la tâche, ce que le document indique. --since-compact part du dernier résumé de compaction ; lorsqu'aucun résumé utilisable n'existe, il ne tronque pas et le dit.

  3. Étape 3 : examiner les findings et l'état de la source

    --json inclut markdown, findings et warnings dans le résultat. degraded signifie que la dégradation a été divulguée, skipped que du contenu a été omis par vos options. Les lignes d'état de la source, de lignes défectueuses, d'usage et de branche dans le document indiquent si la passation est sûre. Un répertoire de travail source indisponible est renvoyé comme sourceCwd: { state } (missing, not-directory, denied ou unknown, avec reason pour unknown) ; un répertoire sain n'émet pas ce champ. Une racine de dépôt normale renvoie sourceBranch ({ branch, repoRoot } ; un HEAD détaché renvoie { detached: true, repoRoot }) et un worktree lié renvoie sourceWorktree ({ mainWorktree, branch }). Si la taille ou la date de modification du fichier source change entre les vérifications, sourceDrift ({ from, to, growth }) rapporte les octets et le sens de croissance. Cela n'établit pas quels enregistrements ont atteint le document. Les appels d'outils explicitement échoués sont renvoyés comme failedAttempts (outil, chemin ou commande et nombre, jamais la sortie de l'outil), avec la section « Échecs et interruptions (Failures and interruptions) » dans le document. Au rendu, l'aperçu des changements vérifie aussi si les fichiers listés sont toujours dans le répertoire de session : un fichier confirmé disparu est marqué comme n'étant plus sur disque, un fichier invérifiable comme non vérifié, un fichier supprimé ou déplacé par le patch de session est étiqueté comme tel, et les chemins hors du répertoire de session sont comptés à part ; l'en-tête de section indique combien ont été vérifiés, ou pourquoi la vérification n'a pas eu lieu. --json ajoute manifestDisk (checked, missing, unverified, outside, removed) pour que les scripts ne lisent jamais un champ absent comme « tout est présent ». Les appels d outil non clos et une fin de session suspendue sont signalés par stats.danglingToolCalls, stats.unansweredTail et les findings correspondants : le premier compte toute la session, le second ne s applique que si le dernier tour utilisateur contient du texte. Les deux sont décrits dans les métadonnées et la section Continue working du document, avec les mêmes champs dans --json.

  4. Étape 4 : préciser qu'il s'agit d'une passation récapitulative

    Collez le Markdown ou enregistrez-le comme fichier et dites à l'assistant cible au premier tour qu'il s'agit d'une passation récapitulative, pas d'une session native. La cible ne peut pas reprendre nativement, et les appels d'outils, raisonnements et pièces jointes peuvent avoir été tronqués ; ce qui est omis ne peut pas être récupéré depuis le document.

# 1. Choisir automatiquement la session la plus récente du répertoire courant au profil standard npm run watch -- prompt --cwd /abs/project # 2. Nommer la session et ne garder que les 5 derniers tours utilisateur npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. Émettre du JSON pour examiner les findings avec le document npm run watch -- prompt <session-id> --cwd /abs/project --json
Limites

1. Lecture seule : il n'écrit aucun fichier de session, n'ouvre aucune base locale et ne lance aucune CLI cible ; vous décidez comment livrer le Markdown. 2. Un résumé n'est pas une session native : les appels d'outils, raisonnements et pièces jointes peuvent être tronqués, et les parties omises ne peuvent pas être récupérées depuis le document. 3. Les troncatures sont comptées : les omissions du profil, de --last et de --since-compact figurent dans le corps et les findings ; sans résumé, il ne tronque pas et le dit. 4. Une source à 0 tour ou endommagée n'est pas rapportée comme un succès : le corps indique une source vide ou des lignes défectueuses, et un usage ou un nombre de lignes illisible est marqué comme éventuellement sous-compté ou non confirmé.

Questions fréquentes

watch prompt écrit-il dans la session de l'outil cible ?

Non. Il lit seulement l'enregistrement source et imprime du Markdown ; il n'écrit aucun fichier de session cible, n'ouvre aucune base et ne lance aucune CLI. Lorsque vous avez besoin d'une reprise native dans la cible, utilisez la route lanceur ou chaîne pour cet adaptateur ; la seule route d'import officielle est Claude Code vers Codex Desktop.

Pourquoi le document dit-il que la description initiale de la tâche n'a pas été conservée ?

Avec --last N, Watch commence au N-ième tour utilisateur depuis la fin, donc les tours précédents, y compris la description initiale de la tâche, sont omis. Retirez --last pour tout le contexte, ou utilisez --since-compact avec un profil plus large ; le corps liste chaque troncature réellement effectuée.

L'assistant cible peut-il poursuivre exactement comme une session native ?

Non. Il reçoit un document récapitulatif sans reprise native et ne voit pas les détails tronqués de l'exécution des outils. Demandez-lui au premier tour de redire l'objectif de la tâche et la branche courante, puis seulement confiez-lui des modifications.
