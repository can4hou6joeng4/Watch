Continuer dans Codex après qu’Claude Code a atteint sa limite d’usage

Quand Claude Code signale une limite de cinq heures ou hebdomadaire, /compact ne restaure pas le quota. Watch ne lit que le fichier local ~/.claude/projects/<encoded-cwd>/<session>.jsonl, vérifie le répertoire de travail et copie cet enregistrement dans Codex. Le fichier d’origine reste inchangé. Les événements d’outils peuvent devenir du texte.

Quand Claude Code atteint une limite d’usage (fenêtre de 5 heures ou quota hebdomadaire) ou que le dépannage bloque, ce guide explique comment conserver le répertoire de travail et l’historique de session, préparer un plan d’importation officiel et reprendre dans OpenAI Codex via Watch.

Publié: 2026-09-17 Modifié: 2026-10-14 S’applique à: Watch v0.1.335
Limite opérationnelle essentielle

Une limite d’usage restreint l’utilisation de Claude sur une fenêtre de temps donnée, tandis que les limites de fenêtre de contexte contraignent la capacité d’une seule conversation. Si la fenêtre de contexte est simplement pleine, utilisez /compact ou /clear dans Claude Code. Si vous avez atteint une limite d’usage du compte et devez changer d’agent, Watch transfère l’historique de session local enregistré vers Codex. Watch ne contourne pas les limites et ne modifie pas les fichiers du dépôt local.

Lors de tâches d’ingénierie prolongées, Claude Code peut signaler que vous avez atteint la limite de votre forfait, avec un horodatage de réinitialisation. Le raisonnement, les itérations échouées et les sorties de commandes accumulés restent sur votre disque. Watch fait le pont de cette session enregistrée vers OpenAI Codex, pour que le nouvel outil inspecte le contexte précédent sans que vous résumiez l’enquête à la main.

  1. Étape 1 : Vérifier l’ID de session source et le répertoire de travail

    Localisez l’ID de session Claude Code active. L’historique est stocké sous ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl. Assurez-vous que le chemin du répertoire (cwd) correspond à l’espace de travail réel du projet, afin d’éviter les décalages de worktree et de dépôt.

  2. Étape 2 : Vérifier que le projet cible existe dans Codex Desktop

    Ce guide utilise la route --desktop-project de Watch, qui exige que le projet soit enregistré dans Codex Desktop et synchronisé avec app-server. Ouvrez le répertoire de destination dans Codex Desktop avant de préparer le plan. C'est une garde propre à cette route de passation de bureau.

  3. Étape 3 : Préparer le plan d’importation (Prepare)

    Sélectionnez la session source et cliquez sur OpenAI Codex dans Watch Desktop, ou exécutez prepare. Watch vérifie la source, le répertoire de travail, la destination et la version de Codex, puis enregistre un plan d'import local. Il ne soumet pas l'import de session et n'acquiert pas le verrou cible Watch utilisé lors de la confirmation. La vérification de version native peut maintenir ses propres fichiers d'exécution ; l'opération n'est donc pas entièrement sans écriture.

  4. Étape 4 : Confirmer l’importation et examiner les dégradations (Confirm)

    Examinez le nombre de messages prévisualisé, le répertoire de travail et les traces d’appels d’outils. Confirmez explicitement pour lancer le transfert via le protocole d’importation local du app-server Codex. Notez que les événements d’appels d’outils peuvent se dégrader en représentations textuelles.

  5. Étape 5 : Lancer le client cible séparément (Open)

    Une fois confirmé, ouvrez Codex Desktop via l’interface de l’application ou la commande de reprise. Importation et ouverture sont strictement séparées : si le lancement échoue, ne réessayez que l’ouverture, sans répéter la phase d’importation.

# 1. Vérifier l'environnement et enregistrer un plan local (aucun import de session soumis) npm run watch -- import-codex prepare <claude-id> --cwd /abs/project/path --desktop-project --experimental --json # 2. Confirmer et exécuter l'import (utiliser le planId renvoyé par prepare) npm run watch -- import-codex confirm <plan-id> --experimental --json # 3. Lire le journal d'exécution local (ne lance aucun client natif) npm run watch -- import-codex status <plan-id> --json
Signatures d'erreur de limite de débit et de quota, citées mot pour mot

Si votre terminal affiche ces messages, vous avez atteint une limite d'usage au niveau du compte, pas la limite de contexte de la conversation : • "You have reached your 5-hour limit for Claude 3.7 Sonnet / Opus. Limit will reset at 14:30." • "Weekly usage limit reached. Your quota resets on Monday at 00:00 UTC." • "Rate limit exceeded for organization. Please wait before retrying." Dans ces cas, exécuter /compact dans Claude Code ne restaure ni ne libère le quota du modèle.

Claude Code enregistre les sessions sous ~/.claude/projects/<encoded-cwd>/<session>.jsonl. Lors de l'import Watch, les événements propriétaires tool_use et tool_result sont convertis en enregistrements Markdown en texte brut structurés dans les sessions rollout de Codex. L'agent cible dispose ainsi de tout l'historique d'investigation sans blocs natifs falsifiés qui briseraient l'intégrité de la reprise Codex.

Contraintes de sûreté et avertissements

1. Aucune garantie sans perte : les structures d’appels d’outils se dégradent en texte brut dans Codex, et la poursuite par le modèle est hors du périmètre de validation limité. 2. Arrêt en cas d’état incertain : si le processus est interrompu ou expire, le verrou est conservé. Inspectez avec la commande status plutôt que de supprimer les verrous de force ou de resoumettre. 3. La conversion locale n’est pas entièrement hors ligne : Watch fonctionne sans serveurs externes, mais Codex invoque son propre démon app-server et s’authentifie auprès de son fournisseur de modèle.

Questions fréquentes

Watch contourne-t-il ou réinitialise-t-il les limites de débit de Claude Code ?

Non. Watch est un utilitaire de relais local. Il ne modifie pas les comptes Anthropic et n’injecte pas de crédits ; il transfère les artefacts de session enregistrés localement vers un autre agent qui dispose encore de capacité.

Puis-je demander tout de suite à Codex de continuer à coder ?

Codex inspectera l’historique de conversation importé, mais les performances du modèle sur les tâches reprises dépendent de la capacité de contexte de l’agent cible. Nous recommandons de demander à Codex de résumer l’objectif actuel avant de lui confier de nouvelles modifications de code.

Que se passe-t-il si je soumets une importation deux fois ?

Watch applique des verrous persistants et l’idempotence des plans. Les requêtes prepare en double pour la même source et le même répertoire renvoient le plan existant sans dupliquer les enregistrements.
