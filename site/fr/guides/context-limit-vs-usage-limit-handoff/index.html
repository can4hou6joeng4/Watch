Fenêtre de contexte pleine et limites d’usage dans Claude Code : guide pratique

Une fenêtre de contexte pleine signifie que cette conversation est trop longue : lancez /compact ou /clear dans Claude Code. Une limite de compte indique une heure de réinitialisation, et /compact n’y change rien. Watch n’agrandit pas la fenêtre et ne restaure pas le quota. Il copie la session enregistrée vers un autre agent qui peut encore s’exécuter.

Interrompu pendant une tâche complexe dans Claude Code, apprenez à distinguer l’épuisement de la fenêtre de contexte et les quotas d’usage du compte, puis appliquez /compact ou le relais de session multi-agent de Watch.

Publié: 2026-09-21 Modifié: 2026-10-14 S’applique à: Watch v0.1.496
Limite opérationnelle essentielle : deux limites physiques distinctes

1. Limite de fenêtre de contexte : contraint le nombre total de jetons que le modèle peut traiter simultanément dans une seule session. Une fois pleine, le modèle invite à compacter ou compresse automatiquement l’historique. 2. Limite d’usage du compte : restreint le volume total de requêtes ou la consommation de jetons sur une fenêtre glissante (par exemple des réinitialisations de 5 heures ou des quotas hebdomadaires). Une fois atteinte, Claude affiche « You have exceeded your current usage limit » avec un horodatage de réinitialisation.

Les développeurs confondent souvent une fenêtre de contexte pleine avec une limite de débit du compte, ou supposent que les outils de relais de session agrandissent artificiellement la fenêtre de contexte de Claude. Watch ne contourne pas les quotas d’usage et ne remplace pas le compactage natif de Claude. Comprendre la différence permet de choisir le bon chemin de reprise.

  1. Étape 1 : Lire les signaux d’erreur du terminal pour identifier le type de limite

    Si Claude signale « exceeded your limit » avec une heure de réinitialisation, c’est une limite d’usage du compte : /compact échouera car le quota du modèle est épuisé ; attendez la réinitialisation ou relayer vers Codex / OpenCode. Si Claude signale des limites de longueur de conversation ou une latence élevée, c’est une limite de fenêtre de contexte : lancez /compact.

  2. Étape 2 : Appliquer la résolution native pour la longueur de contexte (/compact et /clear)

    Dans Claude Code, lancez /compact pour compresser l’historique de conversation en un résumé condensé. Si les tours d’enquête passés ne sont plus nécessaires, lancez /clear pour repartir à zéro dans l’espace de travail courant.

  3. Étape 3 : Enregistrer l’état de la session en atteignant les quotas d’usage du compte

    Vérifiez que Claude Code a écrit la transcription de session dans ~/.claude/projects/<enc-cwd>/<session-id>.jsonl. Utilisez Watch pour inspecter le répertoire de travail et la disponibilité de la cible Codex ou OpenCode.

  4. Étape 4 : Relayer vers un autre agent sans répéter le contexte

    Utilisez Watch pour convertir le raisonnement et les résultats de tests enregistrés au format de l’agent de destination, puis reprenez dans le nouveau CLI avec le contexte précédent.

# Scénario A : résolution native des limites de fenêtre de contexte (dans Claude Code) /compact # Compresser automatiquement l’historique pour libérer de la capacité de contexte /clear # Effacer la conversation tout en conservant le contexte du répertoire de travail # Scénario B : relais multi-agent en cas de limite d’usage du compte (dans le shell) npm run watch -- open <claude-session-id> --to codex --json npm run watch -- open <claude-session-id> --to opencode --json
Contraintes de sûreté et avertissements

1. Watch n’étend pas le contexte d’un seul agent : la reprise dans un nouvel agent est soumise aux limites de fenêtre de contexte de cet agent. 2. Changement de représentation des outils : les événements tool_use de Claude se dégradent en représentations textuelles structurées dans Codex afin d’éviter les erreurs d’analyse du schéma. 3. N’interrompez pas brutalement les processus : assurez-vous que les fichiers de session sont écrits avant de fermer les fenêtres de terminal.

Questions fréquentes

/compact abandonne-t-il les modifications de code déjà sur le disque ?

Non. Les modifications de fichiers existent déjà sur votre système de fichiers local. /compact ne compresse que l’historique de conversation en mémoire. En revanche, les messages d’erreur détaillés peuvent être résumés.

Pourquoi /compact échoue-t-il en cas de limite d’usage du compte ?

/compact organise l'historique de la conversation ; il ne restaure pas le quota du compte, et une demande de résumé peut elle aussi être bloquée par la limite. Vous pouvez attendre la réinitialisation, choisir un autre outil disponible et suivre une route de passation validée, ou exporter un document plus court avec watch prompt pour une passation manuelle. Watch ne restaure ni ne contourne les quotas.

Relayer vers Codex ou OpenCode réinitialise-t-il le contexte ?

La passation transporte un historique enregistré qui peut être converti en session de destination, où il consomme encore du contexte. Watch n'agrandit pas la fenêtre et ne résume pas automatiquement selon un budget de tokens cible ; il ne peut donc pas garantir que la saturation est résolue. Pour raccourcir l'entrée, utilisez la compaction native de l'outil cible ou exportez un document de passation plus court avec les préréglages de watch prompt et --last, puis examinez ses mentions d'omission.
