재개 시 빈 세션이 열리는 이유: 0턴 세션 감지와 복구

재개 후 세션이 비어 있다면 보통 파일에 남은 턴이 없다는 뜻입니다. watch new로 만든 정상적인 빈 세션, 자리표시자 헤더만 남기고 내용이 지워진 세션, 또는 0바이트 파일입니다. watch status의 체인 끝 행에서 턴 수를 확인하세요. Watch가 기록을 대신 복구하지는 않습니다. 백업에서 파일을 복원하거나, 다른 세션에 다시 연결하거나, 새 체인을 시작하세요.

Watch는 체인 끝 세션과 작업 디렉터리를 대상 도구에 넘기며, 재개 명령 자체는 세션을 여는 일만 합니다. 이 가이드는 status의 체인 끝 행에서 시작해 읽을 수 있는 0턴 세션과 0바이트 파일을 구분하고, 백업 복원·adopt로 다시 연결·새 체인이라는 세 가지 복구 경로를 제시합니다.

게시: 2026-11-17 수정: 2026-11-23 적용 버전: Watch v0.1.313
핵심 구분

재개 명령과 각 클라이언트의 네이티브 재개 명령은 한 가지 일만 합니다. 지정한 세션을 여는 것입니다. 이어서 진행할 수 있는지는 그 파일에 턴이 얼마나 남아 있는지에 달려 있습니다. '존재함'과 '읽을 수 있음'은 내용이 있다는 뜻이 아니며, 바로 이 점 때문에 모든 것이 정상으로 보이는데도 재개가 빈 세션으로 열립니다. Watch는 v0.1.84부터 open, switch, new, status에서 이 경우를 따로 고지합니다.

'비어 있음'에는 두 가지가 있습니다. 읽을 수 있는 0턴 파일은 유효한 세션 헤더(Claude Code의 자리표시자 user 줄, Codex 롤아웃의 session_meta 줄)는 있지만 대화 턴이 없습니다. 0바이트 파일은 쓰기 도중 강제 종료, 디스크 소진, 잘림으로 생겼으며 세션 메타데이터조차 없을 수 있습니다. Codex는 첫 롤아웃 줄에 귀속 정보를 저장하므로 0바이트로 잘리면 조회도 깨집니다.

빈 세션이 열리는 세 번째 경우는 파일이 더 이상 존재하지 않을 때입니다. Claude Code는 세션 시작 후 cleanupPeriodDays보다 오래된 트랜스크립트를 삭제하며, 공식 기본값은 30일이고 이 키는 어떤 설정 파일에서도 허용되므로 프로젝트 설정이 사용자 설정을 덮어쓸 수 있습니다. 만료된 세션은 /resume에 더 이상 나타나지 않고 watch open이나 resume으로도 찾을 수 없습니다. watch doctor는 쓰기 없이 사용자 설정, 현재 디렉터리 프로젝트 설정, 일반 Git 저장소의 하위 디렉터리에서는 저장소 루트 로컬 설정(scope repository-local)을 읽고, 값이 기본값보다 짧거나 확인할 수 없을 때 경고합니다. 그 값을 실제 적용 값으로 제시하지 않으며 --settings와 관리형 설정은 범위 밖입니다. 보존 기간을 늘리면 앞으로의 삭제만 줄어들 뿐 이미 삭제된 파일은 복구되지 않으므로 중요한 세션은 미리 백업하세요.

  1. 1단계: status의 체인 끝 행 읽기

    watch status를 실행하세요. v0.1.90부터 체인 끝 행에 턴 수가 표시됩니다(예: 12턴인 체인 끝). 0턴으로 파싱되면 0턴을 파싱했다고 표시하며 위의 경고를 가리킵니다. 파일을 읽을 수 없거나 없으면 턴 수가 표시되지 않습니다. JSON에서는 chainTipTurns와 chainTipEmpty 필드이며 chainTipTurns는 파싱이 성공할 때만 존재합니다. 체인이 여러 개면 watch chain list의 끝 행에도 같은 수가 표시됩니다(v0.1.93). 확실하지 않으면 watch doctor의 store.emptyTips가 0턴으로 파싱된 끝을 나열합니다(v0.1.92). watch new --json도 실제 파싱된 턴 수를 보고합니다(v0.1.94). claude와 pi는 자리표시자 user 메시지를 쓰므로 1턴으로, codex, grok, opencode는 0으로 표시됩니다. v0.1.95부터 watch usage는 0턴 빈 세션과 내용은 있지만 사용량 기록이 없는 세션을 구분하므로 새로 만든 체인이 통계 공백으로 보고되지 않습니다. v0.1.96부터 파싱할 수 없는 내용 줄과 Codex 압축 레코드가 빈 세션으로 잘못 보고되지 않습니다. v0.1.97부터 사이드카 사용량이 남아 있어도 삭제된 내용 파일을 고지합니다. v0.1.98부터 잘못된 내용 줄을 침묵하지 않고 warnings와 필드에 고지하며, v0.1.99부터 턴이 있는 잘못된 내용 줄을 0턴 파싱으로 묘사하지 않습니다. v0.1.100부터 텍스트 요약이 0턴 세션과 사용량이 있는 세션을 구분하고, 스캔 실패 시 잘못된 줄 수를 알 수 없다고 밝힙니다. v0.1.101부터 0턴 요약에 사용량 집계 문구가 붙지 않으며, v0.1.98 관련 설명은 사용량 손실이 아니라 고지 공백을 가리킵니다.

  2. 2단계: 다섯 가지 경고 경우 읽기

    같은 결과가 0바이트(세션 파일이 비어 있음), 읽을 수 있는 0턴(0턴 파싱, 이어갈 내용 없음), 읽을 수 없는 내용(권한 또는 내용), 없는 파일(삭제 또는 이동), 내용 파싱 실패(파일은 정상적으로 읽히지만 세션 형식이 손상되었거나 OpenCode 데이터베이스에 message 테이블이 없음, v0.1.279부터 경고 문구가 내용 파싱에 실패해 턴 수나 꼬리 상태를 확인할 수 없다고 표시)를 구분합니다. 경우마다 다음 단계가 다르므로 '비어 있다'는 단어만 보고 다시 연결하지 마세요. 마지막 경우는 세션이 비었는지조차 알려 주지 않으므로 빈 세션으로 취급하지 말고, watch switch나 watch open을 한 번 실행해 사전 검사가 구체적 이유를 보고하게 하세요.

  3. 3단계: 새로 만든 빈 세션인지 확인

    watch new로 만든 세션은 설계상 비어 있습니다. 첫 체인의 정상적인 출발점이며, 다음 switch나 open --to가 이를 대상으로 삼아 원본 내용을 병합합니다. 체인 끝이 그 새 세션이고 아직 switch하지 않았다면 0턴은 예상된 상태이지 손상이 아닙니다.

  4. 4단계: 경우에 따라 복구

    내용이 지워짐: 백업에서 파일을 복원하고 재개를 다시 시도하세요. Watch는 기록을 복구하지 않습니다. 잘못된 세션: watch adopt <provider> --session <another-session-id>로 체인 끝을 다시 연결하세요. 양쪽 모두 유지: watch chain new <new-chain-name>로 다른 체인을 시작하고 원래 기록은 건드리지 마세요. 백업 없는 0바이트: 복구할 것이 없으므로 새 세션으로 취급하세요.

# 1. 체인 끝 턴 수와 경고 읽기 (v0.1.90부터) npm run watch -- status --json # 2. 체인 끝이 빈 세션일 때의 세 가지 경로 npm run watch -- adopt <provider> --session <another-session-id> # 다른 세션으로 다시 연결 npm run watch -- chain new <new-chain-name> # 다른 체인 시작 # 3. 먼저 백업에서 복원한 뒤 재개 재시도 npm run watch -- switch <provider>
경계

1. Watch는 기록을 복구하지 않습니다. 0턴 세션은 자신의 백업으로만 되살릴 수 있습니다. 2. Watch는 0바이트 파일을 스스로 삭제하거나 복구하지 않습니다. 그것은 사용자의 네이티브 세션 파일이며 복원 여부는 사용자가 결정합니다. 3. 읽을 수 있는 0턴 세션이 반드시 내용이 지워진 것은 아닙니다. watch new가 바로 그 모양을 만들므로 숫자만 보고 판단하지 말고 맥락을 보세요. 4. 이 고지는 로컬 파일을 읽어 얻은 것이며 네이티브 클라이언트가 세션을 열 것이라는 보장이 아닙니다. 클라이언트 수용 여부는 버전과 플랫폼별로 기록됩니다.

자주 묻는 질문

재개가 빈 세션을 열었을 때 Watch가 기록을 잃은 건가요?

보통은 아닙니다. Watch는 원본을 먼저 읽고 쓰기 가드와 원자적 쓰기로 대상에 덧붙입니다. 0턴 세션은 대개 처음부터 비어 있거나(watch new로 만든 새 세션) 이전에 지워지거나 잘린 것입니다. Watch 쓰기가 원인인지 확인하려면 핸드오프 결과의 턴 수와 warnings를 백업 파일과 비교하세요.

0턴과 0바이트는 무엇이 다른가요?

0턴은 파일을 읽을 수 있고 유효한 세션 헤더가 있지만 대화가 없다는 뜻입니다. 새 세션이거나 자리표시자 헤더만 남은 것일 수 있습니다. 0바이트는 파일 자체가 비어 있다는 뜻으로, 프로세스 강제 종료, 디스크 소진, 불완전한 쓰기로 생기며 세션 메타데이터조차 없을 수 있습니다. 전자는 아직 시작하지 않았을 수 있고, 후자는 먼저 백업을 확인해야 합니다.

Watch가 지워진 세션을 자동으로 복구할 수 있나요?

아니요. Watch는 로컬 세션 파일을 읽고 쓸 뿐이며 기록 백업 기능이 없고 대화를 만들어 내지 않습니다. 복구는 사용자의 백업(Time Machine, 저장소 밖 복사본, 편집기 기록)에서 이루어지며, 파일을 복원한 뒤 재개하세요.

Claude Code가 오래된 세션을 스스로 삭제하나요?

예. 공식 설정 참조의 cleanupPeriodDays 기본값은 30일입니다. 세션이 시작된 뒤 Claude Code는 그 값보다 오래된 트랜스크립트를 백그라운드에서 정리하며, 만료된 세션은 /resume에 나타나지 않습니다. 이 키는 어떤 설정 파일에서도 허용되므로 프로젝트 설정이 사용자 설정을 덮어쓸 수 있습니다. watch doctor는 사용자 설정, 현재 디렉터리 프로젝트 설정, 저장소 루트 로컬 설정을 쓰기 없이 읽지만 --settings와 관리형 설정은 범위 밖이므로 보고서가 실제 적용 값은 아닙니다. 값을 늘리면 앞으로의 삭제만 줄어들 뿐 이미 삭제된 파일은 되살릴 수 없습니다.
