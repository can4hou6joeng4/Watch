Codex 세션이 .jsonl.zst로 남은 경우: Watch 읽기 경계와 복구

Codex가 로컬 스레드를 압축하면 롤아웃은 .jsonl.zst로만 남고 Watch는 압축 형식을 읽지 않으므로 그 세션은 어떤 목록에도 나오지 않습니다. watch doctor에서 귀속 불가 개수를 확인하고 Codex에서 스레드를 이어 다시 펼쳐지게 하세요. 0바이트 사본은 내용이 사라진 것이므로 백업에서 복원해야 합니다. .zst 파일을 삭제하거나 이름을 바꾸지 마세요.

Watch는 ~/.codex/sessions 아래의 압축되지 않은 롤아웃 .jsonl 파일을 읽습니다. Codex가 로컬 스레드를 압축하면 원본 .jsonl은 사라지고 같은 이름의 .jsonl.zst만 남으며, 그 세션은 목록·파싱·핸드오프가 불가능합니다. watch doctor와 목록 명령은 없는 척하지 않고 개수를 고지합니다. Codex가 압축한 파일이고 사본이 온전하다면 Codex에서 세션을 이어 보며 .jsonl이 다시 나타나는지 확인하세요.

게시: 2026-11-23 수정: 2026-11-23 적용 버전: Watch v0.1.376
핵심 구분

Watch는 ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl 같은 압축되지 않은 파일을 읽습니다. Codex가 로컬 스레드를 압축하면 원본 파일이 사라지고 같은 디렉터리에 같은 이름의 .jsonl.zst만 남습니다. Watch는 이를 압축 해제하거나 다시 쓰지 않으며, 읽을 수 없음을 없음으로 보고하지도 않습니다. 목록, status, doctor, search 모두 개수를 고지하고 이 파일들은 어떤 디렉터리에도 귀속할 수 없다고 밝힙니다.

Codex는 첫 session_meta 줄의 cwd 필드에 세션 귀속 정보를 저장하는데 압축 사본에서는 그 줄을 읽을 수 없습니다. 그래서 Watch는 세션이 어느 작업 디렉터리에 속하는지 알 수 없습니다. watch doctor의 귀속 불가 개수와 watch sessions의 unattributable 필드가 말하는 것이 바로 이것입니다. 오류가 아니라, 파일은 존재하지만 이 버전이 그 안을 볼 수 없다는 뜻입니다. 압축된 이력이 크면 개수도 커질 수 있으며 이는 정상입니다.

사본은 다음 단계가 정반대인 두 상태로 나뉩니다. 비어 있지 않은 사본은 Codex가 만든 것이고 온전하다면 Codex에서 세션을 이어갈 때 .jsonl로 다시 펼쳐질 수 있습니다. 다시 나타난 뒤에는 Watch가 일반 파일을 읽을 수 있습니다. 0바이트 사본은 내용이 사라진 것이므로 다시 펼쳐도 대화가 돌아오지 않으며, 백업에서 복원하거나 새 세션으로 취급해야 합니다. Watch는 사본의 존재와 0바이트 여부만 stat으로 확인하고 열거나 압축 해제하지 않습니다. 그래서 고지 문구도 '사본이 온전한 Codex 압축일 때만 성립한다'는 조건부로 적힙니다.

  1. 1단계: 개수와 파일 형태 확인

    watch doctor --json을 실행하세요. codex의 경우 count는 읽을 수 있는 세션만 세고 unattributable은 압축 사본처럼 디렉터리를 읽을 수 없는 파일을 셉니다. 텍스트 출력은 세션 수 옆에 귀속 불가 합계를 표시합니다. watch sessions --json과 watch recent --json도 같은 필드를 담습니다. 경고는 형태를 밝힙니다. 같은 이름의 .jsonl.zst 압축 사본인지, 0바이트 같은 이름 사본인지에 따라 다음 단계가 다릅니다.

  2. 2단계: 비어 있지 않은 사본과 0바이트 사본 구분

    해당 .jsonl.zst를 찾으세요. 비어 있지 않은 파일은 바이트가 남아 있지만 그것이 온전하거나 압축 해제가 가능하다는 증거는 아닙니다. 0바이트 사본은 복구할 내용이 없으니 백업을 찾으세요. 세션이 쓸 수 없는 체인 끝이면 watch doctor --json의 store.brokenTips[].compressedPath에 사본 경로가 나오고, 0바이트 사본이면 compressedEmpty가 true로 설정됩니다. 목록의 unattributable 필드는 개수만 보고합니다.

  3. 3단계: Codex에서 세션 이어가기

    Codex에서 스레드를 열거나 이어가세요. 사본이 온전한 Codex 로컬 스레드 압축이라면 Codex가 이를 .jsonl로 다시 펼칩니다. 그 뒤 watch sessions를 실행하면 세션이 다시 나타나고 status, switch, open에서도 읽을 수 있습니다. Watch는 다시 펼치기를 유도하지 않고 .zst를 절대 건드리지 않습니다.

  4. 4단계: 다시 펼친 뒤 핸드오프

    다시 펼쳐진 세션 id를 얻었으면 평소 경로를 쓰세요. watch open <id> --to <provider> 또는 watch switch <provider>입니다. watch prompt도 압축 파일을 읽지 않으므로 그 세션을 지정하면 오류를 보고하고 핸드오프 문서를 만들지 않습니다.

# 1. 읽기 전용: 개수와 원인 npm run watch -- doctor --json npm run watch -- sessions --json # 2. 파일 찾기 (원본 .jsonl은 사라지고 .zst만 남음) ls ~/.codex/sessions/*/*/*/*.jsonl.zst # 3. Codex에서 세션을 이어 다시 펼치면 Watch가 목록에 올릴 수 있음 npm run watch -- sessions --json # 4. 다시 펼친 뒤 핸드오프 npm run watch -- open <session-id> --to <provider>
경계와 하지 말아야 할 일

1. Watch는 .jsonl.zst를 압축 해제하거나 다시 쓰거나 삭제하지 않으며 내용을 해독할 수 있는지도 판단하지 않습니다. 존재와 0바이트 여부만 stat으로 확인합니다. 2. .zst 파일은 사용자가 직접 만든 아카이브일 수도 있습니다. Watch는 Codex가 만들었다고 가정하지 않으므로, 다시 펼치기 경로는 온전한 Codex 로컬 스레드 압축일 때만 성립합니다. 3. 직접 압축을 풀어 sessions 디렉터리에 되돌려 놓지 마세요. Watch는 손으로 만든 파일을 검증하지 않고 Codex 수용 여부에는 검증 기록이 없습니다. 4. .zst를 삭제하거나 이름을 바꾸지 마세요. 사용자의 네이티브 세션 데이터이며 삭제하면 복구 경로가 사라집니다. 5. 이 가이드는 로컬 파일과 Watch 고지 동작을 따릅니다. 네이티브 클라이언트가 다시 펼친 세션을 받아들이는지는 버전과 플랫폼별로 따로 검증되며 이 가이드는 네이티브 수용이 아닙니다.

자주 묻는 질문

Watch가 제 Codex 세션을 압축하거나 삭제하나요?

아니요. 압축은 Codex의 동작입니다. Watch는 .zst 파일을 읽거나 다시 쓰거나 삭제하지 않으며 목록과 파싱은 압축되지 않은 .jsonl을 사용합니다. Codex로의 쓰기 가능한 핸드오프는 별개이며 압축되지 않은 대상 세션 파일을 만들거나 갱신할 수 있습니다.

doctor가 파일이 압축되었다고 말하지 않고 디렉터리를 귀속할 수 없다고 하는 이유는 무엇인가요?

Watch는 압축 파일을 stat으로 확인만 하고 열지 않기 때문입니다. 원본 .jsonl이 사라지고 같은 이름의 .zst가 있다는 것과 그 압축 사본 경우를 경고로 밝힐 수는 있지만, 사본이 해독되는지, 귀속 정보가 담긴 session_meta 첫 줄을 읽을 수 있는지는 확인할 수 없습니다. 확인되지 않은 사실을 보증하지 않도록 문구를 조건부로 유지합니다.

.zst를 직접 .jsonl로 압축 해제해도 되나요?

권장하지 않습니다. 그곳은 네이티브 저장 디렉터리이고 Watch는 손으로 만든 파일을 검증하지 않으며 Codex 수용 여부에는 검증 기록이 없습니다. 더 안전한 경로는 Codex에서 세션을 이어 네이티브 클라이언트가 다시 펼치게 하는 것입니다.

0바이트 사본과 온전한 사본은 무엇이 다른가요?

0바이트 사본은 내용이 사라진 것이므로 다시 펼쳐도 대화가 돌아오지 않습니다. 백업에서 복원하거나 새 세션으로 취급하세요. 온전한 사본은 Codex에서 세션을 이어갈 때 다시 펼쳐질 수 있고, 그 뒤에는 Watch도 읽을 수 있습니다.

이 압축 세션들을 다른 에이전트로 핸드오프할 수 있나요?

직접은 안 됩니다. 먼저 Codex에서 다시 펼친 뒤 watch open <id> --to <provider> 또는 watch switch를 사용하세요. 핸드오프 전에 세션 id와 작업 디렉터리를 확인하고 결과의 warnings를 읽는 것도 잊지 마세요.
