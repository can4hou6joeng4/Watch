어댑터가 없을 때 watch prompt 사용하기

대상 도구에 어댑터가 없거나 네이티브 형식이 막 바뀌었을 때 watch prompt <session-id>로 읽기 전용 Markdown 핸드오프를 만드세요. 세션 파일을 쓰지 않고 CLI도 시작하지 않으며, 생략 수와 저하는 문서와 --json findings에 기록되므로 대상은 이를 네이티브 세션이 아닌 요약으로 다뤄야 합니다.

watch prompt는 로컬 네이티브 세션 기록을 Markdown 요약 핸드오프로 바꾸며, 파일을 쓰지 않고 대상 CLI도 실행하지 않습니다. 대상은 네이티브 재개를 물려받지 않으며, 모든 생략과 원본 상태가 문서와 findings에 기록됩니다.

게시: 2026-11-18 수정: 2026-11-18 적용 버전: Watch v0.1.413
이 경로를 쓰는 때

세 가지 네이티브 핸드오프 경로(런처, 체인 핸드오프, Codex 공식 가져오기)는 어댑터와 검증 가능한 대상 형식을 요구합니다. 대상 CLI에 아직 어댑터가 없거나 네이티브 형식이 막 바뀌었거나, 컨텍스트를 웹 어시스턴트에 넘기기만 하면 될 때 watch prompt로 읽기 전용 요약을 만드세요. 네이티브 세션이 아니라 복사·검토할 수 있는 핸드오프 자료일 뿐입니다.

watch prompt는 원본 어시스턴트의 로컬 세션 기록만 읽어 턴, 도구 이벤트, 작업 매니페스트를 Markdown으로 렌더링합니다. 헤더에는 원본 어시스턴트, 세션 ID, 원본 파일, 작업 디렉터리, 워크트리 유형, 현재 브랜치가 표시되고, 본문에는 몇 턴을 생략했는지, 무엇을 뺐는지, 사용량이 과소 집계될 수 있는지가 적힙니다. 이 명령은 세션 파일을 쓰지 않고 데이터베이스도 열지 않으며 CLI도 실행하지 않습니다.

  1. 1단계: 원본 세션과 디렉터리 확인

    세션 ID를 직접 넘기거나 --cwd만 넘기고 ID를 생략하세요. ID가 없으면 Watch가 현재 디렉터리에서 가장 최근에 읽을 수 있는 세션을 골라 헤더에 자동 선택으로 표시합니다. 확실하지 않으면 ID를 지정해 다른 세션이 원본으로 오인되지 않게 하세요.

  2. 2단계: 프로필과 범위 선택

    --profile minimal|standard|verbose|full은 텍스트와 도구 이벤트를 얼마나 펼칠지 정합니다. --last N은 최신 N개 사용자 턴만 남기고 원래 작업 설명을 버리며 문서에도 그렇게 적힙니다. --since-compact는 최신 압축 요약에서 시작하고, 쓸 만한 요약이 없으면 생략하지 않고 그렇다고 밝힙니다.

  3. 3단계: findings와 원본 상태 확인

    --json을 주면 결과에 markdown, findings, warnings가 포함됩니다. degraded는 저하가 고지되었다는 뜻이고 skipped는 옵션에 의해 내용이 빠졌다는 뜻입니다. 문서의 원본 상태, 잘못된 줄, 사용량, 브랜치 줄을 보고 인계해도 안전한지 판단하세요. 원본 작업 디렉터리를 사용할 수 없으면 sourceCwd: { state }(missing, not-directory, denied 또는 unknown, unknown이면 reason 포함)로 반환되고 정상 디렉터리면 이 필드가 없습니다. 일반 저장소 루트는 구조화된 sourceBranch({ branch, repoRoot }, 분리된 HEAD는 { detached: true, repoRoot })를, 연결된 워크트리는 sourceWorktree({ mainWorktree, branch })를 반환합니다. 검사 사이에 원본 파일 크기나 수정 시각이 바뀌면 sourceDrift({ from, to, growth })가 바이트 수와 증가 방향을 보고합니다. 다만 어떤 레코드가 문서에 들어갔는지까지 입증하지는 않습니다. 명시적으로 실패한 도구 호출은 failedAttempts(도구, 경로 또는 명령과 횟수, 도구 출력은 제외)로 반환되고 문서에는 '실패와 중단(Failures and interruptions)' 절이 붙습니다. 렌더링 시점에 변경 개요는 나열한 파일이 아직 세션 디렉터리에 있는지도 확인합니다. 사라진 것이 확인된 파일은 더 이상 디스크에 없음으로, 확인할 수 없는 파일은 미확인으로, 세션 패치가 삭제하거나 옮긴 파일은 그렇게 표시되고, 세션 디렉터리 밖 경로는 따로 집계됩니다. 절 머리글에는 몇 개를 확인했는지 또는 확인하지 못한 이유가 적힙니다. --json에는 manifestDisk(checked, missing, unverified, outside, removed)가 추가되므로 스크립트가 없는 필드를 '전부 존재'로 읽지 않게 합니다. 완료되지 않은 도구 호출과 매달린 사용자 마지막 턴은 stats.danglingToolCalls, stats.unansweredTail 및 해당 finding으로 보고됩니다. 전자는 전체 세션을 세고, 후자는 마지막 사용자 턴에 실제 텍스트가 있을 때만 적용됩니다. 둘 다 문서 메타데이터와 Continue working 섹션에 설명되며 --json에도 같은 필드가 있습니다.

  4. 4단계: 요약 핸드오프임을 밝히기

    Markdown을 붙여 넣거나 파일로 저장하고, 첫 턴에서 이것이 네이티브 세션이 아닌 요약 핸드오프임을 대상 어시스턴트에게 알리세요. 대상은 네이티브로 재개할 수 없고 도구 호출, 추론, 첨부가 생략되었을 수 있으며, 빠진 내용은 문서에서 복구할 수 없습니다.

# 1. 현재 디렉터리의 최신 세션을 standard 프로필로 자동 선택 npm run watch -- prompt --cwd /abs/project # 2. 세션을 지정하고 최신 사용자 턴 5개만 유지 npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. 문서와 함께 findings를 검토하려면 JSON 출력 npm run watch -- prompt <session-id> --cwd /abs/project --json
경계

1. 읽기 전용: 세션 파일을 쓰지 않고 로컬 데이터베이스도 열지 않으며 대상 CLI도 실행하지 않습니다. Markdown 전달 방식은 사용자가 정합니다. 2. 요약은 네이티브 세션이 아닙니다. 도구 호출, 추론, 첨부가 생략될 수 있고 빠진 부분은 문서에서 복구할 수 없습니다. 3. 생략은 집계됩니다. 프로필, --last, --since-compact로 빠진 내용이 본문과 findings에 기록되며, 요약이 없으면 생략하지 않고 그렇다고 밝힙니다. 4. 0턴이거나 손상된 원본을 성공으로 보고하지 않습니다. 본문에 빈 원본이나 잘못된 줄이 적히고, 읽을 수 없는 사용량이나 잘못된 줄 수는 과소 집계 가능 또는 미확인으로 표시됩니다.

자주 묻는 질문

watch prompt가 대상 도구 세션에 쓰나요?

아니요. 원본 기록을 읽어 Markdown을 출력할 뿐 대상 세션 파일을 쓰지 않고 데이터베이스도 열지 않으며 CLI도 실행하지 않습니다. 대상에서 네이티브 재개가 필요하면 해당 어댑터의 런처나 체인 경로를 쓰세요. 유일한 공식 가져오기 경로는 Claude Code에서 Codex 데스크톱으로 가는 경로입니다.

문서에 첫 작업 설명이 유지되지 않았다고 적힌 이유는 무엇인가요?

--last N을 주면 Watch는 끝에서 N번째 사용자 턴부터 시작하므로 그보다 앞선 턴, 즉 원래 작업 설명이 빠집니다. 전체 배경이 필요하면 --last를 빼거나 더 큰 프로필과 --since-compact를 쓰세요. 본문에는 실제로 일어난 생략이 각각 나열됩니다.

대상 어시스턴트가 네이티브 세션처럼 정확히 이어서 진행할 수 있나요?

아니요. 네이티브 재개 없이 요약 문서만 받으며 생략된 도구 실행 세부를 볼 수 없습니다. 첫 턴에서 작업 목표와 현재 브랜치를 다시 말하게 한 뒤에 편집을 맡기세요.
