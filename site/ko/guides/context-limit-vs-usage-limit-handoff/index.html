Claude Code의 컨텍스트 창 가득 참과 사용 한도: 실무 가이드

컨텍스트 창이 가득 찼다는 것은 이 대화가 너무 길다는 뜻입니다. Claude Code 안에서 /compact 또는 /clear를 실행하세요. 계정 한도는 재설정 시각을 알려 주며, 그때 /compact는 효과가 없습니다. Watch는 창을 넓히지도 할당량을 복원하지도 않습니다. 아직 실행할 수 있는 다른 에이전트로 저장된 세션을 복사합니다.

Claude Code의 복잡한 작업이 중단되면 컨텍스트 창 소진과 계정 사용 할당량을 구분하고, /compact 또는 Watch 다중 에이전트 세션 핸드오프를 적절히 적용하는 방법을 알아봅니다.

게시: 2026-09-21 수정: 2026-10-14 적용 버전: Watch v0.1.472
핵심 운영 경계: 서로 다른 두 물리적 한도

1. 컨텍스트 창 한도: 한 세션에서 모델이 동시에 처리할 수 있는 총 토큰 수를 제한합니다. 가득 차면 모델이 압축을 요청하거나 기록을 자동으로 압축합니다. 2. 계정 사용 한도: 이동 시간 창(예: 5시간 재설정 또는 주간 할당량)의 총 요청량 또는 토큰 소비를 제한합니다. 도달하면 Claude는 재설정 시각과 함께 "You have exceeded your current usage limit"를 표시합니다.

개발자는 가득 찬 컨텍스트 창을 계정 속도 제한과 혼동하거나, 세션 핸드오프 도구가 Claude의 컨텍스트 창을 인위적으로 넓힌다고 여기기도 합니다. Watch는 사용 할당량을 우회하거나 Claude의 네이티브 압축을 대체하지 않습니다. 차이를 알아야 올바른 복구 경로를 고릅니다.

  1. 1단계: 터미널 오류 신호로 한도 유형 식별

    Claude가 재설정 시각과 함께 "exceeded your limit"를 보고하면 계정 사용 한도입니다. 모델 할당량이 소진되어 /compact는 실패합니다. 재설정을 기다리거나 Codex / OpenCode로 넘기세요. Claude가 대화 길이 한도나 높은 지연을 보고하면 컨텍스트 창 한도입니다. /compact를 실행하세요.

  2. 2단계: 컨텍스트 길이는 네이티브 방법으로 해결 (/compact & /clear)

    Claude Code 안에서 /compact를 실행해 대화 기록을 압축된 요약으로 만듭니다. 과거의 조사 턴이 더 이상 필요 없으면 /clear를 실행해 현재 작업 공간에서 깨끗이 시작하세요.

  3. 3단계: 계정 사용 할당량에 걸리면 세션 상태 저장

    Claude Code가 세션 기록을 ~/.claude/projects/<enc-cwd>/<session-id>.jsonl에 기록했는지 확인합니다. Watch로 작업 디렉터리와 Codex 또는 OpenCode 대상 준비 상태를 살펴보세요.

  4. 4단계: 컨텍스트를 반복하지 않고 다른 에이전트로 핸드오프

    Watch로 기록된 추론과 테스트 결과를 대상 에이전트 형식으로 변환한 뒤, 앞선 컨텍스트 전체와 함께 새 CLI에서 이어가세요.

# 시나리오 A: 컨텍스트 창 한도의 네이티브 해결 (Claude Code 내부) /compact # 기록을 자동 압축해 컨텍스트 용량 확보 /clear # 작업 디렉터리 컨텍스트는 유지하고 대화 비우기 # 시나리오 B: 계정 사용 한도에 걸렸을 때의 다중 에이전트 핸드오프 (Shell) npm run watch -- open <claude-session-id> --to codex --json npm run watch -- open <claude-session-id> --to opencode --json
안전 제약 및 고지

1. Watch는 단일 에이전트 컨텍스트를 확장하지 않음: 새 에이전트에서 이어가기는 그 에이전트 자신의 컨텍스트 창 한도를 받습니다. 2. 도구 표현 변화: Claude tool_use 이벤트는 스키마 파싱 오류를 막기 위해 Codex에서 구조화된 텍스트 표현으로 저하됩니다. 3. 프로세스를 갑자기 종료하지 말 것: 터미널 창을 닫기 전에 세션 파일이 기록되었는지 확인하세요.

자주 묻는 질문

/compact가 디스크의 코드 수정을 버리나요?

아니요. 파일 편집은 이미 로컬 파일시스템에 있습니다. /compact는 메모리 안의 대화 기록만 압축합니다. 다만 세부 하위 오류 메시지는 요약될 수 있습니다.

계정 사용 한도에 걸리면 /compact가 왜 실패하나요?

/compact는 대화 기록을 정리할 뿐 계정 할당량을 되돌리지 않으며, 요약 생성 요청도 한도에 막힐 수 있습니다. 초기화를 기다리거나, 사용 가능한 다른 도구를 골라 검증된 핸드오프 경로를 따르거나, watch prompt로 더 짧은 문서를 내보내 수동으로 인계할 수 있습니다. Watch는 할당량을 되돌리거나 우회하지 않습니다.

Codex나 OpenCode로 넘기면 컨텍스트가 재설정되나요?

핸드오프는 저장된 이력을 대상 세션으로 변환해 전달하며, 그 이력은 대상에서도 컨텍스트를 차지합니다. Watch는 윈도를 늘리거나 목표 토큰 예산에 맞춰 자동 요약하지 않으므로 포화가 해소된다고 보장할 수 없습니다. 입력을 줄이려면 대상 도구의 네이티브 압축을 쓰거나 watch prompt 프리셋과 --last로 더 짧은 핸드오프 문서를 내보낸 뒤 생략 고지를 확인하세요.
