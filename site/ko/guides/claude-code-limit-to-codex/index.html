Claude Code가 사용 한도에 도달한 뒤 Codex에서 계속하기

Claude Code가 5시간 또는 주간 한도를 보고하면 /compact는 할당량을 복원하지 않습니다. Watch는 로컬 ~/.claude/projects/<encoded-cwd>/<session>.jsonl만 읽고, 작업 디렉터리를 확인한 뒤 그 기록을 Codex로 복사합니다. 원본 파일은 그대로입니다. 도구 이벤트는 텍스트가 될 수 있습니다.

Claude Code가 사용 한도(5시간 창 또는 주간 할당량)에 걸리거나 문제 해결이 막히면, 이 가이드는 작업 디렉터리와 세션 기록을 유지하고, 공식 가져오기 계획을 준비하며, Watch를 통해 OpenAI Codex에서 이어가는 방법을 설명합니다.

게시: 2026-09-17 수정: 2026-10-14 적용 버전: Watch v0.1.313
핵심 운영 경계

사용 한도는 주어진 시간 창에서 Claude를 얼마나 쓸 수 있는지를 제한하고, 컨텍스트 창 한도는 한 대화의 용량을 제한합니다. 컨텍스트 창만 가득 찼다면 Claude Code 안에서 /compact 또는 /clear를 사용하세요. 계정 사용 한도에 걸려 에이전트를 바꿔야 한다면, Watch가 저장된 로컬 세션 기록을 Codex로 전달합니다. Watch는 한도를 우회하거나 로컬 저장소 파일을 바꾸지 않습니다.

긴 엔지니어링 작업 중 Claude Code는 재설정 시각과 함께 플랜 한도에 도달했다고 보고할 수 있습니다. 지금까지 쌓인 추론, 실패한 반복, 명령 출력은 디스크에 남아 있습니다. Watch는 이 저장된 세션을 OpenAI Codex로 이어 주어, 조사를 직접 요약하지 않아도 새 도구가 앞선 컨텍스트를 볼 수 있게 합니다.

  1. 1단계: 소스 세션 ID와 작업 디렉터리 확인

    활성 Claude Code 세션 ID를 찾습니다. 기록은 ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl에 있습니다. worktree와 저장소가 어긋나지 않도록 디렉터리 경로(cwd)가 실제 프로젝트 작업 공간과 일치하는지 확인하세요.

  2. 2단계: 대상 프로젝트가 Codex Desktop에 있는지 확인

    이 가이드는 Watch의 --desktop-project 경로를 사용하며, 프로젝트가 Codex Desktop에 등록되어 app-server와 동기화되어 있어야 합니다. 계획을 준비하기 전에 Codex Desktop에서 대상 디렉터리를 여세요. 이는 이 데스크톱 핸드오프 경로의 가드입니다.

  3. 3단계: 가져오기 계획 준비 (Prepare)

    원본 세션을 선택하고 Watch Desktop에서 OpenAI Codex를 클릭하거나 prepare를 실행하세요. Watch는 원본, 작업 디렉터리, 대상 및 Codex 버전을 확인한 뒤 로컬 가져오기 계획을 저장합니다. 세션 가져오기를 제출하지 않으며 확인 단계에서 쓰는 Watch 대상 잠금도 잡지 않습니다. 네이티브 버전 확인이 자체 런타임 파일을 유지할 수 있으므로 완전히 쓰기가 없는 작업은 아닙니다.

  4. 4단계: 가져오기 확인 및 저하 항목 검토 (Confirm)

    미리보기의 메시지 수, 작업 디렉터리, 도구 호출 흔적을 검토합니다. 로컬 Codex app-server 가져오기 프로토콜로 전달을 시작하려면 명시적으로 확인하세요. 도구 호출 이벤트는 텍스트 표현으로 저하될 수 있습니다.

  5. 5단계: 대상 클라이언트를 독립적으로 실행 (Open)

    확인한 뒤 앱 인터페이스나 이어하기 명령으로 Codex Desktop을 엽니다. 가져오기와 열기는 엄격히 분리됩니다. 실행이 실패하면 가져오기 단계를 반복하지 말고 열기만 다시 시도하세요.

# 1. 환경 확인 및 로컬 계획 저장 (세션 가져오기 제출 없음) npm run watch -- import-codex prepare <claude-id> --cwd /abs/project/path --desktop-project --experimental --json # 2. 확인 및 가져오기 실행 (prepare 출력의 planId 사용) npm run watch -- import-codex confirm <plan-id> --experimental --json # 3. 로컬 실행 저널 읽기 (네이티브 클라이언트를 실행하지 않음) npm run watch -- import-codex status <plan-id> --json
그대로 인용한 요율 제한 및 할당량 오류 문구

터미널에 다음 메시지가 표시되면 대화 컨텍스트 한도가 아니라 계정 수준 사용량 한도에 도달한 것입니다: • "You have reached your 5-hour limit for Claude 3.7 Sonnet / Opus. Limit will reset at 14:30." • "Weekly usage limit reached. Your quota resets on Monday at 00:00 UTC." • "Rate limit exceeded for organization. Please wait before retrying." 이 경우 Claude Code 안에서 /compact를 실행해도 모델 할당량이 회복되거나 확보되지 않습니다.

Claude Code는 세션을 ~/.claude/projects/<encoded-cwd>/<session>.jsonl에 기록합니다. Watch 가져오기는 독점 tool_use 및 tool_result 이벤트를 Codex 롤아웃 세션 안의 구조화된 일반 텍스트 마크다운 레코드로 변환합니다. 이렇게 하면 대상 에이전트에 전체 조사 이력을 제공하면서도 Codex 재개 무결성을 깨뜨리는 위조 네이티브 블록을 만들지 않습니다.

안전 제약 및 고지

1. 무손실 보장 없음: 도구 호출 구조는 Codex에서 일반 텍스트로 저하되며, 모델 이어가기는 제한된 검증 범위 밖입니다. 2. 불확실한 상태에서는 중단: 프로세스가 중단되거나 시간 초과되면 잠금은 유지됩니다. 잠금을 강제로 지우거나 다시 제출하지 말고 status 명령으로 확인하세요. 3. 로컬 변환은 완전히 오프라인이 아님: Watch는 외부 서버 없이 동작하지만, Codex는 자체 app-server 데몬을 호출하고 상위 모델 제공자와 인증합니다.

자주 묻는 질문

Watch가 Claude Code 속도 제한을 우회하거나 재설정하나요?

아니요. Watch는 로컬 핸드오프 도구입니다. Anthropic 계정을 조작하거나 크레딧을 넣지 않으며, 로컬에 저장된 세션 산출물을 아직 용량이 있는 다른 에이전트로 전달합니다.

바로 Codex에 코딩을 계속하라고 지시할 수 있나요?

Codex는 가져온 대화 기록을 살펴보지만, 이어간 작업의 모델 성능은 대상 에이전트의 컨텍스트 용량에 달렸습니다. 새 코드 수정을 맡기기 전에 Codex에 현재 목표를 요약해 달라고 하는 것을 권합니다.

가져오기를 두 번 제출하면 어떻게 되나요?

Watch는 지속 잠금과 계획 멱등성을 적용합니다. 같은 소스와 디렉터리에 대한 중복 prepare 요청은 기록을 복제하지 않고 기존 계획을 반환합니다.
