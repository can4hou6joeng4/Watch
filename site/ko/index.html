QUESTIONS & BOUNDARIES
질문
작업 도중 Claude Code가 한도에 걸렸습니다. 어떻게 계속하나요?
Watch에 소스 세션 ID를 입력하고, 감지된 작업 디렉터리를 확인한 뒤 대상 에이전트를 고릅니다. Claude → Codex는 공식 프로젝트 우선 가져오기 미리보기를 보여 주고 확인한 뒤에만 쓰며, 대상은 따로 엽니다. 다른 대상은 기존 CLI 어댑터를 사용합니다. Watch는 사용 한도를 우회하지 않고 코드를 옮기지 않으며, 저장된 세션 기록만 전달합니다.
Claude Code에서 Codex로 전환해 같은 세션을 어떻게 이어가나요?
진입점은 두 가지입니다. 데스크톱 앱에서 소스 세션을 고르고 OpenAI Codex 카드를 클릭하거나(공식 단일 세션 가져오기: prepare → confirm → open), watch import-codex prepare <claude-id> --cwd <project> --desktop-project --experimental을 실행한 뒤 confirm을 실행합니다. 프로젝트는 이미 Codex Desktop에 있어야 합니다. 도구 기록은 Codex 쪽에서 텍스트가 될 수 있으며, 모델 이어가기는 검증 범위 밖입니다.
Claude Code 컨텍스트 창이 가득 찼습니다. Watch가 압축하나요?
아니요. 컨텍스트 압축이나 비우기는 Claude Code 자체의 /compact와 /clear입니다. Watch는 저장된 세션 기록 전체를 다른 에이전트로 옮깁니다. 대상 세션은 그 기록에서 시작하고 원래 세션은 그대로입니다. 들어가는지는 대상 도구의 컨텍스트 창에 달렸습니다.
Claude Code, Codex, OpenCode 세션 파일은 어디에 있고, 이전 대화는 어떻게 이어가나요?
Claude Code: ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl, claude --resume <id>로 이어가기. Codex: ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl, codex resume <id>로 이어가기. OpenCode: ~/.local/share/opencode/opencode.db, opencode -s <id>로 이어가기. Watch는 세션 ID로 이들을 찾고, 소속 작업 디렉터리를 보여 주며, 그 디렉터리의 연결된 핸드오프를 핸드오프 기록에 나열합니다.
watch status에 표시되는 세션이 재개 후 비어 있는 이유는 무엇인가요?
재개(resume) 명령은 기존 세션을 여는 일만 합니다. 비어 있는 세션은 보통 남은 턴이 없다는 뜻입니다. watch new로 만든 정상적인 빈 세션, 자리표시자 헤더만 남기고 내용이 지워진 세션, 또는 0바이트 파일일 수 있습니다. watch status에서 체인 끝 턴 수를 확인하세요. Watch는 0일 때 이유를 함께 알려 줍니다. Watch가 기록을 복구하지는 않습니다. 백업에서 파일을 복원하거나, watch adopt로 다른 세션에 다시 연결하거나, watch chain new로 새 체인을 시작하세요.
watch doctor의 Claude Code 정리 위험 경고는 확실한가요?
이는 체인 끝 파일의 수정 시각과 설정 우선순위로 정해진 cleanupPeriodDays로 계산한 추정치이며 삭제가 확인된 것은 아닙니다. Claude Code 체인 끝이면서 해당 명시 값이 공식 기본값인 30일보다 짧을 때만 표시됩니다. 더 높은 우선순위 설정이 값을 덮어쓰면 더 이상 보고하지 않고, 우선순위가 높은 파일을 읽을 수 없을 때 낮은 값으로 추측하지 않습니다. 워크트리와 서브모듈은 메인 체크아웃의 저장소 루트 설정을 조회하지 않으므로 추정이 보수적일 수 있습니다. 실제 적용 값은 Claude Code가 불러오는 모든 설정에 달려 있으며 --settings와 관리형 설정은 범위 밖입니다. 체인 끝 파일을 백업하거나 보존 기간을 늘리거나 watch switch로 다시 연결하세요. --strict를 주면 경고도 실패로 처리합니다.
Claude Code와 Codex를 함께 씁니다. 컨텍스트를 잃지 않고 어떻게 오가나요?
Watch는 둘을 순위 매기지 않습니다. 둘 다 설치되고 인증되어 있으면 세션을 넘깁니다. Claude → Codex는 공식 가져오기 미리보기를, Codex → Claude는 CLI 어댑터 변환을 사용하며, 둘 다 작업 디렉터리를 유지합니다. 일부 이벤트는 형식 사이에서 저하될 수 있으며, 결과에 저하된 항목이 나열됩니다.
기록이 Watch 클라우드 서버를 거치나요?
Watch에는 자체 중계 서버가 없습니다. 일부 네이티브 세션 생성 경로는 대상 CLI를 호출하고 그 네트워크 서비스에 접근할 수 있습니다. 모델 이어가기도 해당 서비스의 개인정보 및 모델 규칙을 따릅니다. 로컬 변환이 완전히 오프라인인 작업 흐름을 뜻하지는 않습니다.
변환은 무손실이거나 위험 없나요?
아니요. 새 파일과 전체 파일 교체는 원자적 쓰기와 재파싱 검사가 있고, 일부 추가 경로는 보호가 다릅니다. 공식 Codex 가져오기는 자체 기록, 대상 잠금, 읽기 검증을 사용합니다. 정확한 경계는 아키텍처를 보세요.

Antigravity CLI: 동일 제품 내 이어하기와 가져오기
공식 진입점은 검토했으며 Watch에는 통합하지 않았습니다. 이는 Antigravity 작업이지 Watch 변환 명령이 아닙니다.
공식 문서화됨 / Watch 미검증
01
특정 CLI 대화 이어하기
agy --conversation <conversation-id>
기존 Antigravity CLI 대화 ID를 이어갑니다. Claude, Codex 또는 데스크톱 대화를 가져오는 도구가 아닙니다.
02
작업 공간의 최신 대화 계속하기
agy -c
현재 작업 디렉터리의 최신 대화를 찾습니다. 기록이 없거나 삭제되면 새 대화가 시작될 수 있으므로, 부작용 없는 상태 확인이 아닙니다.
03
Antigravity 2.0에서 가져오기
/resume
CLI 세션 선택기에서 Antigravity 탭으로 전환하고, 데스크톱 대화를 선택한 뒤 가져오기를 확인합니다. 공식 문서는 복제된 기록, 컨텍스트, 도구 궤적을 설명합니다. Watch는 이를 네이티브로 검증하지 않았으며 외부 에이전트 가져오기 계약도 없습니다.
