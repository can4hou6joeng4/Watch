为什么 resume 打开是空会话：0 轮会话的识别与恢复

resume 打开空会话，通常是因为这条会话文件里没有可继续的对话：可能是 watch new 建出的合法空会话、内容被清空只剩占位头，也可能是 0 字节文件。用 watch status 看链尾行的轮数即可判断；Watch 不会替你重建历史，只能从备份恢复、换绑到另一条会话，或另起一条链。

Watch 会把链尾会话连同工作目录交到目标工具，resume 命令本身只负责打开。本指南从 status 的链尾行读起，区分 0 轮可读会话与 0 字节文件，并给出备份恢复、adopt 换绑与另起一条链三条路径。

发布日期: 2026-11-17 更新日期: 2026-11-17 适用版本: Watch v0.1.91
核心判断依据

resume（以及各家的原生恢复命令）只做一件事：打开指定的那条会话。它能不能接着聊，取决于那条会话文件里还有多少对话。文件在、读得出来，不等于有内容——这正是「看起来一切正常，打开什么也没有」的来源。Watch 从 v0.1.84 起在 open / switch / new / status 各入口分别披露这一档，两者要分开看。

会话文件有两种「空」：一种是 0 轮可读——文件里有合法的会话头（Claude Code 的占位 user 行、Codex rollout 的 session_meta），但没有任何对话轮次；另一种是 0 字节——进程被杀、磁盘写满或只写了一半，文件本身空了。两者的下一步不同：0 轮可读可能只是刚建出来的新会话，也可能内容被清空；0 字节则连会话元数据都可能一起丢了，Codex 的归属写在 rollout 首行，截成 0 字节后连反查都会失败。

  1. 步骤 1：看 status 的链尾行

    执行 watch status。链尾那一行在 v0.1.90 起会显示轮数，例如「← 链尾（12 轮）」；解析出 0 轮时写「（解析出 0 轮，原因见上方警告）」；文件读不出来或不存在时不给轮数。JSON 输出里对应 chainTipTurns 与 chainTipEmpty 两个字段，chainTipTurns 只在解析成功时存在。

  2. 步骤 2：按警告分档读原因

    同一份结果里，警告会区分：0 字节（「会话文件是空的」）、可读 0 轮（「解析出 0 轮（没有可继续的对话）」）、文件读不出来（权限或内容问题）、文件不存在（被删或被移走）。四档的下一步不同，不要只看到「空」就去换绑：文件不存在时先找文件，0 字节时先确认有没有备份。

  3. 步骤 3：确认是不是刚建出来的空会话

    watch new <provider> 建出来的会话本来就是空的，这是首条链的正常起点：下一次 switch 或 open --to 会把它当作目标，把来源内容并进去。如果链尾是这条新会话、你还没切过去，它就是 0 轮，不是损坏。

  4. 步骤 4：按原因恢复

    内容被清空：从备份恢复该文件，再重试 resume（Watch 不替你重建历史）。会话选错了：watch adopt <provider> --session <另一个会话 id> 换绑链尾。两边都要保留：watch chain new <新名字> 另起一条链，原链记录不动。0 字节且没有备份：这条会话已经没有可恢复的内容，按新会话处理。

# 1. 看链尾轮数与警告（v0.1.90 起链尾行带轮数） npm run watch -- status --json # 2. 链尾是空会话时的三条路 npm run watch -- adopt <provider> --session <another-session-id> # 换绑到另一条会话 npm run watch -- chain new <new-chain-name> # 另起一条链 # 3. 有备份时先恢复文件，再重试 resume npm run watch -- switch <provider>
边界与安全限制

1. Watch 不重建历史：0 轮会话只能从备份恢复，工具不会替你补写对话内容。 2. Watch 不会自动删除或修复 0 字节文件：那是你的原生会话文件，需要你自己决定恢复还是放弃。 3. 可读 0 轮不一定等于「被清空」：watch new 建出来的合法空会话就是这个形状，判断依据是上下文而不是轮数本身。 4. 这些披露只是读取本地文件得出的结论，不代表原生客户端一定能打开该会话；客户端验收仍按各自的版本与平台单独记录。

常见问题与限制

resume 打开什么也没有，是 Watch 把历史弄丢了吗？

通常不是。Watch 在交接时会先读来源、再用写前守卫与原子写追加到目标；0 轮会话多数是本来就空的（watch new 建出的空会话）或在此之前就被清空 / 截断的。要确认是不是 Watch 写入导致，先看交接结果里的轮数与 warnings，再对比备份文件。

0 轮和 0 字节有什么区别？

0 轮是文件可读、有合法会话头但没有对话，可能是新会话或只剩占位头；0 字节是文件本身空了，进程被杀、磁盘满或只写了一半都会造成，连会话元数据都可能一起丢失。前者可能只是还没开始，后者要优先找备份。

Watch 能帮我自动恢复被清空的会话吗？

不能。Watch 只读写本地会话文件，没有历史备份能力，也不会凭空重建对话。恢复只能来自你自己的备份（Time Machine、git 之外的副本、编辑器历史等），恢复文件后再 resume 即可。
