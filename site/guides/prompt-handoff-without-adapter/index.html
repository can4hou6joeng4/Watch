没有适配器时，用 watch prompt 交接会话

目标工具没有适配器或原生格式刚变化时，用 watch prompt <session-id> 生成只读 Markdown 交接文档；它不写会话文件、不启动 CLI，裁剪计数与降级说明写进正文和 --json 的 findings，目标端只能把它当作摘要而不是原生会话。

watch prompt 从本机原生会话记录生成一份 Markdown 摘要交接文档，不写任何文件、不启动目标 CLI。目标工具不会继承原生恢复能力，所有裁剪与来源状态都写在正文和 findings 里。

发布日期: 2026-11-18 更新日期: 2026-11-18 适用版本: Watch v0.1.201
什么时候用这一条

三条原生接力路径（启动器、链式交接、Codex 官方导入）都要求目标端有对应适配器与可验证的格式。目标 CLI 尚无适配器、原生格式刚变化，或你只想把上下文交给一个网页端助手时，用 watch prompt 生成只读摘要。它不是原生会话，只是可复制、可审阅的交接材料。

watch prompt 只读取来源助手在本机保存的会话记录，把轮次、工具过程与改动概览整理成 Markdown。文档头会写明来源助手、会话 ID、源文件、工作目录、工作树类型与当前分支；正文会逐项说明裁剪了多少轮、哪些内容被省略、用量是否可能偏少。整个命令不写会话文件、不建库、不启动任何 CLI。

  1. 步骤 1：确定来源会话与目录

    显式给出会话 ID，或用 --cwd 指定工作目录后省略 ID。省略 ID 时 Watch 按当前目录最新的可读会话自动挑选，并在文档头标注「自动挑选」；不确定时请显式指定，避免把另一条会话当成来源。

  2. 步骤 2：选择档位与窗口

    --profile minimal|standard|verbose|full 控制每条正文与过程记录的展开程度；--last N 只保留最近 N 个用户轮，会省略首条任务描述，正文会明确写出；--since-compact 从最近一次压缩摘要开始，找不到可用摘要时不裁剪并说明。

  3. 步骤 3：检查 findings 与来源状态

    加 --json 时，除 markdown 外还会返回 findings 与 warnings。degraded 表示已降级但说清了，skipped 表示按你的选项省略了内容；正文里的来源状态、坏行、用量与分支行用于判断这份文档能不能直接交给目标助手。工作目录不可用时另有 sourceCwd: { state }（missing / not-directory / denied / unknown，unknown 附 reason），健康目录不输出；普通仓库根返回结构化 sourceBranch（{ branch, repoRoot }，detached HEAD 为 { detached: true, repoRoot }），链接工作树返回 sourceWorktree（{ mainWorktree, branch }）。读取前后来源文件的大小或修改时间有变化时，sourceDrift（{ from, to, growth }）报告字节数和增长方向，无法确认正文包含了哪些记录。明确标记失败的工具调用另有 failedAttempts（工具、路径或命令与次数，不复制工具输出），正文保留「失败与中断」一节。

  4. 步骤 4：明确说明这是摘要交接

    把 Markdown 粘贴或保存成文件交给目标工具，并在首轮说明这是摘要交接而不是原生会话。目标端不能原生恢复，工具调用、思考过程与附件可能已被裁剪，未包含的部分无法从文档恢复。

# 1. 自动挑选当前目录最近的会话，生成 standard 档位摘要 npm run watch -- prompt --cwd /abs/project # 2. 显式指定会话，只保留最近 5 个用户轮 npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. 输出 JSON，检查 findings 与正文 npm run watch -- prompt <session-id> --cwd /abs/project --json
边界与安全限制

1. 只读：不写会话文件、不建本地库、不启动目标 CLI，生成的 Markdown 由你决定如何交付。 2. 摘要不等于原生会话：工具调用、思考过程与附件可能被裁剪，未包含的部分无法从文档恢复。 3. 裁剪必须计数：档位、--last 与 --since-compact 的省略会写进正文与 findings；找不到摘要时宁可不裁剪，也会说明。 4. 0 轮或来源损坏不会假装成功：正文会说明来源为空或坏行，无法确认的用量与坏行数会标注可能偏少或无法确认。

常见问题与限制

watch prompt 会写入目标工具的会话吗？

不会。它只读取来源记录并输出 Markdown，不写目标会话文件、不建库、不启动任何 CLI。需要目标端原生恢复时，请改用对应适配器的启动器或链式路径；支持官方导入的只有 Claude Code 到 Codex 桌面这一条。

为什么文档说「首条任务描述未保留」？

使用 --last N 时，Watch 从倒数第 N 条用户轮开始截取，更早的轮次会被省略，其中就包括最初的任务描述。需要完整背景时去掉 --last，或改用 --since-compact 与更高的档位；正文会按实际发生的裁剪逐项说明。

目标助手能像原生会话一样继续吗？

不能。目标端拿到的是一份摘要文档，不继承原生恢复能力，也看不到被裁剪的工具执行细节。建议在首轮要求目标助手复述任务目标与当前分支，确认理解后再分配修改任务。
