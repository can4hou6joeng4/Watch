Claude Code 达到使用限额后转入 Codex 继续实操指南

Claude Code 提示 5 小时或周限额时，/compact 不能恢复额度。Watch 只读取本机 ~/.claude/projects/<编码目录>/<会话>.jsonl，核对工作目录后转入 Codex；原文件不改，工具事件可能降级为文本。

当 Claude Code 遇到使用限额或排查停滞时，本指南说明如何保留工作目录与历史记录，通过 Watch 桌面端或 CLI 准备官方导入计划，并在核验后转入 OpenAI Codex 继续开发。

发布日期: 2026-09-17 更新日期: 2026-10-14 适用版本: Watch v0.1.1
核心判断依据

使用限额（Usage Limit）约束一段时间内可用额度，与单会话的上下文长度限制（Context Window）是两类不同问题。若仅是上下文过长，应优先在 Claude Code 内部执行 /compact 压缩；若确定是账户达到额度限制且需要更换工具，再使用 Watch 接力已保存的历史记录。Watch 不绕过限额，也不迁移磁盘代码。

在长任务调试过程中，Claude Code 界面可能会显示达到使用限额及预计重置时间。此时已探索的思路、报错结论和测试命令都保存在本机会话文件中。Watch 提供了将该会话记录转入 OpenAI Codex 的限定通道，确保新工具能够读取此前的上下文，而不必由人工重新向新 Agent 叙述整个背景。

  1. 步骤 1：核对来源会话 ID 与工作目录

    在原终端或会话目录确认 Claude Code 的 Session ID。Claude Code 会话记录保存在 ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl 中。检查当前项目目录（cwd）与会话记录所属目录完全一致，避免 Worktree 路径与主仓库路径发生混淆。

  2. 步骤 2：在 OpenAI Codex 中预先建立项目

    依据官方通用导入协议要求，目标项目必须已经存在于 Codex Desktop 中。如果尚未添加，请先在 Codex Desktop 中打开该目录并完成首次信任确认，确保 Codex 的项目数据库能识别该工作空间。

  3. 步骤 3：准备导入计划并核查字段（Prepare）

    在 Watch 桌面端选择来源会话并点击 OpenAI Codex，或在终端执行 prepare 命令生成导入计划。此阶段仅建立计划并核验目标锁状态，不会向目标文件写入任何记录。

  4. 步骤 4：确认导入并核查降级项（Confirm）

    在预览窗口核对检测到的来源路径、消息条数与工具调用记录后，显式点击确认导入。Watch 将调用本地 Codex app-server 的会话导入接口并写入目标记录。工具调用与执行结果在 Codex 侧可能降级为文本展示。

  5. 步骤 5：独立打开目标客户端（Open）

    导入完成后，通过桌面端或目标恢复命令独立唤起 Codex Desktop。导入过程与打开客户端是严格分离的两个步骤；如果打开失败，仅需重试打开动作，切勿重复发起导入。

# 1. 准备导入计划（只读探测与生成计划） npm run watch -- import-codex prepare <claude-id> --cwd /abs/project/path --desktop-project --experimental --json # 2. 明确确认并写入（使用计划返回的 planId） npm run watch -- import-codex confirm <plan-id> --json # 3. 查看执行状态（发生异常时只读查询） npm run watch -- import-codex status <plan-id> --json
高频限额报错原文对照（Error Signatures）

终端出现以下明确提示时，表明触及了账户级额度限制而非单会话上下文容量： • "You have reached your 5-hour limit for Claude 3.7 Sonnet / Opus. Limit will reset at 14:30." • "Weekly usage limit reached. Your quota resets on Monday at 00:00 UTC." • "Rate limit exceeded for organization. Please wait before retrying." 此类情况下，在 Claude Code 内部执行 /compact 无法重置或释放可用额度。

Claude Code 的会话记录保存在 ~/.claude/projects/<编码目录>/<会话>.jsonl。当执行 Watch 导入时，Claude 格式中的工具调用事件（如 tool_use: Bash 与 tool_result）会被结构化重构为 Codex 可读的只读文本记录并写入 rollout 日志，确保接手的 Agent 拥有清晰的上下文足迹，同时杜绝伪造原生结构破坏 Codex 的状态机。

边界与安全限制

1. 不支持无损还原：工具调用记录在 Codex 端将作为文本参考呈现，模型的自动延续不在当前限定验收范围内。 2. 遇到 uncertain 状态必须立即停止：若提交过程中断或网络超时，状态会保持锁定，请通过 status 命令只读排查，严禁强制删除锁或重复再次提交。 3. 本地转换不等于全流程离线：Watch 自身无中继服务器，但在触发 Codex 原生接口时，Codex 会遵循其本地配置与模型云端鉴权。

常见问题与限制

Claude Code 限额后，Watch 会帮我自动续订或绕过限制吗？

不会。Watch 是本地会话接力工具，不接触用户账户、不提供额度注入、也不破解官方限制。它的作用是将您此前已保存在本地的调试足迹转录给另一个有可用额度的 Agent。

转入 Codex 后，是否可以直接继续提问模型？

Codex 会加载此前会话的消息记录，但模型针对接力会话的续写质量受目标 Agent 自身上下文长度和 Prompt 解释能力影响。建议在首轮提问中先要求 Codex 简要复述任务目标，确认理解后再分配代码编辑任务。

如果不小心点了两次导入，会导致会话重复或冲突吗？

不会。Watch 设计了持久锁与计划幂等机制。同一来源与工作目录在未完成前不会重复创建新计划；对已完成计划再次执行将保持原样并返回已导入的会话指向。
