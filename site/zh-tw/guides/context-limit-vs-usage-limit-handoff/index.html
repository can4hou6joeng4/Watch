Claude Code 中上下文視窗已滿與用量上限：實作指南

上下文視窗已滿表示這段對話太長：請在 Claude Code 內執行 /compact 或 /clear。帳號上限會標出重設時間，此時 /compact 沒有作用。Watch 既不會放大視窗，也不會恢復配額。它把已儲存的會話複製到另一個仍能執行的 Agent。

在 Claude Code 處理複雜工作而中斷時，學會區分上下文視窗耗盡與帳號用量配額，並適當使用 /compact 或 Watch 的多 Agent 會話交接。

發布日期: 2026-09-21 更新日期: 2026-10-14 適用版本: Watch v0.1.376
關鍵操作邊界：兩種不同的實質上限

1. 上下文視窗上限：限制模型在單一會話中能同時處理的權杖總數。滿了時，模型會提示壓縮，或自動壓縮紀錄。 2. 帳號用量上限：限制滾動時間視窗內的總請求量或權杖消耗（例如 5 小時重設或每週配額）。達到時，Claude 會顯示「You have exceeded your current usage limit」，並附上重設時間。

開發者常把上下文視窗已滿與帳號速率上限搞混，或以為會話交接工具會人為放大 Claude 的上下文視窗。Watch 不會繞過用量配額，也不會取代 Claude 的原生壓縮。理解差異才能選對恢復路徑。

  1. 步驟 1：查看終端機錯誤訊號以辨識上限類型

    若 Claude 回報「exceeded your limit」並附重設時間，那是帳號用量上限：執行 /compact 會失敗，因為模型配額已用盡；請等待重設，或交接給 Codex／OpenCode。若 Claude 回報對話長度上限或高延遲，那是上下文視窗上限：請執行 /compact。

  2. 步驟 2：對上下文長度使用原生處理（/compact 與 /clear）

    在 Claude Code 內執行 /compact，把對話紀錄壓縮成精簡摘要。若不再需要先前的調查回合，執行 /clear，在目前工作區重新開始。

  3. 步驟 3：達到帳號用量配額時保存會話狀態

    確認 Claude Code 已將會話文字稿寫入 ~/.claude/projects/<enc-cwd>/<session-id>.jsonl。使用 Watch 檢查工作目錄，以及 Codex 或 OpenCode 目標是否就緒。

  4. 步驟 4：交接給另一個 Agent，不必重述脈絡

    使用 Watch 把已記錄的推理與測試結果轉成目的地 Agent 的格式，再在新的 CLI 中帶著先前脈絡繼續。

限制類別典型錯誤與表現處理機制與命令是否需要 Watch
上下文超限（Context Limit）Prompt too long for context window在 Claude 終端機執行 /compact 壓縮或 /clear 清空否（工具內部自行消化）
5 小時帳戶限額（5-Hour Limit）5-hour limit reached. Resets at HH:MM/compact 無效；等待重置或切換工具是（轉入 Codex / OpenCode）
每週總配額耗盡（Weekly Quota）Weekly usage limit reached for org/compact 無效；切換至其他可用 Agent是（轉入其他備選 Agent）
終端機或網路中斷（Crash / Restart）Process exit / Terminal closed執行 claude --resume <id> 恢復原會話否（原生 CLI 恢復即可）

安全限制與免責聲明

1. Watch 不會擴大單一 Agent 的上下文：在新 Agent 繼續時，仍受該 Agent 自己的上下文視窗上限約束。 2. 工具呈現會改變：Claude 的 tool_use 事件在 Codex 會降級為結構化文字，以避免結構解析錯誤。 3. 不要突然終止程序：關閉終端機視窗前，請確認會話檔已寫入。

常見問題

/compact 會捨棄磁碟上已做的程式修改嗎？

不會。檔案修改已存在於本機檔案系統。/compact 只壓縮記憶體中的對話紀錄。不過，詳細的次要錯誤訊息可能會被摘要。

為什麼達到帳號用量上限時 /compact 會失敗？

/compact 用於整理會話歷史，不會恢復帳戶額度；額度耗盡時，生成摘要的請求也可能被限額阻止。你可以等待重置，或選擇仍可用的工具，依已驗證的路徑交接；也可用 watch prompt 匯出裁剪後的交接文件，再手動交給目標工具。Watch 不恢復、也不繞過額度。

交接給 Codex 或 OpenCode 會重設上下文嗎？

接力會把已儲存且能轉換的歷史帶入目標會話，這些歷史仍佔用目標模型的上下文。Watch 不擴大視窗，也不依目標 token 預算自動摘要，因此無法保證消除上下文飽和。需要縮短輸入時，可使用目標工具的原生壓縮，或透過 watch prompt 的檔位與 --last 選項匯出較短的交接文件，並核對省略項。
