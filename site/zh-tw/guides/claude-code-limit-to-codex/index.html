Claude Code 達到用量上限後在 Codex 繼續

當 Claude Code 回報五小時或每週上限時，/compact 不會恢復配額。Watch 只讀取本機的 ~/.claude/projects/<encoded-cwd>/<session>.jsonl，核對工作目錄，並把該紀錄複製到 Codex。原始檔案維持不變。工具事件可能變成文字。

當 Claude Code 達到用量上限（5 小時視窗或每週配額），或除錯停滯時，本指南說明如何保留工作目錄與會話紀錄、準備官方匯入計畫，並透過 Watch 在 OpenAI Codex 繼續。

發布日期: 2026-09-17 更新日期: 2026-10-14 適用版本: Watch v0.1.446
關鍵操作邊界

用量上限限制的是一段時間內能使用多少 Claude，而上下文視窗上限限制的是單次對話的容量。若只是上下文視窗已滿，請在 Claude Code 內使用 /compact 或 /clear。若已達到帳號用量上限且需要切換 Agent，Watch 會把已儲存的本機會話紀錄轉入 Codex。Watch 不會繞過上限，也不會改動本機儲存庫檔案。

在長時間的工程工作中，Claude Code 可能回報你已達到方案上限，並附上重設時間。截至目前累積的推理、失敗迭代與命令輸出仍留在磁碟上。Watch 把這份已儲存的會話接到 OpenAI Codex，讓新工具能檢視先前脈絡，而不必由你手動摘要這次調查。

  1. 步驟 1：核對來源會話 ID 與工作目錄

    找出目前使用中的 Claude Code 會話 ID。紀錄存放於 ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl。請確認目錄路徑（cwd）與實際專案工作區一致，以免 Worktree 與儲存庫對不上。

  2. 步驟 2：確認目標專案已存在於 Codex Desktop

    本指南使用 Watch 的 --desktop-project 路徑，要求專案已在 Codex Desktop 中登記並同步到 app-server。請先在 Codex Desktop 中開啟目標目錄，再準備匯入計畫；這是該桌面接力路徑的保護條件。

  3. 步驟 3：準備匯入計畫（Prepare）

    在 Watch 桌面端選擇來源會話並點選 OpenAI Codex，或執行 prepare。Watch 核對來源、工作目錄、目標與 Codex 版本，並儲存本機匯入計畫；此時不提交會話匯入，也不取得確認階段的 Watch 目標鎖。原生版本檢查可能維護自身的執行階段檔案，因此不能把這一步稱為全流程零寫入。

  4. 步驟 4：確認匯入並檢視降級項目（Confirm）

    檢視預覽的訊息數量、工作目錄與工具呼叫軌跡。明確確認後，才會透過本機 Codex app-server 匯入協定開始轉移。請注意，工具呼叫事件可能降級為文字呈現。

  5. 步驟 5：獨立啟動目標用戶端（Open）

    確認後，使用應用程式介面或繼續命令開啟 Codex Desktop。匯入與開啟嚴格分開：若啟動失敗，只重試開啟，不要重複匯入階段。

# 1. 核對環境並儲存本機計畫（不提交會話匯入） npm run watch -- import-codex prepare <claude-id> --cwd /abs/project/path --desktop-project --experimental --json # 2. 明確確認並寫入（使用計畫回傳的 planId） npm run watch -- import-codex confirm <plan-id> --experimental --json # 3. 唯讀查詢本機執行日誌（不啟動原生用戶端） npm run watch -- import-codex status <plan-id> --json
高頻限額錯誤原文對照（Error Signatures）

終端機出現以下明確提示時，代表觸及了帳戶層級的額度限制，而非單一會話的上下文容量： • "You have reached your 5-hour limit for Claude 3.7 Sonnet / Opus. Limit will reset at 14:30." • "Weekly usage limit reached. Your quota resets on Monday at 00:00 UTC." • "Rate limit exceeded for organization. Please wait before retrying." 此類情況下，在 Claude Code 內執行 /compact 無法重置或釋放可用額度。

Claude Code 的會話紀錄存放在 ~/.claude/projects/<編碼目錄>/<會話>.jsonl。執行 Watch 匯入時，Claude 格式中的工具呼叫事件（如 tool_use: Bash 與 tool_result）會被結構化重建為 Codex 可讀的唯讀文字紀錄並寫入 rollout 日誌，確保接手的 Agent 擁有清晰的上下文足跡，同時杜絕偽造原生結構破壞 Codex 的狀態機。

安全限制與免責聲明

1. 不保證無損：工具呼叫結構在 Codex 會降級為純文字，模型續寫也不在有限驗證範圍內。 2. 狀態不明時停止：若程序中斷或逾時，鎖定會保留。請用 status 命令檢查，不要強行刪除鎖定或重新提交。 3. 本機轉換並非完全離線：Watch 雖不使用外部伺服器，但 Codex 會呼叫自己的 app-server 常駐程序，並向其上游模型提供者驗證。

常見問題

Watch 會繞過或重設 Claude Code 的速率上限嗎？

不會。Watch 是本機交接工具。它不會竄改 Anthropic 帳號或注入額度；它把本機已儲存的會話產物轉到另一個仍有可用容量的 Agent。

我可以立刻請 Codex 繼續寫程式嗎？

Codex 會檢視匯入的對話紀錄，但續寫任務的模型表現取決於目標 Agent 的上下文容量。建議先請 Codex 摘要目前目標，再指派新的程式修改。

如果我提交兩次匯入會怎樣？

Watch 強制使用持續鎖定與計畫冪等。對相同來源與目錄重複的 prepare 請求會回傳既有計畫，不會重複建立紀錄。
