Claude Opus 5.5 對五小時上限改變了什麼，以及仍被限制時該怎麼做

Opus 5.5 提高了 Pro、Max、Team 與按席位計費 Enterprise 的五小時上限，並新增一次可儲存的重設。它並沒有取消上限。Watch 不會讀取或提高 Claude 配額。只有在該官方重設仍然不夠時，才把已儲存的會話交給 Codex。

Opus 5.5 提高了所列 Claude 方案的五小時用量上限，並新增一個可儲存的速率上限重設。Watch 不會恢復 Claude 配額。若你仍被阻擋，請使用既有的 Codex 交接。

發布日期: 2026-09-23 更新日期: 2026-10-14 適用版本: Watch v0.1.422
公告實際改變了什麼

2026 年 9 月 22 日，Anthropic 推出 Claude Opus 5.5。關於上限，公告只說兩件事：Pro、Max、Team 與按席位計費 Enterprise 方案的五小時用量上限提高，以及訂閱使用者會得到一次可儲存、並可在自選時機使用的速率上限重設。它沒有說每週上限已取消，也沒有說任何第三方工具可以補回 Claude 配額。

更快或更便宜的模型不會把兩種上限合併。上下文視窗已滿仍是對話太長：請在 Claude Code 內壓縮。帳號用量上限仍會在視窗重設前停止請求。Opus 5.5 放寬的是上述方案的五小時用量視窗。它不會放大上下文視窗。

  1. 步驟 1：看產品回報的是哪一種上限

    若訊息說你已超過目前用量上限並附有重設時間，那是帳號上限。/compact 不會恢復該配額。關於對話長度的訊息則是上下文視窗上限。請在 Claude Code 內壓縮。更換模型名稱對這兩種情況都不是解法。

  2. 步驟 2：使用方案自己的五小時上限與已儲存的重設

    較高的五小時上限適用於 Pro、Max、Team 與按席位計費 Enterprise。可儲存的重設屬於 Claude 訂閱。Watch 尚未驗證有哪個 CLI 旗標能儲存它，因此不要以為 Watch 命令已替你保留這次重設。若在 Anthropic 提供的重設之後仍被阻擋，再考慮另一個 Agent。

  3. 步驟 3：只有在 Claude 仍被阻擋時才交接

    Watch 不會讀取、提高或繞過 Claude 配額。它把已儲存在磁碟上的會話複製到 Codex，並保留工作目錄。請依既有指南「Claude Code 達到用量上限後在 Codex 繼續」：檢查會話 id 與目錄，然後分別 prepare、confirm，並另行開啟 Codex。

熱門查詢不能證明什麼

查詢「opus 5.5」曾出現在新加坡與澳洲 48 小時內的熱門搜尋。那是近似的熱門分組，不是搜尋量的全球排名，也不能證明每週上限、上下文長度或會話檔有所改變。同一輪新聞中的其他模型名稱與這次交接無關。工具呼叫在 Codex 端仍可能降級為文字。

常見問題

Claude Opus 5.5 取消了五小時用量上限嗎？

沒有。Anthropic 提高了 Pro、Max、Team 與按席位計費 Enterprise 的五小時上限。上限仍然存在，達到時仍會顯示重設時間。

Watch 可以替我使用可儲存的速率上限重設嗎？

不行。該控制屬於 Claude 訂閱。Watch 不會登入 Claude 帳號，也不會儲存或使用這次重設。

上限提高之後，我還要把會話交給 Codex 嗎？

只有在官方重設仍然不夠、且 Codex 仍有配額時才需要。交接步驟並沒有因 Opus 5.5 而改變。
