為什麼 resume 開啟是空會話：0 回合會話的辨識與恢復

resume 開啟空會話，通常是因為這條會話檔案裡沒有可繼續的對話：可能是 watch new 建立的合法空會話、內容被清空只剩佔位標頭，也可能是 0 位元組檔案。用 watch status 看鏈尾列的回合數即可判斷；Watch 不會替你重建歷史，只能從備份還原、改綁到另一條會話，或另開一條鏈。

Watch 會把鏈尾會話連同工作目錄交到目標工具，resume 命令本身只負責開啟。本指南從 status 的鏈尾列讀起，區分 0 回合可讀會話與 0 位元組檔案，並給出備份還原、adopt 改綁與另開一條鏈三條路徑。

發布日期: 2026-11-17 更新日期: 2026-11-23 適用版本: Watch v0.1.401
核心判斷依據

resume（以及各家的原生恢復命令）只做一件事：開啟指定的那條會話。它能不能接著聊，取決於那條會話檔案裡還有多少對話。檔案在、讀得出來，不等於有內容——這正是「看起來一切正常，開啟卻什麼也沒有」的來源。Watch 從 v0.1.84 起在 open / switch / new / status 各入口分別揭露這一檔，兩者要分開看。

會話檔案有兩種「空」：一種是 0 回合可讀——檔案裡有合法的會話標頭（Claude Code 的佔位 user 列、Codex rollout 的 session_meta），但沒有任何對話回合；另一種是 0 位元組——處理程序被終止、磁碟寫滿或只寫了一半，檔案本身空了。兩者的下一步不同：0 回合可讀可能只是剛建立的新會話，也可能內容被清空；0 位元組則連會話中繼資料都可能一起遺失，Codex 的歸屬寫在 rollout 首列，截成 0 位元組後連反查都會失敗。

還有一種「開啟是空的」發生在檔案已經不在的時候：Claude Code 會依 cleanupPeriodDays 在會話啟動後清理過期的 transcript，官方預設 30 天，這個鍵允許寫在任意設定檔裡，專案設定可以覆蓋使用者設定。逾期會話不再出現在 /resume 裡，Watch 的 open 與 resume 自然也找不到。watch doctor 會以唯讀方式核對使用者設定、目前目錄的專案設定，以及在一般 Git 儲存庫子目錄執行時的儲存庫根目錄本機設定（scope 為 repository-local），低於預設值或無法確認時給出警告；它不會把這個值說成實際生效值，--settings 與受管理設定也不在偵測範圍。調高保留期只能減少以後被清理的會話，不會恢復已經刪除的檔案——重要會話請提前備份。

  1. 步驟 1：看 status 的鏈尾列

    執行 watch status。鏈尾那一列在 v0.1.90 起會顯示回合數，例如「← 鏈尾（12 回合）」；解析出 0 回合時寫「（解析出 0 回合，原因見上方警告）」；檔案讀不出來或不存在時不給回合數。JSON 輸出對應 chainTipTurns 與 chainTipEmpty 兩個欄位，chainTipTurns 只在解析成功時存在。多條鏈時，watch chain list 的鏈尾列同樣帶回合數（v0.1.93）；不確定時，watch doctor 的 store.emptyTips 會列出解析出 0 回合的鏈尾（v0.1.92）。watch new 的 --json 也回報實際解析出的回合數（v0.1.94）：claude / pi 會寫出一列佔位 user，所以顯示 1 回合，codex / grok / opencode 是 0 回合。watch usage 從 v0.1.95 起把「解析出 0 回合的空會話」與「有內容卻沒記錄 usage」分檔，新建的空鏈不會再被說成統計缺失；v0.1.96 起內容檔案的壞列與 Codex 壓縮紀錄也不再冒充空會話；v0.1.97 起旁路用量仍可讀時，內容檔案被刪除也會明說對話已遺失；v0.1.98 起內容壞列會進入警告與欄位，不再靜默；v0.1.99 起已有回合的內容壞列不再被說成「解析出 0 回合」；v0.1.100 起文字摘要依 0 回合與已讀到用量分檔，壞列掃描失敗會說明數量未知；v0.1.101 起 0 回合摘要不再附帶「用量已計入」，並更正 v0.1.98 的歷史表述。

  2. 步驟 2：依警告分檔讀原因

    同一份結果裡，警告會區分：0 位元組（「會話檔案是空的」）、可讀 0 回合（「解析出 0 回合（沒有可繼續的對話）」）、檔案讀不出來（權限或內容問題）、檔案不存在（被刪除或被移走）、內容解析失敗（檔案讀得出來，但會話格式損壞或 OpenCode 資料庫缺少正文表等；v0.1.279 起警告寫「內容解析失敗，Watch 未能核對它的回合數與收尾狀態」）。五檔的下一步不同，不要只看到「空」就去改綁：檔案不存在時先找檔案，0 位元組時先確認有沒有備份；解析失敗這一檔連「是不是空」都不知道，不能當空會話處理，先用 watch switch 或 watch open 開啟一次，讓預檢給出具體原因。

  3. 步驟 3：確認是不是剛建立的空會話

    watch new <provider> 建立的會話本來就是空的，這是首條鏈的正常起點：下一次 switch 或 open --to 會把它當作目標，把來源內容併進去。如果鏈尾是這條新會話、你還沒切過去，它就是 0 回合，不是損壞。

  4. 步驟 4：依原因恢復

    內容被清空：從備份還原該檔案，再重試 resume（Watch 不替你重建歷史）。會話選錯了：watch adopt <provider> --session <另一個會話 id> 改綁鏈尾。兩邊都要保留：watch chain new <新名稱> 另開一條鏈，原鏈紀錄不動。0 位元組且沒有備份：這條會話已經沒有可恢復的內容，視為新會話處理。

# 1. 看鏈尾回合數與警告（v0.1.90 起鏈尾列帶回合數） npm run watch -- status --json # 2. 鏈尾是空會話時的三條路 npm run watch -- adopt <provider> --session <another-session-id> # 改綁到另一條會話 npm run watch -- chain new <new-chain-name> # 另開一條鏈 # 3. 有備份時先還原檔案，再重試 resume npm run watch -- switch <provider>
邊界與安全限制

1. Watch 不重建歷史：0 回合會話只能從備份恢復，工具不會替你補寫對話內容。 2. Watch 不會自動刪除或修復 0 位元組檔案：那是你的原生會話檔案，需要你自己決定恢復還是放棄。 3. 可讀 0 回合不一定等於「被清空」：watch new 建立的合法空會話就是這個形狀，判斷依據是上下文而不是回合數本身。 4. 這些揭露只是讀取本機檔案得出的結論，不代表原生用戶端一定能開啟該會話；用戶端驗收仍依各自的版本與平台單獨記錄。

常見問題

resume 開啟什麼也沒有，是 Watch 把歷史弄丟了嗎？

通常不是。Watch 在交接時會先讀來源、再用寫入前守衛與原子寫入附加到目標；0 回合會話多數是本來就空的（watch new 建立的空會話），或在此之前就被清空 / 截斷的。要確認是不是 Watch 寫入造成，先看交接結果裡的回合數與 warnings，再對比備份檔案。

0 回合和 0 位元組有什麼區別？

0 回合是檔案可讀、有合法會話標頭但沒有對話，可能是新會話或只剩佔位標頭；0 位元組是檔案本身空了，處理程序被終止、磁碟寫滿或只寫了一半都會造成，連會話中繼資料都可能一起遺失。前者可能只是還沒開始，後者要優先找備份。

Watch 能幫我自動恢復被清空的會話嗎？

不能。Watch 只讀寫本機會話檔案，沒有歷史備份能力，也不會憑空重建對話。恢復只能來自你自己的備份（Time Machine、git 之外的副本、編輯器歷史等），還原檔案後再 resume 即可。

Claude Code 會自己刪掉舊會話嗎？

會。官方 settings 裡的 cleanupPeriodDays 預設 30 天，會話啟動後背景清理超過期限的 transcript，逾期會話不再出現在 /resume 裡。它允許寫在任意設定檔裡，專案設定可以覆蓋使用者設定；watch doctor 會以唯讀方式核對使用者設定、目前目錄的專案設定與儲存庫根目錄本機設定，但 --settings 與受管理設定不在偵測範圍，報告不代表實際生效值。調高這個值只能減少以後被刪除的會話，不能找回已經刪掉的檔案。
