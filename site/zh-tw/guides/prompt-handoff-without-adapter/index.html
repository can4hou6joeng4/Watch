沒有轉接器時，用 watch prompt 交接會話

目標工具沒有轉接器或原生格式剛變化時，用 watch prompt <session-id> 產生唯讀 Markdown 交接文件；它不寫會話檔案、不啟動 CLI，裁剪計數與降級說明寫進正文和 --json 的 findings，目標端只能把它當作摘要而不是原生會話。

watch prompt 從本機原生會話紀錄產生一份 Markdown 摘要交接文件，不寫任何檔案、不啟動目標 CLI。目標工具不會繼承原生恢復能力，所有裁剪與來源狀態都寫在正文和 findings 裡。

發布日期: 2026-11-18 更新日期: 2026-11-18 適用版本: Watch v0.1.475
什麼時候用這一條

三條原生接力路徑（啟動器、鏈式交接、Codex 官方匯入）都要求目標端有對應的轉接器與可驗證的格式。目標 CLI 尚無轉接器、原生格式剛變化，或你只想把上下文交給一個網頁端助手時，用 watch prompt 產生唯讀摘要。它不是原生會話，只是可複製、可審閱的交接材料。

watch prompt 只讀取來源助手在本機儲存的會話紀錄，把回合、工具過程與改動概覽整理成 Markdown。文件開頭會寫明來源助手、會話 ID、來源檔案、工作目錄、工作樹類型與目前分支；正文會逐項說明裁剪了多少回合、哪些內容被省略、用量是否可能偏少。整個命令不寫會話檔案、不建資料庫、不啟動任何 CLI。

  1. 步驟 1：確定來源會話與目錄

    明確給出會話 ID，或用 --cwd 指定工作目錄後省略 ID。省略 ID 時，Watch 依目前目錄最新的可讀會話自動挑選，並在文件開頭標註「自動挑選」；不確定時請明確指定，避免把另一條會話當成來源。

  2. 步驟 2：選擇檔位與視窗

    --profile minimal|standard|verbose|full 控制每條正文與過程記錄的展開程度；--last N 只保留最近 N 個使用者回合，會省略首條任務描述，正文會明確寫出；--since-compact 從最近一次壓縮摘要開始，找不到可用摘要時不裁剪並說明。

  3. 步驟 3：檢查 findings 與來源狀態

    加上 --json 時，除 markdown 外還會回傳 findings 與 warnings。degraded 表示已降級但說清楚了，skipped 表示依你的選項省略了內容；正文裡的來源狀態、壞列、用量與分支列用於判斷這份文件能不能直接交給目標助手。工作目錄不可用時另有 sourceCwd: { state }（missing / not-directory / denied / unknown，unknown 附 reason），健康目錄不輸出；一般儲存庫根目錄回傳結構化 sourceBranch（{ branch, repoRoot }，detached HEAD 為 { detached: true, repoRoot }），連結工作樹回傳 sourceWorktree（{ mainWorktree, branch }）。讀取前後來源檔案的大小或修改時間有變化時，sourceDrift（{ from, to, growth }）報告位元組數與增長方向，無法確認正文包含了哪些紀錄。明確標記失敗的工具呼叫另有 failedAttempts（工具、路徑或命令與次數，不複製工具輸出），正文保留「失敗與中斷」一節。產生文件時，「改動概覽」還會核對清單裡的檔案是否仍在會話目錄裡：確定不在的標「磁碟上已不在」，無法確認的標「沒能核對」，本會話修補刪除或移走的標「已刪除 / 移走」，會話目錄之外的路徑單獨計數；開頭也會寫明這次核對了幾個、或為什麼沒核對。--json 另有 manifestDisk（checked / missing / unverified / outside / removed），缺欄位不代表都還在。未閉合的工具呼叫與懸空的尾輪會以 stats.danglingToolCalls、stats.unansweredTail 及對應 finding 回報：前者以整條工作階段計數，後者只在最後一個使用者輪有實際文字時生效；兩者都寫進文件詮釋資料與「繼續工作」，--json 保留同名欄位。

  4. 步驟 4：明確說明這是摘要交接

    把 Markdown 貼上或存成檔案交給目標工具，並在首回合說明這是摘要交接而不是原生會話。目標端不能原生恢復，工具呼叫、思考過程與附件可能已被裁剪，未包含的部分無法從文件恢復。

# 1. 自動挑選目前目錄最近的會話，產生 standard 檔位摘要 npm run watch -- prompt --cwd /abs/project # 2. 明確指定會話，只保留最近 5 個使用者回合 npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. 輸出 JSON，檢查 findings 與正文 npm run watch -- prompt <session-id> --cwd /abs/project --json
邊界與安全限制

1. 唯讀：不寫會話檔案、不建本機資料庫、不啟動目標 CLI，產生的 Markdown 由你決定如何交付。 2. 摘要不等於原生會話：工具呼叫、思考過程與附件可能被裁剪，未包含的部分無法從文件恢復。 3. 裁剪必須計數：檔位、--last 與 --since-compact 的省略會寫進正文與 findings；找不到摘要時寧可不裁剪，也會說明。 4. 0 回合或來源損壞不會假裝成功：正文會說明來源為空或壞列，無法確認的用量與壞列數會標註可能偏少或無法確認。

常見問題

watch prompt 會寫入目標工具的會話嗎？

不會。它只讀取來源紀錄並輸出 Markdown，不寫目標會話檔案、不建資料庫、不啟動任何 CLI。需要目標端原生恢復時，請改用對應轉接器的啟動器或鏈式路徑；支援官方匯入的只有 Claude Code 到 Codex 桌面這一條。

為什麼文件說「首條任務描述未保留」？

使用 --last N 時，Watch 從倒數第 N 條使用者回合開始截取，更早的回合會被省略，其中就包括最初的任務描述。需要完整背景時去掉 --last，或改用 --since-compact 與更高的檔位；正文會依實際發生的裁剪逐項說明。

目標助手能像原生會話一樣繼續嗎？

不能。目標端拿到的是一份摘要文件，不繼承原生恢復能力，也看不到被裁剪的工具執行細節。建議在首回合要求目標助手複述任務目標與目前分支，確認理解後再分配修改任務。
