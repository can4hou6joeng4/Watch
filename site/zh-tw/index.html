UNDER THE HOOD
核心機制
防護依路徑而異。範圍狹窄的檢查並非通用的安全保證。桌面應用程式有四個檢視（會話交接、交接紀錄、支援路徑、設定），並提供淺色、深色與跟隨系統外觀。
01
定位來源與 cwd
以原生會話 ID 找出已儲存的紀錄，並保留實際的 cwd。既有的 Worktree 不會被悄悄換成儲存庫根目錄。
02
確認官方匯入
Codex 路徑會綁定目標目錄與設定，並附有執行日誌與持續鎖定。結果不明時會查詢，不會盲目重新提交。
03
揭露格式限制
把已記錄的訊息與事件轉入目標格式。保留程度各不相同；內部往返並不能證明原生續寫。
04
匯入與開啟分開
若匯入後開啟失敗，只重試開啟。終端機啟動失敗時，會在檢查控制字元後才退回複製命令，不再做一次轉移。

ANSWERS FIRST
指南
每篇指南先給出可獨立閱讀的答案，再列出步驟。Watch 不會繞過用量上限，也不會為模型排名。
Claude Code 達到用量上限後在 Codex 繼續
當 Claude Code 回報五小時或每週上限時，/compact 不會恢復配額。Watch 只讀取本機的 ~/.claude/projects/<encoded-cwd>/<session>.jsonl，核對工作目錄，並把該紀錄複製到 Codex。原始檔案維持不變。工具事件可能變成文字。
閱讀指南
OpenCode、Claude 與 Codex 雙向會話交接指南
OpenCode 把會話放在 ~/.local/share/opencode/opencode.db。WATCH_OPENCODE_DB 會讓 Watch 指向另一個檔案。Watch 在同一個 SQLite 交易中寫入 sessions、messages 與 parts，失敗則回復。不支援的工具欄位會變成文字。後續回覆取決於你設定的模型。
閱讀指南
Claude Code 中上下文視窗已滿與用量上限：實作指南
上下文視窗已滿表示這段對話太長：請在 Claude Code 內執行 /compact 或 /clear。帳號上限會標出重設時間，此時 /compact 沒有作用。Watch 既不會放大視窗，也不會恢復配額。它把已儲存的會話複製到另一個仍能執行的 Agent。
閱讀指南
Claude Opus 5.5 對五小時上限改變了什麼，以及仍被限制時該怎麼做
Opus 5.5 提高了 Pro、Max、Team 與按席位計費 Enterprise 的五小時上限，並新增一次可儲存的重設。它並沒有取消上限。Watch 不會讀取或提高 Claude 配額。只有在該官方重設仍然不夠時，才把已儲存的會話交給 Codex。
閱讀指南
為什麼 resume 開啟是空會話：0 回合會話的辨識與恢復
resume 開啟空會話，通常是因為這條會話檔案裡沒有可繼續的對話：可能是 watch new 建立的合法空會話、內容被清空只剩佔位標頭，也可能是 0 位元組檔案。用 watch status 看鏈尾列的回合數即可判斷；Watch 不會替你重建歷史，只能從備份還原、改綁到另一條會話，或另開一條鏈。
閱讀指南
沒有轉接器時，用 watch prompt 交接會話
目標工具沒有轉接器或原生格式剛變化時，用 watch prompt <session-id> 產生唯讀 Markdown 交接文件；它不寫會話檔案、不啟動 CLI，裁剪計數與降級說明寫進正文和 --json 的 findings，目標端只能把它當作摘要而不是原生會話。
閱讀指南
Codex 會話只剩 .jsonl.zst：Watch 的讀取邊界與恢復路徑
Codex 壓縮本機執行緒後，原 rollout 只剩 .jsonl.zst；Watch 不讀壓縮格式，這些會話不會出現在任何列表裡。用 watch doctor 看「讀不出目錄歸屬」的數量，並在 Codex 裡繼續該執行緒以觸發重新展開。副本是 0 位元組時內容已遺失，只能從備份還原；不要刪除或改名 .zst 檔案。

以下命令依 CLI 與桌面端分組，可直接複製。從原始碼執行前，先在儲存庫根目錄執行 npm install；桌面端還需安裝 desktop/ 下的相依套件。安裝程式在使用者機器上仍依賴外部的 Node。
Node ≥ 22.13 · 桌面建置另需 Rust / Tauri
$git clone https://github.com/can4hou6joeng4/Watch.git
$cd Watch && npm install
$npm run watch -- status --json
$npm run watch -- import-codex prepare <claude-id> --cwd /abs/project --desktop-project --experimental --json
$npm --prefix desktop install
$npm run desktop:dev
$cd desktop && npx tauri build
缺少 tsx？請先執行 npm install。node:sqlite 錯誤需要檢查 Node 版本。

QUESTIONS & BOUNDARIES
問題
Claude Code 做到一半達到上限。要怎麼繼續？
在 Watch 輸入來源會話 ID，核對偵測到的工作目錄，再選擇目標 Agent。Claude → Codex 會顯示官方、先有專案的匯入預覽，只有在你確認後才寫入，然後另行開啟目標；其他目標使用既有的 CLI 轉接器。Watch 不會繞過用量上限，也不會搬移程式碼；它轉移的是已儲存的會話紀錄。
如何從 Claude Code 切換到 Codex 並繼續同一個會話？
兩個進入點：在桌面應用程式選取來源會話並點選 OpenAI Codex 卡片（官方單一會話匯入：prepare → confirm → open），或執行 watch import-codex prepare <claude-id> --cwd <project> --desktop-project --experimental，接著再 confirm。專案必須已存在於 Codex Desktop。工具紀錄在 Codex 端可能變成文字，模型續寫不在已驗證範圍內。
我的 Claude Code 上下文視窗滿了。Watch 會壓縮它嗎？
不會。壓縮或清除脈絡是 Claude Code 自己的 /compact 與 /clear。Watch 把已儲存的會話紀錄整份移到另一個 Agent；目標會話從該紀錄開始，原本的會話不會被改動。能不能放得下，取決於目標工具的上下文視窗。
Claude Code、Codex 與 OpenCode 的會話檔在哪裡，又要如何繼續先前的對話？
Claude Code：~/.claude/projects/<encoded-cwd>/<session-id>.jsonl，以 claude --resume <id> 繼續。Codex：~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl，以 codex resume <id> 繼續。OpenCode：~/.local/share/opencode/opencode.db，以 opencode -s <id> 繼續。Watch 依會話 ID 查找這些紀錄，顯示所屬工作目錄，並在交接紀錄下列出該目錄的串接交接。
為什麼 watch status 列出的會話，resume 之後卻是空的？
resume 只負責開啟既有會話；空會話通常代表檔案裡已經沒有可繼續的對話：watch new 建立的合法空會話、內容被清空只剩佔位標頭，或是 0 位元組檔案。用 watch status 看鏈尾那一列的回合數，0 回合時 Watch 會揭露原因。它不會替你重建歷史：可以從備份還原檔案、用 watch adopt 改綁到另一條會話，或 watch chain new 另開一條鏈。
watch doctor 提示鏈尾可能被 Claude Code 清理，可信嗎？
這是依鏈尾檔案的最後修改時間與依設定優先序偵測到的 cleanupPeriodDays 估算出的風險，不是刪除事實：只在明確設定低於官方預設 30 天、且鏈尾是 Claude Code 會話時提示。被更高優先序覆蓋的短值不再拿來示警；高層設定讀不出來時，也不拿低層值猜測。工作樹 / 子模組不偵測主檢出的儲存庫根目錄設定，估算可能偏保守；實際生效值仍取決於 Claude Code 載入的全部設定，--settings 與受管理設定不在偵測範圍。先備份鏈尾檔案、調高保留期，或用 watch switch 重新綁定；--strict 會把警告視為失敗。
我同時使用 Claude Code 與 Codex。如何在兩者之間移動而不失去脈絡？
Watch 不會為兩者排名。兩者都已安裝並完成驗證時，可以交接會話：Claude → Codex 使用官方匯入預覽，Codex → Claude 使用 CLI 轉接器轉換；兩者都會保留工作目錄。部分事件在格式之間可能降級，結果會列出哪些項目被降級。
紀錄會經過 Watch 的雲端伺服器嗎？
Watch 沒有自己的轉送伺服器。部分原生會話建立路徑會呼叫目標 CLI，並可能存取其網路服務。模型續寫也遵循該服務的隱私與模型規則。本機轉換並不代表整個流程完全離線。
轉換是無損或無風險的嗎？
不是。新檔與整檔取代有原子寫入與回解析檢查，部分附加路徑的防護則不同。官方 Codex 匯入使用自己的日誌、目標鎖與讀回驗證。確切邊界請見架構說明。
