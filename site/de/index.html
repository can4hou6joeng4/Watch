UNDER THE HOOD
Kernmechanismen
Der Schutz ist routenspezifisch. Eine enge Prüfung ist keine universelle Sicherheitsgarantie. Die Desktop-App hat vier Ansichten (Sitzungsübergabe, Übergabehistorie, unterstützte Routen, Einstellungen) mit hellem, dunklem und System-Erscheinungsbild.
01
Quelle und cwd finden
Gespeicherte Datensätze über die native Sitzungs-ID finden und das tatsächliche cwd beibehalten. Bestehende Worktrees werden nicht stillschweigend durch die Repository-Wurzel ersetzt.
02
Offizielle Importe bestätigen
Die Codex-Route bindet Zielverzeichnis und Konfiguration, mit Ausführungsprotokoll und dauerhafter Sperre. Unsichere Ergebnisse werden abgefragt, nicht blind erneut übermittelt.
03
Formatgrenzen offenlegen
Aufgezeichnete Nachrichten und Ereignisse in das Zielformat übertragen. Die Erhaltung variiert; ein interner Roundtrip ist kein Nachweis nativer Fortsetzung.
04
Import vom Öffnen trennen
Schlägt das Öffnen nach dem Import fehl, nur das Öffnen erneut versuchen. Ein fehlgeschlagener Terminalstart fällt auf das Kopieren eines Befehls zurück, nachdem er auf Steuerzeichen geprüft wurde, ohne eine weitere Übertragung.

ANSWERS FIRST
Anleitungen
Jede Anleitung beginnt mit einer eigenständigen Antwort, danach folgen die Schritte. Watch umgeht keine Limits und bewertet keine Modelle.
Weiterarbeiten in Codex, nachdem Claude Code das Nutzungslimit erreicht hat
Meldet Claude Code ein Fünf-Stunden- oder Wochenlimit, stellt /compact kein Kontingent wieder her. Watch liest nur die lokale Datei ~/.claude/projects/<encoded-cwd>/<session>.jsonl, prüft das Arbeitsverzeichnis und kopiert diesen Datensatz nach Codex. Die Originaldatei bleibt unverändert. Tool-Ereignisse können zu Text werden.
Anleitung lesen
Anleitung zur bidirektionalen Sitzungsübergabe zwischen OpenCode, Claude und Codex
OpenCode speichert Sitzungen in ~/.local/share/opencode/opencode.db. WATCH_OPENCODE_DB zeigt Watch auf eine andere Datei. Watch schreibt sessions, messages und parts in einer SQLite-Transaktion und rollt bei Fehler zurück. Nicht unterstützte Tool-Felder werden zu Text. Spätere Antworten hängen vom konfigurierten Modell ab.
Anleitung lesen
Volles Kontextfenster oder Nutzungslimits in Claude Code: Praxisanleitung
Ein volles Kontextfenster bedeutet, dass diese Konversation zu lang ist: Führen Sie /compact oder /clear in Claude Code aus. Ein Kontolimit nennt einen Zurücksetzungszeitpunkt, und /compact bewirkt dann nichts. Watch vergrößert weder das Fenster noch stellt es Kontingent wieder her. Es kopiert die gespeicherte Sitzung in einen anderen Agenten, der noch laufen kann.

Was Claude Opus 5.5 an den Fünf-Stunden-Limits ändert und was zu tun ist, wenn Sie trotzdem gedeckelt sind
Opus 5.5 erhöht das Fünf-Stunden-Limit für Pro, Max, Team und sitzbasiertes Enterprise und fügt ein speicherbares Reset hinzu. Es hebt das Limit nicht auf. Watch liest oder erhöht kein Claude-Kontingent. Übergeben Sie die gespeicherte Sitzung erst dann an Codex, wenn dieses offizielle Reset immer noch nicht ausreicht.

Warum die Wiederaufnahme eine leere Sitzung öffnet: 0-Turn-Sitzungen erkennen und wiederherstellen
Eine leere Sitzung nach der Wiederaufnahme bedeutet meist, dass die Datei keine Turns mehr enthält: eine reguläre leere Sitzung aus watch new, eine Sitzung, deren Inhalt bis auf einen Platzhalter-Kopf gelöscht wurde, oder eine 0-Byte-Datei. Prüfen Sie die Turn-Anzahl in der Ketten-Spitzen-Zeile von watch status. Watch baut die Historie nicht selbst neu auf; stellen Sie die Datei aus einer Sicherung wieder her, binden Sie eine andere Sitzung ein, oder starten Sie eine neue Kette.

watch prompt ohne Adapter verwenden
Wenn das Zielwerkzeug keinen Adapter hat oder sein natives Format sich gerade geändert hat, erzeugen Sie mit watch prompt <session-id> eine schreibgeschützte Markdown-Übergabe. Es werden keine Sitzungsdateien geschrieben und keine CLI gestartet; Kürzungszahlen und Einschränkungen stehen im Dokument und in den Findings von --json, und das Ziel muss sie als Zusammenfassung behandeln, nicht als native Sitzung.

Codex-Sitzungen nur noch als .jsonl.zst: Lesegrenzen und Wiederherstellung in Watch
Nachdem Codex einen lokalen Thread komprimiert hat, bleibt der Rollout nur als .jsonl.zst; Watch liest das komprimierte Format nicht, daher erscheint die Sitzung in keiner Liste. Sehen Sie mit watch doctor die Zahl der nicht zuordenbaren Dateien und setzen Sie den Thread in Codex fort, um die erneute Entfaltung auszulösen. Eine 0-Byte-Kopie hat ihren Inhalt verloren; stellen Sie sie aus einer Sicherung wieder her. Löschen oder benennen Sie die .zst-Datei nicht um.

Führen Sie vor dem Start aus dem Quellcode im Repository-Stamm npm install aus; die Desktop-App benötigt zusätzlich ihre Abhängigkeiten unter desktop/. Node ≥ 22.13 · Desktop-Builds benötigen außerdem Rust / Tauri
$git clone https://github.com/can4hou6joeng4/Watch.git
$cd Watch && npm install
$npm run watch -- status --json
$npm run watch -- import-codex prepare <claude-id> --cwd /abs/project --desktop-project --experimental --json
$npm --prefix desktop install
$npm run desktop:dev
$cd desktop && npx tauri build

QUESTIONS & BOUNDARIES
Fragen
Claude Code hat mitten in der Aufgabe sein Limit erreicht. Wie mache ich weiter?
Geben Sie die Quellsitzungs-ID in Watch ein, prüfen Sie das erkannte Arbeitsverzeichnis und wählen Sie einen Zielagenten. Claude → Codex zeigt die offizielle Projekt-zuerst-Importvorschau und schreibt erst nach Ihrer Bestätigung, danach öffnet es das Ziel separat; andere Ziele nutzen die bestehenden CLI-Adapter. Watch umgeht keine Nutzungslimits und verschiebt keinen Code; es überträgt den gespeicherten Sitzungsdatensatz.
Wie wechsle ich von Claude Code zu Codex und setze dieselbe Sitzung fort?
Zwei Einstiegspunkte: Wählen Sie in der Desktop-App die Quellsitzung und klicken Sie auf die OpenAI-Codex-Karte (offizieller Einzelsitzungsimport: prepare → confirm → open), oder führen Sie watch import-codex prepare <claude-id> --cwd <project> --desktop-project --experimental aus, gefolgt von confirm. Das Projekt muss bereits in Codex Desktop existieren. Tool-Datensätze können auf der Codex-Seite zu Text werden, und die Modellfortsetzung liegt außerhalb des validierten Umfangs.
Mein Claude-Code-Kontextfenster ist voll. Verdichtet Watch es?
Nein. Kontext verdichten oder leeren ist Claudes eigenes /compact und /clear. Watch überträgt den gespeicherten Sitzungsdatensatz als Ganzes in einen anderen Agenten; die Zielsitzung startet von diesem Datensatz, die ursprüngliche Sitzung bleibt unberührt. Ob er hineinpasst, hängt vom Kontextfenster des Zielwerkzeugs ab.
Wo liegen die Sitzungsdateien von Claude Code, Codex und OpenCode, und wie setze ich eine frühere Konversation fort?
Claude Code: ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl, fortsetzen mit claude --resume <id>. Codex: ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl, fortsetzen mit codex resume <id>. OpenCode: ~/.local/share/opencode/opencode.db, fortsetzen mit opencode -s <id>. Watch sucht sie über die Sitzungs-ID, zeigt das zugehörige Arbeitsverzeichnis und listet verkettete Übergaben für dieses Verzeichnis unter Übergabehistorie.
Warum öffnet sich eine Sitzung, die watch status auflistet, nach der Wiederaufnahme leer?
resume öffnet nur eine vorhandene Sitzung. Eine leere Sitzung hat meist keine Turns mehr: eine reguläre leere Sitzung aus watch new, eine Sitzung, deren Inhalt bis auf einen Platzhalter-Kopf gelöscht wurde, oder eine 0-Byte-Datei. Prüfen Sie die Turn-Anzahl der Ketten-Spitze in watch status; bei 0 nennt Watch den Grund. Watch baut keine Historie neu auf: Stellen Sie die Datei aus einer Sicherung wieder her, binden Sie mit watch adopt eine andere Sitzung ein, oder starten Sie mit watch chain new eine neue Kette.
Ist die Warnung von watch doctor zum Claude-Code-Aufräumrisiko sicher?
Sie ist eine Schätzung aus der Änderungszeit der Ketten-Spitzen-Datei und dem per Einstellungsrang ermittelten cleanupPeriodDays, kein Nachweis einer Löschung. Sie erscheint nur für Claude-Code-Kettenspitzen, wenn der ausdrückliche Wert unter dem offiziellen Standard von 30 Tagen liegt. Wird ein kurzer Wert durch eine höherrangige Einstellung überschrieben, wird er nicht mehr gemeldet; lässt sich eine höherrangige Datei nicht lesen, wird kein niedrigerer Wert zur Schätzung herangezogen. Worktrees und Submodule lesen die Einstellungen im Repository-Stamm des Haupt-Checkouts nicht, daher kann die Schätzung konservativ ausfallen. Der wirksame Wert hängt weiterhin von allen Einstellungen ab, die Claude Code lädt; --settings und verwaltete Einstellungen liegen außerhalb des Bereichs. Sichern Sie die Ketten-Spitzen-Datei, erhöhen Sie die Aufbewahrung, oder binden Sie mit watch switch neu ein; --strict behandelt Warnungen als Fehler.
Ich nutze sowohl Claude Code als auch Codex. Wie wechsle ich zwischen ihnen, ohne den Kontext zu verlieren?
Watch bewertet die beiden nicht. Sind beide installiert und authentifiziert, übergeben Sie Sitzungen: Claude → Codex nutzt die offizielle Importvorschau, Codex → Claude die Konvertierung des CLI-Adapters; beide behalten das Arbeitsverzeichnis. Manche Ereignisse können zwischen den Formaten degradiert werden, und das Ergebnis listet auf, was degradiert wurde.
Läuft die Historie über einen Watch-Cloud-Server?
Watch hat keinen eigenen Relay-Server. Manche nativen Routen zur Sitzungserstellung rufen die Ziel-CLI auf und können deren Netzwerkdienste nutzen. Die Modellfortsetzung folgt ebenfalls den Datenschutz- und Modellregeln dieses Dienstes. Lokale Konvertierung bedeutet keinen vollständig offline ablaufenden Workflow.
Ist die Konvertierung verlustfrei oder risikofrei?
Nein. Neue Dateien und komplette Dateiersetzungen haben atomare Schreibvorgänge und Rückleseprüfungen, während manche Anhängpfade anderen Schutz haben. Offizielle Codex-Importe nutzen ein eigenes Protokoll, eine Zielsperre und eine Rückleseverifikation. Die genauen Grenzen stehen in der Architektur.

      
OFFICIAL ENTRY / NOT INTEGRATED
Antigravity CLI: Fortsetzen und Import im selben Produkt
Offizielle Einstiegspunkte geprüft; nicht in Watch integriert. Das sind Antigravity-Operationen, keine Watch-Konvertierungsbefehle.
Offiziell dokumentiert / Nicht von Watch validiert
01
Eine bestimmte CLI-Konversation fortsetzen
agy --conversation <conversation-id>
Setzt eine bestehende Antigravity-CLI-Konversations-ID fort. Es ist kein Importer für Claude-, Codex- oder Desktop-Konversationen.
02
Die neueste Workspace-Konversation fortsetzen
agy -c
Sucht die neueste Konversation für das aktuelle Arbeitsverzeichnis. Fehlende oder gelöschte Historie kann eine neue Konversation starten, daher ist das keine nebenwirkungsfreie Statusprüfung.
03
Import aus Antigravity 2.0
/resume
Wechseln Sie im CLI-Sitzungsauswahlfenster zum Antigravity-Tab, wählen Sie eine Desktop-Konversation und bestätigen Sie den Import. Die offizielle Dokumentation beschreibt geklonte Historie, Kontext und Tool-Verläufe. Watch hat das nicht nativ validiert und hat keinen Importvertrag für externe Agenten.
