watch prompt ohne Adapter verwenden

Wenn das Zielwerkzeug keinen Adapter hat oder sein natives Format sich gerade geändert hat, erzeugen Sie mit watch prompt <session-id> eine schreibgeschützte Markdown-Übergabe. Es werden keine Sitzungsdateien geschrieben und keine CLI gestartet; Kürzungszahlen und Einschränkungen stehen im Dokument und in den Findings von --json, und das Ziel muss sie als Zusammenfassung behandeln, nicht als native Sitzung.

watch prompt wandelt lokale native Sitzungsaufzeichnungen in eine Markdown-Zusammenfassung als Übergabe um, ohne eine Datei zu schreiben oder die Ziel-CLI zu starten. Das Ziel erbt keine native Wiederaufnahme; jede Kürzung und jeder Quellzustand wird im Dokument und in findings festgehalten.

Veröffentlicht: 2026-11-18 Aktualisiert: 2026-11-18 Gilt für: Watch v0.1.386
Wann dieser Pfad passt

Die drei nativen Übergabepfade (Launcher, verkettete Übergabe und offizieller Codex-Import) erfordern einen Adapter und ein prüfbares Zielformat. Wenn die Ziel-CLI noch keinen Adapter hat, ihr natives Format sich gerade geändert hat, oder Sie Kontext nur an einen Web-Assistenten geben wollen, erzeugt watch prompt eine schreibgeschützte Zusammenfassung. Sie ist keine native Sitzung, sondern kopier- und prüfbares Übergabematerial.

watch prompt liest nur die lokale Sitzungsaufzeichnung des Quell-Assistenten und rendert Turns, Werkzeugereignisse und ein Arbeitsmanifest als Markdown. Der Kopf nennt Quell-Assistent, Sitzungs-ID, Quelldatei, Arbeitsverzeichnis, Worktree-Typ und aktuellen Branch; der Text sagt, wie viele Turns gekürzt wurden, was ausgelassen wurde und ob die Nutzung eventuell zu niedrig gezählt ist. Der Befehl schreibt keine Sitzungsdateien, öffnet keine Datenbank und startet keine CLI.

  1. Schritt 1: Quellsitzung und Verzeichnis bestimmen

    Geben Sie die Sitzungs-ID ausdrücklich an, oder übergeben Sie --cwd und lassen Sie die ID weg. Ohne ID wählt Watch die neueste lesbare Sitzung im aktuellen Verzeichnis und markiert sie im Kopf als automatisch gewählt; im Zweifel nennen Sie die ID, damit keine andere Sitzung als Quelle missverstanden wird.

  2. Schritt 2: Profil und Fenster wählen

    --profile minimal|standard|verbose|full steuert, wie viel Text und wie viele Werkzeugereignisse entfaltet werden. --last N behält nur die neuesten N Benutzer-Turns und verwirft die ursprüngliche Aufgabenbeschreibung, was das Dokument ausweist. --since-compact beginnt bei der letzten Kompaktierungszusammenfassung; gibt es keine brauchbare Zusammenfassung, wird nicht gekürzt und das gesagt.

  3. Schritt 3: findings und Quellzustand prüfen

    --json liefert markdown, findings und warnings im Ergebnis. degraded bedeutet, dass die Einschränkung offengelegt wurde; skipped bedeutet, dass Inhalt durch Ihre Optionen entfallen ist. Die Zeilen zu Quellzustand, fehlerhaften Zeilen, Nutzung und Branch im Dokument sagen, ob eine Übergabe sicher ist. Ist das Arbeitsverzeichnis der Quelle nicht verfügbar, wird es als sourceCwd: { state } zurückgegeben (missing, not-directory, denied oder unknown, bei unknown mit reason); ein gesundes Verzeichnis erzeugt dieses Feld nicht. Ein normales Repository-Stammverzeichnis liefert sourceBranch ({ branch, repoRoot }; ein detached HEAD liefert { detached: true, repoRoot }), ein verknüpfter Worktree liefert sourceWorktree ({ mainWorktree, branch }). Ändern sich Dateigröße oder Änderungszeit der Quelldatei zwischen den Prüfungen, meldet sourceDrift ({ from, to, growth }) Byte-Zahlen und Wachstumsrichtung. Das belegt jedoch nicht, welche Einträge es ins Dokument geschafft haben. Ausdrücklich fehlgeschlagene Werkzeugaufrufe werden als failedAttempts zurückgegeben (Werkzeug, Pfad oder Befehl und Anzahl, nie Werkzeugausgabe), und im Dokument steht der Abschnitt „Fehler und Unterbrechungen (Failures and interruptions)“. Beim Rendern prüft die Änderungsübersicht außerdem, ob die gelisteten Dateien noch im Sitzungsverzeichnis liegen: eine nachweislich verschwundene Datei wird als nicht mehr auf der Platte markiert, eine nicht prüfbare als ungeprüft, eine vom Sitzungspatch gelöschte oder verschobene Datei entsprechend benannt, und Pfade außerhalb des Sitzungsverzeichnisses werden getrennt gezählt; die Abschnittsüberschrift nennt, wie viele geprüft wurden oder warum die Prüfung nicht lief. --json ergänzt manifestDisk (checked, missing, unverified, outside, removed), damit Skripte ein fehlendes Feld nicht als „alles vorhanden“ lesen. Nicht abgeschlossene Werkzeugaufrufe und ein hängender Nutzertail werden als stats.danglingToolCalls, stats.unansweredTail und passende findings gemeldet; Erstere zählt die gesamte Sitzung, Letztere greift nur, wenn der letzte Nutzer-Turn echten Text enthält. Beides steht in den Metadaten und im Abschnitt Continue working des Dokuments; --json liefert dieselben Felder.

  4. Schritt 4: Als Zusammenfassungsübergabe kennzeichnen

    Fügen Sie das Markdown ein oder speichern Sie es als Datei und sagen Sie dem Ziel-Assistenten im ersten Turn, dass dies eine Zusammenfassungsübergabe ist, keine native Sitzung. Das Ziel kann nicht nativ fortsetzen, und Werkzeugaufrufe, Denkschritte und Anhänge können gekürzt sein; Ausgelassenes lässt sich aus dem Dokument nicht zurückholen.

# 1. Die neueste Sitzung im aktuellen Verzeichnis mit dem standard-Profil automatisch wählen npm run watch -- prompt --cwd /abs/project # 2. Sitzung benennen und nur die neuesten 5 Benutzer-Turns behalten npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. JSON ausgeben, um findings zusammen mit dem Dokument zu prüfen npm run watch -- prompt <session-id> --cwd /abs/project --json
Grenzen

1. Schreibgeschützt: Es schreibt keine Sitzungsdateien, öffnet keine lokale Datenbank und startet keine Ziel-CLI; wie Sie das Markdown übergeben, entscheiden Sie. 2. Eine Zusammenfassung ist keine native Sitzung: Werkzeugaufrufe, Denkschritte und Anhänge können gekürzt sein, und Ausgelassenes lässt sich aus dem Dokument nicht zurückholen. 3. Kürzungen werden gezählt: Auslassungen durch Profil, --last und --since-compact stehen im Text und in findings; ohne Zusammenfassung wird nicht gekürzt und das gesagt. 4. Eine 0-Turn- oder beschädigte Quelle wird nicht als Erfolg gemeldet: Der Text nennt eine leere Quelle oder fehlerhafte Zeilen, und unlesbare Nutzung oder Zeilenzahlen werden als eventuell zu niedrig gezählt oder unbestätigt markiert.

Häufige Fragen

Schreibt watch prompt in die Sitzung des Zielwerkzeugs?

Nein. Es liest nur die Quellaufzeichnung und gibt Markdown aus; es schreibt keine Ziel-Sitzungsdatei, öffnet keine Datenbank und startet keine CLI. Wenn Sie im Ziel eine native Wiederaufnahme brauchen, nutzen Sie für diesen Adapter den Launcher- oder Kettenpfad; der einzige offizielle Importpfad ist Claude Code zu Codex Desktop.

Warum sagt das Dokument, die ursprüngliche Aufgabenbeschreibung sei nicht erhalten?

Mit --last N beginnt Watch beim N-ten Benutzer-Turn von hinten, daher entfallen frühere Turns einschließlich der ursprünglichen Aufgabenbeschreibung. Lassen Sie --last weg für den vollen Hintergrund, oder nutzen Sie --since-compact mit einem größeren Profil; der Text listet jede tatsächlich erfolgte Kürzung.

Kann der Ziel-Assistent genau wie eine native Sitzung fortsetzen?

Nein. Er erhält ein Zusammenfassungsdokument ohne native Wiederaufnahme und sieht gekürzte Werkzeugausführungsdetails nicht. Bitten Sie ihn im ersten Turn, Aufgabenziel und aktuellen Branch zu wiederholen, und übertragen Sie erst dann Änderungen.
