Weiterarbeiten in Codex, nachdem Claude Code das Nutzungslimit erreicht hat

Meldet Claude Code ein Fünf-Stunden- oder Wochenlimit, stellt /compact kein Kontingent wieder her. Watch liest nur die lokale Datei ~/.claude/projects/<encoded-cwd>/<session>.jsonl, prüft das Arbeitsverzeichnis und kopiert diesen Datensatz nach Codex. Die Originaldatei bleibt unverändert. Tool-Ereignisse können zu Text werden.

Wenn Claude Code ein Nutzungslimit (5-Stunden-Fenster oder Wochenkontingent) erreicht oder die Fehlersuche stockt, erklärt diese Anleitung, wie Sie Arbeitsverzeichnis und Sitzungshistorie behalten, einen offiziellen Importplan vorbereiten und über Watch in OpenAI Codex fortsetzen.

Veröffentlicht: 2026-09-17 Aktualisiert: 2026-10-14 Gilt für: Watch v0.1.492
Zentrale Betriebsgrenze

Ein Nutzungslimit beschränkt, wie viel Claude in einem gegebenen Zeitfenster genutzt werden kann, während Kontextfenstergrenzen die Kapazität einer einzelnen Konversation begrenzen. Ist das Kontextfenster nur voll, verwenden Sie /compact oder /clear in Claude Code. Haben Sie ein Kontonutzungslimit erreicht und müssen den Agenten wechseln, überträgt Watch Ihre gespeicherte lokale Sitzungshistorie nach Codex. Watch umgeht keine Limits und ändert keine lokalen Repository-Dateien.

Bei längeren Entwicklungsaufgaben kann Claude Code melden, dass Sie Ihr Planlimit erreicht haben, zusammen mit einem Zurücksetzungszeitpunkt. Die bisher angesammelten Begründungen, fehlgeschlagenen Iterationen und Befehlsausgaben bleiben auf Ihrer Festplatte. Watch überbrückt diese gespeicherte Sitzung nach OpenAI Codex, sodass das neue Werkzeug den vorangehenden Kontext prüfen kann, ohne dass Sie die Untersuchung manuell zusammenfassen müssen.

  1. Schritt 1: Quellsitzungs-ID und Arbeitsverzeichnis prüfen

    Ermitteln Sie die aktive Claude-Code-Sitzungs-ID. Die Historie liegt unter ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl. Stellen Sie sicher, dass der Verzeichnispfad (cwd) zum tatsächlichen Projekt-Workspace passt, um Fehlzuordnungen von Worktree und Repository zu vermeiden.

  2. Schritt 2: Sicherstellen, dass das Zielprojekt in Codex Desktop existiert

    Diese Anleitung nutzt die Route --desktop-project von Watch; sie erfordert, dass das Projekt in Codex Desktop registriert und mit app-server synchronisiert ist. Öffnen Sie das Zielverzeichnis in Codex Desktop, bevor Sie den Plan vorbereiten. Dies ist ein Schutz für diesen Desktop-Übergabepfad.

  3. Schritt 3: Importplan vorbereiten (Prepare)

    Wählen Sie die Quell-Sitzung und klicken Sie in Watch Desktop auf OpenAI Codex, oder führen Sie prepare aus. Watch prüft Quelle, Arbeitsverzeichnis, Ziel und Codex-Version und speichert einen lokalen Importplan. Der Sitzungsimport wird nicht übermittelt, und die beim Bestätigen verwendete Watch-Zielsperre wird nicht erworben. Die native Versionsprüfung kann eigene Laufzeitdateien pflegen; der Vorgang ist daher nicht vollständig schreibfrei.

  4. Schritt 4: Import bestätigen und Degradierungspunkte prüfen (Confirm)

    Prüfen Sie die angezeigte Nachrichtenanzahl, das Arbeitsverzeichnis und die Tool-Aufrufspuren. Bestätigen Sie ausdrücklich, um die Übertragung über das lokale Codex-app-server-Importprotokoll zu starten. Beachten Sie, dass Tool-Aufrufereignisse zu Textdarstellungen degradiert werden können.

  5. Schritt 5: Zielclient unabhängig starten (Open)

    Öffnen Sie nach der Bestätigung Codex Desktop über die App-Oberfläche oder den Fortsetzungsbefehl. Import und Öffnen sind strikt getrennt: Schlägt der Start fehl, nur das Öffnen erneut versuchen, ohne die Importphase zu wiederholen.

# 1. Umgebung prüfen und lokalen Plan speichern (kein Sitzungsimport übermittelt) npm run watch -- import-codex prepare <claude-id> --cwd /abs/project/path --desktop-project --experimental --json # 2. Bestätigen und Import ausführen (planId aus der prepare-Ausgabe verwenden) npm run watch -- import-codex confirm <plan-id> --experimental --json # 3. Lokales Ausführungsjournal lesen (startet keinen nativen Client) npm run watch -- import-codex status <plan-id> --json
Wörtliche Fehlersignaturen für Raten- und Kontingentlimits

Wenn Ihr Terminal diese Meldungen anzeigt, haben Sie ein Kontingentlimit auf Kontoebene erreicht, nicht das Kontextlimit der Unterhaltung: • "You have reached your 5-hour limit for Claude 3.7 Sonnet / Opus. Limit will reset at 14:30." • "Weekly usage limit reached. Your quota resets on Monday at 00:00 UTC." • "Rate limit exceeded for organization. Please wait before retrying." In diesen Fällen kann /compact in Claude Code das Modellkontingent weder wiederherstellen noch freigeben.

Claude Code legt Sitzungen unter ~/.claude/projects/<encoded-cwd>/<session>.jsonl ab. Beim Watch-Import werden proprietäre tool_use- und tool_result-Ereignisse in strukturierte Klartext-Markdown-Einträge innerhalb der Codex-Rollout-Sitzungen umgewandelt. So erhält der Ziel-Agent die vollständige Untersuchungshistorie, ohne gefälschte native Blöcke zu erzeugen, die die Integrität der Codex-Wiederaufnahme brechen.

Sicherheitsgrenzen und Hinweise

1. Keine Verlustfrei-Garantie: Tool-Aufrufstrukturen degradieren in Codex zu Klartext, und die Modellfortsetzung liegt außerhalb des begrenzten Validierungsumfangs. 2. Bei unsicherem Zustand anhalten: Wird der Vorgang unterbrochen oder läuft er in eine Zeitüberschreitung, bleibt die Sperre bestehen. Prüfen Sie mit dem Befehl status, statt Sperren zwangsweise zu löschen oder erneut zu übermitteln. 3. Lokale Konvertierung ist nicht vollständig offline: Watch arbeitet ohne externe Server, Codex startet jedoch seinen eigenen app-server-Daemon und authentifiziert sich bei seinem vorgelagerten Modellanbieter.

Häufige Fragen

Umgeht oder setzt Watch die Claude-Code-Ratenlimits zurück?

Nein. Watch ist ein lokales Übergabewerkzeug. Es manipuliert keine Anthropic-Konten und fügt keine Kontingente hinzu; es überträgt lokal gespeicherte Sitzungsartefakte in einen anderen Agenten mit verfügbarer Kapazität.

Kann ich Codex sofort auffordern, weiter zu programmieren?

Codex prüft die importierte Konversationshistorie, aber die Modellleistung bei fortgesetzten Aufgaben hängt von der Kontextkapazität des Zielagenten ab. Wir empfehlen, Codex zuerst das aktuelle Ziel zusammenfassen zu lassen, bevor Sie neue Codeänderungen vergeben.

Was passiert, wenn ich einen Import zweimal absende?

Watch erzwingt dauerhafte Sperren und Plan-Idempotenz. Doppelte prepare-Anfragen für dieselbe Quelle und dasselbe Verzeichnis geben den bestehenden Plan zurück, ohne Datensätze zu duplizieren.
