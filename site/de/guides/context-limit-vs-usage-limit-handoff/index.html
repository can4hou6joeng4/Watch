Volles Kontextfenster oder Nutzungslimits in Claude Code: Praxisanleitung

Ein volles Kontextfenster bedeutet, dass diese Konversation zu lang ist: Führen Sie /compact oder /clear in Claude Code aus. Ein Kontolimit nennt einen Zurücksetzungszeitpunkt, und /compact bewirkt dann nichts. Watch vergrößert weder das Fenster noch stellt es Kontingent wieder her. Es kopiert die gespeicherte Sitzung in einen anderen Agenten, der noch laufen kann.

Wenn komplexe Aufgaben in Claude Code unterbrochen werden, lernen Sie, Kontextfenstererschöpfung von Kontonutzungskontingenten zu unterscheiden und entweder /compact oder die Watch-Sitzungsübergabe an mehrere Agenten einzusetzen.

Veröffentlicht: 2026-09-21 Aktualisiert: 2026-10-14 Gilt für: Watch v0.1.382
Zentrale Betriebsgrenze: zwei verschiedene physische Limits

1. Kontextfensterlimit: Begrenzt die Gesamtzahl der Tokens, die das Modell gleichzeitig in einer einzelnen Sitzung verarbeiten kann. Ist es voll, fordert das Modell zur Verdichtung auf oder komprimiert die Historie automatisch. 2. Kontonutzungslimit: Begrenzt das Anfragevolumen oder den Tokenverbrauch über ein rollierendes Zeitfenster (z. B. 5-Stunden-Zurücksetzungen oder Wochenkontingente). Ist es erreicht, zeigt Claude „You have exceeded your current usage limit“ mit einem Zurücksetzungszeitpunkt.

Entwickler verwechseln oft ein volles Kontextfenster mit einem Kontoratenlimit oder nehmen an, Sitzungsübergabewerkzeuge würden Claudes Kontextfenster künstlich erweitern. Watch umgeht keine Nutzungskontingente und ersetzt nicht Claudes native Verdichtung. Den Unterschied zu verstehen sorgt dafür, dass Sie den richtigen Wiederherstellungsweg wählen.

  1. Schritt 1: Terminalfehlersignale prüfen, um den Limittyp zu erkennen

    Meldet Claude „exceeded your limit“ mit einem Zurücksetzungszeitpunkt, ist es ein Kontonutzungslimit: /compact schlägt fehl, weil das Modellkontingent erschöpft ist; warten Sie auf die Zurücksetzung oder übergeben Sie an Codex / OpenCode. Meldet Claude Grenzen der Konversationslänge oder hohe Latenz, ist es ein Kontextfensterlimit: Führen Sie /compact aus.

  2. Schritt 2: Native Lösung für die Kontextlänge anwenden (/compact und /clear)

    Führen Sie in Claude Code /compact aus, um die Konversationshistorie zu einer verdichteten Zusammenfassung zu komprimieren. Werden historische Untersuchungsturns nicht mehr benötigt, führen Sie /clear aus, um im aktuellen Workspace neu zu beginnen.

  3. Schritt 3: Sitzungszustand sichern, wenn Kontonutzungskontingente erreicht sind

    Prüfen Sie, dass Claude Code das Sitzungstranskript nach ~/.claude/projects/<enc-cwd>/<session-id>.jsonl geschrieben hat. Nutzen Sie Watch, um das Arbeitsverzeichnis und die Zielbereitschaft für Codex oder OpenCode zu prüfen.

  4. Schritt 4: An einen anderen Agenten übergeben, ohne den Kontext zu wiederholen

    Nutzen Sie Watch, um die aufgezeichneten Begründungen und Testergebnisse in das Format des Zielagenten zu konvertieren, und setzen Sie dann in der neuen CLI mit dem vorangehenden Kontext fort.

# Szenario A: Native Lösung für Kontextfensterlimits (in Claude Code) /compact # Historie automatisch komprimieren, um Kontextkapazität freizugeben /clear # Konversation leeren und den Kontext des Arbeitsverzeichnisses behalten # Szenario B: Übergabe an mehrere Agenten bei Kontonutzungslimit (in der Shell) npm run watch -- open <claude-session-id> --to codex --json npm run watch -- open <claude-session-id> --to opencode --json
Sicherheitsgrenzen und Hinweise

1. Watch erweitert keinen Einzelagenten-Kontext: Die Fortsetzung in einem neuen Agenten unterliegt den eigenen Kontextfensterlimits dieses Agenten. 2. Änderung der Tooldarstellung: Claude-tool_use-Ereignisse degradieren in Codex zu strukturierten Textdarstellungen, um Schema-Parsingfehler zu vermeiden. 3. Prozesse nicht abrupt beenden: Stellen Sie sicher, dass Sitzungsdateien geschrieben sind, bevor Sie Terminalfenster schließen.

Häufige Fragen

Verwirft /compact Codeänderungen auf der Festplatte?

Nein. Dateiänderungen existieren bereits auf Ihrem lokalen Dateisystem. /compact komprimiert nur die Konversationshistorie im Speicher. Detaillierte untergeordnete Fehlermeldungen können jedoch zusammengefasst werden.

Warum schlägt /compact fehl, wenn ein Kontonutzungslimit erreicht ist?

/compact ordnet den Gesprächsverlauf; es stellt das Kontokontingent nicht wieder her, und auch ein Antrag auf eine Zusammenfassung kann am Limit scheitern. Sie können auf die Zurücksetzung warten, ein anderes verfügbares Werkzeug wählen und einem validierten Übergabepfad folgen, oder mit watch prompt ein kürzeres Dokument für die manuelle Übergabe exportieren. Watch stellt Kontingente weder wieder her noch umgeht es sie.

Setzt die Übergabe an Codex oder OpenCode den Kontext zurück?

Die Übergabe transportiert gespeicherte Historie, die in die Zielsitzung umgewandelt wird und dort weiterhin Kontext verbraucht. Watch vergrößert das Fenster nicht und fasst nicht automatisch auf ein Ziel-Tokenbudget zusammen; dass die Sättigung behoben ist, kann es daher nicht garantieren. Um die Eingabe zu verkürzen, nutzen Sie die native Kompaktierung des Zielwerkzeugs oder exportieren Sie mit watch prompt-Presets und --last ein kürzeres Übergabedokument und prüfen Sie dessen Auslassungshinweise.
