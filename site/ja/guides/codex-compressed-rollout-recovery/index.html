Codex のセッションが .jsonl.zst だけになったとき：Watch の読み取り境界と復元経路

Codex がローカルのスレッドを圧縮すると、元の rollout は .jsonl.zst だけになります。Watch は圧縮形式を読まないため、これらのセッションはどの一覧にも現れません。watch doctor で「ディレクトリの帰属を判別できない」件数を確認し、Codex でそのスレッドを続けて再展開を促します。コピーが 0 バイトなら内容は失われており、バックアップから復元するしかありません。.zst ファイルは削除も改名もしないでください。

Watch は ~/.codex/sessions 配下の未圧縮の rollout .jsonl を読み取ります。Codex がローカルのスレッドを圧縮すると元の .jsonl はなくなり、同名の .jsonl.zst だけが残ります。こうしたセッションは一覧、解析、引き継ぎのいずれもできません。watch doctor と一覧コマンドは、存在しないかのように扱わず、件数を開示します。コピーが実際に Codex による圧縮で、内容が無事であれば、Codex でそのセッションを続けて .jsonl が再び現れるか確認してください。

公開日: 2026-11-23 更新日: 2026-11-23 対象バージョン: Watch v0.1.314
主な違い

Watch が読むのは ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl のような未圧縮ファイルです。Codex がローカルのスレッドを圧縮すると、元のファイルはなくなり、同じディレクトリに同名の .jsonl.zst（例：rollout-....jsonl.zst）だけが残ります。Watch は解凍も書き換えもせず、「読めない」を「セッションがない」と言い換えることもありません。一覧、status、doctor、search はこの区分の件数を開示し、どのディレクトリにも帰属できないことを説明します。

Codex のセッションの帰属は rollout の先頭行 session_meta の cwd フィールドに書かれており、圧縮されたコピーでは先頭行を読めないため、Watch はどの作業ディレクトリのセッションかを判断できません。これが watch doctor の「ディレクトリの帰属を判別できない」と、watch sessions の unattributable フィールドです。エラーではなく、「ファイルは存在するが、このバージョンでは中身が見えない」という意味です。同じマシンで圧縮された履歴が大量にたまると件数が大きくなりますが、異常ではありません。

コピーには 2 つの状態があり、次の手順は正反対です。空でないコピーの場合、Codex によるローカルスレッドの圧縮でコピーが無事なら、Codex でそのセッションを続けることで .jsonl に再展開され、その後 Watch が読み取れるようになります。0 バイトのコピーは内容がすでに失われており、再展開しても対話は戻らないため、バックアップから復元するか新しいセッションとして扱います。Watch はコピーが存在するか、0 バイトかを stat するだけで、開いたり解凍したりはしません。そのため開示では「Codex のローカルスレッド圧縮でコピーが無事であれば」と条件を付けています。

  1. ステップ 1：件数とファイルの形を確認する

    watch doctor --json を実行します。storage の codex の行の count は読み取り可能なセッションだけを数え、unattributable は圧縮コピーなど帰属を判別できないファイルの数を示します。テキストモードではセッション数の横に「ほかに M 個のファイルはディレクトリの帰属を判別できません」と表示します。watch sessions --json と watch recent --json も同じフィールドを持ちます。警告にはファイルの形（「.jsonl.zst の圧縮コピーのみ」または「0 バイトの同名圧縮コピー」）が書かれ、次の手順はそれぞれ異なります。

  2. ステップ 2：空でないコピーと 0 バイトのコピーを区別する

    対応する .jsonl.zst を探します。空でないことはバイトが残っているというだけで、コピーが無事であることや解凍できることは意味しません。0 バイトは復元できる内容がないという意味で、別にバックアップを探す必要があります。そのセッションが使えないチェーン末尾の場合、watch doctor --json の store.brokenTips[].compressedPath がコピーのパスを示し、compressedEmpty が true なら 0 バイトです。一覧の unattributable はファイル数だけを示します。

  3. ステップ 3：Codex でそのセッションを続ける

    Codex でそのスレッドを開くか続けます。コピーが Codex のローカルスレッド圧縮で無事なら、Codex が .jsonl に再展開します。その後ターミナルで watch sessions を実行すると、そのセッションが再び現れ、status / switch / open でも読めます。Watch が再展開を促すことも .zst を書き換えることもありません。

  4. ステップ 4：再展開後に引き継ぐ

    再展開されたセッション id を入手したら、通常の経路で引き継ぎます。watch open <id> --to <provider> または watch switch <provider> です。watch prompt も圧縮ファイルは読みません。そのセッションを明示するとエラーになり、引き継ぎドキュメントは生成されません。

# 1. 読み取り専用：件数と原因 npm run watch -- doctor --json npm run watch -- sessions --json # 2. 具体的なファイルを探す（元の .jsonl はなく、同名の .zst だけが残る） ls ~/.codex/sessions/*/*/*/*.jsonl.zst # 3. Codex でそのセッションを続け、再展開させる。その後 Watch が一覧できる npm run watch -- sessions --json # 4. 再展開後に引き継ぐ npm run watch -- open <session-id> --to <provider>
境界とやってはいけないこと

1. Watch は .jsonl.zst を解凍も書き換えも削除もしません。内容が解けるかどうかの判断もしません。行うのはコピーの有無と 0 バイトかどうかの stat だけです。 2. .zst はユーザー自身がアーカイブしたものである可能性もあります。Watch は圧縮が必ず Codex によるものとは仮定しません。「Codex で続けると再展開される」は、実際に Codex のローカルスレッド圧縮でコピーが無事な場合にだけ成り立ちます。 3. 手動で解凍して sessions ディレクトリに戻さないでください。Watch はそのような手書きファイルの形を検証せず、Codex が受け入れるという検証記録もありません。 4. .zst を削除したり改名したりしないでください。それはユーザーのネイティブなセッションデータであり、削除すると復元の経路がなくなります。 5. このガイドはローカルファイルと Watch の開示動作に基づきます。再展開されたセッションをネイティブクライアントが受け入れるかは、バージョンとプラットフォームごとに個別に検証され、このガイドはネイティブ検証ではありません。

よくある質問

Watch は Codex のセッションを圧縮したり削除したりしますか？

いいえ。圧縮は Codex 自身の動作です。Watch は .zst を読まず、書き換えず、削除しません。一覧と解析では未圧縮の .jsonl を読みます。Codex を対象にした書き込みを伴う引き継ぎは別の話で、対象側の未圧縮セッションファイルを新規作成または更新することがあります。

なぜ doctor は「ファイルが圧縮されている」ではなく「ディレクトリの帰属を判別できない」と言うのですか？

Watch は圧縮ファイルを stat するだけで開かないからです。元の .jsonl がなく同名の .zst があることは確認でき、その区分を「圧縮コピー」として警告に書きますが、コピーの内容が解けるかは確認できず、Codex の帰属が書かれた session_meta の先頭行も読めません。「Codex のローカルスレッド圧縮でコピーが無事であれば」という条件を残しているのは、検証していない事実を保証しないためです。

.zst を自分で .jsonl に解凍できますか？

おすすめしません。そこはネイティブの保存ディレクトリであり、手書きファイルの形を Watch は検証せず、Codex が受け入れるという検証記録もありません。最も確実なのは Codex でそのセッションを続け、ネイティブに展開させることです。

0 バイトのコピーと無事なコピーはどう違いますか？

0 バイトのコピーは内容が失われており、再展開しても対話は戻らないため、バックアップから復元するか新しいセッションとして扱います。無事なコピーは、Codex でそのセッションを続けると .jsonl に再展開され、その後 Watch で読めるようになります。

これらの圧縮されたセッションを別のエージェントに引き継げますか？

直接は引き継げません。まず Codex で再展開し、通常の経路で watch open <id> --to <provider> または watch switch を使ってください。引き継ぎの前に、作業ディレクトリとセッション id を確認し、結果の warnings を読むことをおすすめします。
