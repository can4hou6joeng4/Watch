OpenCode、Claude、Codex の双方向セッション引き継ぎガイド

OpenCode はセッションを ~/.local/share/opencode/opencode.db に置きます。WATCH_OPENCODE_DB は Watch を別のファイルへ向けます。Watch は sessions、messages、parts を一つの SQLite トランザクションで書き、失敗すればロールバックします。未対応のツールフィールドはテキストになります。その後の応答は設定したモデルに依存します。

商用クラウドエージェントから OpenCode のローカルなオープンソースモデルへ切り替えるとき（またはクラウドエージェントへ戻すとき）、このガイドは SQLite のトランザクションによるデータ分離で Watch を使い、双方向に引き継ぐ方法を説明します。

公開日: 2026-09-21 更新日: 2026-10-14 対象バージョン: Watch v0.1.478
操作上の重要な境界

OpenCode はセッション保存に単一のリレーショナル SQLite データベース（既定は ~/.local/share/opencode/opencode.db）を使い、ACID トランザクションの整合性と構造化されたクエリを提供します。機密性の高い作業をローカルで動かすオープンソースモデル（OpenCode の Ollama または vLLM）へ移す、あるいはフロンティアのクラウドモデル（Claude/Codex）へ戻すとき、Watch は検証済みの双方向の橋を提供します。

追記専用の JSONL ファイルだけに頼るツールと異なり、OpenCode は sessions、messages、parts を含む正規化されたリレーショナルテーブルにセッションを構成します。外部から直接変更すると外部キー制約が壊れることがあります。Watch は UnifiedTurn 抽象を OpenCode のリレーショナルスキーマへきれいに対応付け、正確なディレクトリコンテキスト（cwd）とタイムスタンプを保ちます。

  1. 手順 1: 元のセッション ID と作業ディレクトリを特定

    アクティブなセッション ID を探します。Claude Code は ~/.claude/projects/ に、Codex は ~/.codex/sessions/ にファイルを置き、OpenCode はグローバルに一意な ID でセッションを索引します。プロジェクト境界を揃えるため、作業ディレクトリが絶対パスであることを確認してください。

  2. 手順 2: 対象データベースの status を事前確認する（Check）

    --check で出力先と書き込み予定のターンをプレビューし、返される writable、blocked、warnings を確認します。書き込み予定のターンがある場合、OpenCode のプリフライトはストレージのレイアウトと既存ターゲットの revert 状態を調べます。2.x のレイアウトは読み取り専用です。ターゲットセッションへの書き込みは行わず、書き込み権限の試験や SQLite の書き込みロックの取得もしないため、後続の書き込みに並行変更がないことは保証できません。

  3. 手順 3: 双方向の引き継ぎを実行する（Handoff）

    Watch Desktop で元セッションを選び OpenCode を対象にするか、CLI の open コマンドを実行します。Watch は増分のターンを取り出し、sessions、messages、parts にまたがる原子的な SQLite トランザクションを実行し、宛先のセッション ID を発行します。

  4. 手順 4: OpenCode でネイティブにセッションを再開する（Resume）

    変換後、ワークスペースのディレクトリで opencode -s <session-id> を実行するか、Watch Desktop の起動ボタンを押します。OpenCode はその作業ディレクトリで記録された会話を読み込みます。

# 1. 出力先と書き込み予定のターンをプレビューし、レイアウトと revert ガードを確認 npm run watch -- open <claude-session-id> --to opencode --check --json # 2. 書き込み：指定セッションを OpenCode のローカル SQLite データベースに取り込み、再開コマンドを出力 npm run watch -- open <claude-session-id> --to opencode --json # 3. 逆方向の引き継ぎ：OpenCode のセッションから Claude Code または Codex へ npm run watch -- open <opencode-session-id> --to claude --json
OpenCode の SQLite テーブル構造とデータ分離の検証

OpenCode のセッションデータベース（~/.local/share/opencode/opencode.db）は、3 つの主要テーブルで構成されています： • session: セッション ID、タイトル、プロジェクトの絶対パス（directory）、更新時刻を保存 • message: 所属する session_id、ロール（user / assistant）、タイムスタンプを記録 • part: メッセージ本文、コードブロック、構造化データを保存 （2.x レイアウトでは session_v2 / session_message / session_part に対応） 環境変数 WATCH_OPENCODE_DB=/tmp/isolated.db でテスト用データベースを分離でき、書き込みが独立した SQLite トランザクション内で完了し、異常時にはアトミックにロールバックすることを確認できます。

安全上の制約と免責

1. データベースの分離とバックアップ: Watch は既定で ~/.local/share/opencode/opencode.db を操作し、テスト環境では WATCH_OPENCODE_DB を使います。書き込みは一つの SQLite トランザクションで、失敗するとロールバックします。 2. ツール呼び出しの表現: ツール記録はスキーマ間で対応付けられ、未対応の独自パラメータは構造化テキストになります。 3. モデルによる続行: Watch は保存済みのセッション記録と作業ディレクトリを書き込みます。すべてのツールイベントが保持される保証はありません。その後の応答は、設定したモデルに依存します。

よくある質問

JSONL に対する OpenCode の SQLite ストレージの利点は何ですか。

SQLite のトランザクションは、1 回のセッション書き込みをまとめて反映し、失敗時にはロールバックします。行単位の書き込みロックは提供しないため、複数の書き込み者がデータベースを競合することがあります。WATCH_OPENCODE_DB は Watch の読み書きを独立したテスト用データベースに向けますが、OpenCode ネイティブクライアントが使うデータベースは自動では変わりません。

OpenCode から渡すとき、カスタムモデルの推論の思考は保持されますか。

Watch は、対応できる範囲のユーザー指示、アシスタント本文、思考の痕跡、ツール出力をコピーします。未対応のツール項目はテキストになるため、OpenCode の元の行の完全な複製ではありません。

Watch は作業ディレクトリの不一致をどう防ぎますか。

Watch は選択した絶対 cwd をセッション記録に書き込み、完全な再開コマンドでは先にディレクトリを移動してから opencode -s <session-id> を実行します。返された作業ディレクトリを確認し、完全なコマンドを使ってください。opencode -s だけでは Watch のディレクトリ移動は含まれません。cwd の記録はファイルアクセスのサンドボックスではないため、出力先ツールでもパスと権限を確認してください。
