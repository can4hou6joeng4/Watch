アダプターがないときは watch prompt でセッションを引き継ぐ

対象ツールにアダプターがない、またはネイティブ形式が変わったばかりのときは、watch prompt <session-id> で読み取り専用の Markdown 引き継ぎドキュメントを生成します。セッションファイルを書かず、CLI も起動しません。トリミングの件数と縮退の説明は本文と --json の findings に入り、対象側はこれをネイティブセッションではなく要約として扱う必要があります。

watch prompt はローカルのネイティブなセッション記録から Markdown の要約引き継ぎドキュメントを生成し、ファイルを書き換えず、対象 CLI も起動しません。対象ツールはネイティブの再開機能を引き継がず、トリミングとソースの状態は本文と findings に書き出されます。

公開日: 2026-11-18 更新日: 2026-11-18 対象バージョン: Watch v0.1.481
この経路を使う場面

3 つのネイティブ引き継ぎ経路（ランチャー、チェーン引き継ぎ、Codex 公式インポート）は、いずれも対象側に対応するアダプターと検証可能な形式を必要とします。対象 CLI にまだアダプターがない、ネイティブ形式が変わったばかり、または Web のアシスタントにコンテキストだけを渡したい場合は、watch prompt で読み取り専用の要約を生成してください。ネイティブセッションではなく、コピーして確認できる引き継ぎ資料です。

watch prompt はソースのアシスタントがローカルに保存したセッション記録だけを読み、ターン、ツールの過程、変更の概要を Markdown にまとめます。冒頭にはソースのアシスタント、セッション ID、ソースファイル、作業ディレクトリ、ワークツリーの種類、現在のブランチを明記します。本文には、何ターンをトリミングしたか、何を省略したか、usage が少なめに出る可能性を項目ごとに説明します。コマンドはセッションファイルを書かず、データベースも作らず、CLI も起動しません。

  1. ステップ 1：ソースのセッションとディレクトリを特定する

    セッション ID を明示するか、--cwd で作業ディレクトリを指定して ID を省略します。ID を省略すると、Watch はカレントディレクトリで最も新しい読み取り可能なセッションを自動で選び、冒頭に「自動選択」と表示します。迷う場合は明示してください。別のセッションをソースと取り違えるのを避けられます。

  2. ステップ 2：プリセットと範囲を選ぶ

    --profile minimal|standard|verbose|full は、本文と過程記録をどこまで展開するかを制御します。--last N は直近 N 個のユーザーターンだけを残し、最初のタスク説明は省略されますが、その旨を本文に明記します。--since-compact は直近の圧縮要約から始め、使える要約がない場合はトリミングせず、そのことを説明します。

  3. ステップ 3：findings とソースの状態を確認する

    --json を付けると、markdown に加えて findings と warnings を返します。degraded は縮退したが説明済み、skipped は指定したオプションで内容を省略したことを表します。本文のソース状態、不正行、usage、ブランチの行は、このドキュメントをそのまま渡してよいかの判断材料になります。作業ディレクトリが使えない場合は sourceCwd: { state }（missing / not-directory / denied / unknown。unknown には reason が付く）を返し、正常なディレクトリでは出力しません。通常のリポジトリルートでは構造化された sourceBranch（{ branch, repoRoot }、detached HEAD は { detached: true, repoRoot }）を返し、リンクされたワークツリーでは sourceWorktree（{ mainWorktree, branch }）を返します。読み取りの前後でソースファイルのサイズや更新時刻が変わった場合は、sourceDrift（{ from, to, growth }）がバイト数と増加の方向を報告しますが、本文にどの記録が入ったかは確認できません。失敗と明示されたツール呼び出しは failedAttempts（ツール、パスまたはコマンド、回数。ツール出力は複製しない）として返り、本文には「失敗と中断」の節が残ります。ドキュメント生成時には「変更の概要」が、一覧のファイルがセッションディレクトリにまだあるかも確認します。確実にないものは「ディスク上に存在しない」、確認できないものは「確認できなかった」、このセッションのパッチで削除・移動されたものは「削除 / 移動済み」と表示し、セッションディレクトリ外のパスは別に数えます。冒頭には、今回いくつ確認したか、または確認しなかった理由も記載します。--json には manifestDisk（checked / missing / unverified / outside / removed）もあり、フィールドがないことは「すべて存在する」を意味しません。 未完了のツール呼び出しと末尾のユーザーメッセージは stats.danglingToolCalls、stats.unansweredTail と対応する finding で報告されます。前者はセッション全体を数え、後者は末尾のユーザーターンに実際の本文がある場合だけ適用されます。どちらも文書のメタデータと「作業の続行」に記載され、--json にも同じフィールドが入ります。

  4. ステップ 4：要約の引き継ぎであることを伝える

    Markdown を貼り付けるかファイルに保存して対象ツールに渡し、最初のターンで、これがネイティブセッションではなく要約の引き継ぎであることを伝えてください。対象側はネイティブに再開できず、ツール呼び出し、思考過程、添付はトリミングされている可能性があり、含まれなかった部分はドキュメントから復元できません。

# 1. カレントディレクトリの最新セッションを自動選択し、standard プリセットの要約を生成 npm run watch -- prompt --cwd /abs/project # 2. セッションを明示し、直近 5 個のユーザーターンだけを残す npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. JSON を出力し、findings と本文を確認 npm run watch -- prompt <session-id> --cwd /abs/project --json
境界と安全上の制限

1. 読み取り専用：セッションファイルを書かず、ローカルデータベースも作らず、対象 CLI も起動しません。生成された Markdown をどう届けるかはユーザーが決めます。 2. 要約はネイティブセッションではありません。ツール呼び出し、思考過程、添付はトリミングされることがあり、含まれない部分はドキュメントから復元できません。 3. トリミングは必ず数えます。プリセット、--last、--since-compact による省略は本文と findings に書かれ、要約がないときはトリミングせずにその旨を説明します。 4. 0 ターンや破損したソースを成功として扱いません。本文にソースが空であることや不正行を明記し、確認できない usage や不正行数には、少なめの可能性や未確認であることを示します。

よくある質問

watch prompt は対象ツールのセッションに書き込みますか？

いいえ。ソースの記録を読んで Markdown を出力するだけで、対象のセッションファイルも書かず、データベースも作らず、CLI も起動しません。対象側でネイティブに再開したい場合は、対応するアダプターのランチャーかチェーン経路を使ってください。公式インポートに対応しているのは Claude Code から Codex デスクトップへの 1 経路だけです。

ドキュメントに「最初のタスク説明は保持されていない」とあるのはなぜですか？

--last N を使うと、Watch は後ろから N 番目のユーザーターンから切り出すため、それより前のターン（最初のタスク説明を含む）は省略されます。背景をすべて含めたい場合は --last を外すか、--since-compact とより高いプリセットを使ってください。本文には実際に行われたトリミングが項目ごとに書かれます。

対象のアシスタントはネイティブセッションと同じようには続けられません。

いいえ。渡されるのは要約ドキュメントで、ネイティブの再開機能は引き継がれず、トリミングされたツール実行の詳細も見えません。最初のターンでタスクの目的と現在のブランチを復唱させ、理解を確認してから編集を割り当ててください。
