Claude Code のコンテキストウィンドウ満杯と使用上限: 実践ガイド

コンテキストウィンドウがいっぱいとは、この会話が長すぎるということです。Claude Code 内で /compact または /clear を実行してください。アカウント上限はリセット時刻を示し、そのとき /compact は何もしません。Watch はウィンドウを広げず、枠も戻しません。まだ実行できる別のエージェントへ、保存済みセッションをコピーします。

Claude Code の複雑な作業が中断されたとき、コンテキストウィンドウの枯渇とアカウント使用枠を見分け、/compact か Watch のマルチエージェントセッション引き継ぎかを適切に使う方法を学びます。

公開日: 2026-09-21 更新日: 2026-10-14 対象バージョン: Watch v0.1.475
操作上の重要な境界: 二つの異なる物理的上限

1. コンテキストウィンドウ上限: 一つのセッションでモデルが同時に処理できるトークン総数を制限します。いっぱいになると、モデルは圧縮を促すか、履歴を自動で圧縮します。 2. アカウント使用上限: 移動する時間枠（例: 5 時間ごとのリセットや週間枠）での要求総量またはトークン消費を制限します。達すると、Claude はリセット時刻とともに "You have exceeded your current usage limit" を表示します。

開発者は、いっぱいのコンテキストウィンドウとアカウントのレート制限を混同したり、セッション引き継ぎツールが Claude のコンテキストウィンドウを人工的に広げると思ったりしがちです。Watch は使用枠を回避せず、Claude のネイティブな圧縮も置き換えません。違いを理解すれば、正しい回復経路を選べます。

  1. 手順 1: ターミナルのエラー表示で上限の種類を見分ける

    Claude がリセット時刻とともに "exceeded your limit" と報告するなら、アカウントの使用上限です。モデルの枠が尽きたため /compact は失敗します。リセットを待つか、Codex / OpenCode へ引き継ぎます。Claude が会話の長さの上限や高い遅延を報告するなら、コンテキストウィンドウ上限です。/compact を実行します。

  2. 手順 2: コンテキスト長にはネイティブの対処を使う（/compact と /clear）

    Claude Code 内で /compact を実行し、会話履歴を要約へ圧縮します。過去の調査ターンが不要なら、/clear を実行して現在のワークスペースで白紙から始めます。

  3. 手順 3: アカウント使用枠に達したらセッション状態を保存する

    Claude Code がセッション記録を ~/.claude/projects/<enc-cwd>/<session-id>.jsonl へ書き出したことを確認します。Watch で作業ディレクトリと、Codex または OpenCode の対象の準備状況を調べます。

  4. 手順 4: コンテキストを繰り返さず別のエージェントへ引き継ぐ

    Watch を使い、記録された推論とテスト結果を宛先エージェントの形式へ変換し、先行するコンテキストを保ったまま新しい CLI で再開します。

制限の種類典型的なエラーと症状対処方法とコマンドWatch が必要か
コンテキスト超過（Context Limit）Prompt too long for context windowClaude ターミナルで /compact による圧縮、または /clear で消去不要（ツール内部で処理）
5 時間のアカウント上限（5-Hour Limit）5-hour limit reached. Resets at HH:MM/compact は無効。リセットを待つかツールを切り替える必要（Codex / OpenCode へ引き継ぎ）
週間の組織クォータ超過（Weekly Quota）Weekly usage limit reached for org/compact は無効。別の利用可能なエージェントへ引き継ぐ必要（他の候補エージェントへ引き継ぎ）
ターミナルやネットワークの中断（Crash / Restart）Process exit / Terminal closedclaude --resume <id> を実行して元のセッションを再開不要（ネイティブ CLI で再開できる）

安全上の制約と免責

1. Watch は単一エージェントのコンテキストを広げません。新しいエージェントでの再開は、そのエージェント自身のコンテキストウィンドウ上限に従います。 2. ツール表現は変わります。スキーマ解析エラーを防ぐため、Claude の tool_use イベントは Codex で構造化テキスト表現に劣化します。 3. プロセスを急に終了しないでください。ターミナルウィンドウを閉じる前に、セッションファイルが書き込まれていることを確認します。

よくある質問

/compact はディスク上のコード変更を破棄しますか。

いいえ。ファイル編集はすでにローカルファイルシステムにあります。/compact が圧縮するのはメモリ上の会話履歴だけです。ただし、詳細な下位エラーメッセージは要約されることがあります。

アカウント使用上限に達すると、なぜ /compact は失敗しますか。

/compact は会話履歴を整理するためのもので、アカウントの利用枠は回復しません。利用枠を使い切ると、要約の生成リクエストも制限で止まることがあります。リセットを待つか、まだ使えるツールを選び、検証済みの経路で引き継いでください。watch prompt でトリミングした引き継ぎドキュメントを出力し、手動で対象ツールに渡す方法もあります。Watch は利用枠を回復したり回避したりしません。

Codex や OpenCode へ引き継ぐとコンテキストはリセットされますか。

引き継ぎは保存済みで変換できる履歴を対象セッションに持ち込みますが、その履歴は引き継ぎ先モデルのコンテキストを消費します。Watch はウィンドウを広げず、対象のトークン予算に合わせた自動要約もしないため、コンテキストの飽和が解消される保証はありません。入力を短くしたい場合は、対象ツールのネイティブ圧縮を使うか、watch prompt のプリセットと --last で短い引き継ぎドキュメントを出力し、省略の開示を確認してください。
