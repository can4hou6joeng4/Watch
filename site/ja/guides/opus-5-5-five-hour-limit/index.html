Claude Opus 5.5 が 5 時間上限について変えることと、それでも制限されているときの対処

Opus 5.5 は Pro、Max、Team、シートベースの Enterprise の 5 時間上限を引き上げ、保存できるリセットを一つ追加します。上限自体はなくしません。Watch は Claude の枠を読まず、引き上げもしません。その公式リセットでも足りない場合にだけ、保存済みセッションを Codex へ渡してください。

Opus 5.5 は名前のある Claude プランの 5 時間使用上限を引き上げ、保存できるレート制限リセットを追加します。Watch は Claude の枠を戻しません。それでもブロックされているなら、既存の Codex 引き継ぎを使います。

公開日: 2026-09-23 更新日: 2026-10-14 対象バージョン: Watch v0.1.501
発表が実際に変えること

2026 年 9 月 22 日、Anthropic は Claude Opus 5.5 を発表しました。上限について発表が述べるのは二つです。Pro、Max、Team、シートベースの Enterprise プランで 5 時間使用上限が上がること、そしてサブスクリプション利用者は保存して好きなときに使えるレート制限リセットを受け取ることです。週間上限がなくなったとは述べておらず、第三者ツールが Claude の枠を補充できるとも述べていません。

より速く、またはより安いモデルでも、二つの上限は一つになりません。いっぱいのコンテキストウィンドウは依然として長い会話です。Claude Code 内で圧縮してください。アカウント使用上限は、枠がリセットされるまで要求を止めます。Opus 5.5 は上記プランの 5 時間使用枠を広げます。コンテキストウィンドウは広げません。

  1. 手順 1: 製品がどの上限を報告しているかを読む

    リセット時刻とともに現在の使用上限を超えたというメッセージは、アカウント上限です。/compact はその枠を戻しません。会話の長さに関するメッセージはコンテキストウィンドウ上限です。Claude Code 内で圧縮してください。モデル名の切り替えは、どちらの場合の修正でもありません。

  2. 手順 2: プラン自身の 5 時間上限と保存済みリセットを使う

    引き上げられた 5 時間上限は Pro、Max、Team、シートベースの Enterprise に適用されます。保存できるリセットは Claude のサブスクリプションに属します。Watch はそれを保存する CLI フラグを検証していないので、Watch のコマンドがリセットを預かっていると思わないでください。Anthropic が提供するリセットの後もブロックされるなら、別のエージェントを検討します。

  3. 手順 3: Claude がまだブロックされている場合だけ引き継ぐ

    Watch は Claude の枠を読まず、引き上げず、回避もしません。ディスクにすでに保存されたセッションを、作業ディレクトリを保ったまま Codex へコピーします。既存のガイド「Claude Code が使用上限に達した後、Codex で続ける」に従ってください。セッション id とディレクトリを確認し、その後 prepare、confirm し、Codex を別に開きます。

急上昇クエリが立証しないこと

検索語 “opus 5.5” は、48 時間のシンガポールとオーストラリアのトレンド検索に現れました。これはおおよそのトレンド区分であり、検索量の世界的な順位ではなく、週間上限、コンテキスト長、セッションファイルが変わったことも示しません。同じニュース周期の他のモデル名は、この引き継ぎと無関係です。ツール呼び出しは Codex 側で依然としてテキストに劣化することがあります。

よくある質問

Claude Opus 5.5 は 5 時間使用上限をなくしますか。

いいえ。Anthropic は Pro、Max、Team、シートベースの Enterprise の 5 時間上限を引き上げました。上限はまだあり、達するとリセット時刻が表示されます。

Watch は保存できるレート制限リセットを代わりに使えますか。

いいえ。その操作は Claude のサブスクリプションに属します。Watch は Claude アカウントにサインインせず、リセットを保存も消費もしません。

上限が上がった後も、セッションを Codex に渡しますか。

公式リセットでは足りず、Codex にまだ枠があるときだけです。引き継ぎの手順は Opus 5.5 で変わっていません。
