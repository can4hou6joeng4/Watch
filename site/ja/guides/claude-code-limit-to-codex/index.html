Claude Code が使用上限に達した後、Codex で続ける

Claude Code が 5 時間または週間の上限を報告しても、/compact は枠を戻しません。Watch はローカルの ~/.claude/projects/<encoded-cwd>/<session>.jsonl だけを読み、作業ディレクトリを確認し、その記録を Codex にコピーします。元のファイルは変わりません。ツールイベントはテキストになることがあります。

Claude Code が使用上限（5 時間の枠または週間枠）に達するか、調査が行き詰まったとき、このガイドは作業ディレクトリとセッション履歴を保ち、公式のインポート計画を準備し、Watch 経由で OpenAI Codex に再開する方法を説明します。

公開日: 2026-09-17 更新日: 2026-10-14 対象バージョン: Watch v0.1.405
操作上の重要な境界

使用上限は、ある時間枠で Claude をどれだけ使えるかを制限します。一方、コンテキストウィンドウの上限は一つの会話の容量を制限します。コンテキストウィンドウがいっぱいなだけなら、Claude Code 内で /compact または /clear を使います。アカウントの使用上限に達してエージェントを切り替える必要がある場合、Watch は保存済みのローカルセッション履歴を Codex に渡します。Watch は上限を回避せず、ローカルリポジトリのファイルも変更しません。

長いエンジニアリング作業の途中で、Claude Code はリセット時刻とともにプラン上限へ達したと報告することがあります。それまでに積もった推論、失敗した反復、コマンド出力はディスクに残ります。Watch はこの保存済みセッションを OpenAI Codex につなぎ、調査を手で要約しなくても、新しいツールが先行するコンテキストを確認できるようにします。

  1. 手順 1: 元のセッション ID と作業ディレクトリを確認

    アクティブな Claude Code のセッション ID を探します。履歴は ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl にあります。worktree とリポジトリのずれを防ぐため、ディレクトリパス（cwd）が実際のプロジェクトのワークスペースと一致することを確認してください。

  2. 手順 2: 対象プロジェクトが Codex Desktop に存在することを確認

    このガイドは Watch の --desktop-project 経路を使うため、プロジェクトが Codex Desktop に登録され、app-server に同期されている必要があります。プランを準備する前に、Codex Desktop で対象ディレクトリを開いてください。これはこのデスクトップ引き継ぎ経路のガードです。

  3. 手順 3: インポート計画を準備する（Prepare）

    Watch デスクトップでソースセッションを選び OpenAI Codex をクリックするか、prepare を実行します。Watch はソース、作業ディレクトリ、出力先、Codex のバージョンを確認し、ローカルのインポートプランを保存します。この時点ではセッションのインポートを送信せず、確認段階で使う Watch のターゲットロックも取得しません。ネイティブのバージョン確認が独自のランタイムファイルを更新することがあるため、全体が書き込みゼロの操作とは言えません。

  4. 手順 4: インポートを確定し、劣化項目を確認する（Confirm）

    プレビューされたメッセージ数、作業ディレクトリ、ツール呼び出しの痕跡を確認します。明示的に確定すると、ローカルの Codex app-server インポートプロトコルで転送が始まります。ツール呼び出しイベントはテキスト表現に劣化することがあります。

  5. 手順 5: 対象クライアントを独立して起動する（Open）

    確定したら、アプリの画面または再開コマンドで Codex Desktop を開きます。インポートと起動は厳密に分かれています。起動に失敗した場合は、インポート段階を繰り返さず起動だけを再試行します。

# 1. 環境を確認してローカルプランを保存（セッションのインポートは送信しない） npm run watch -- import-codex prepare <claude-id> --cwd /abs/project/path --desktop-project --experimental --json # 2. 明示的に確認して書き込む（プランが返す planId を使う） npm run watch -- import-codex confirm <plan-id> --experimental --json # 3. ローカル実行ログを読み取り専用で確認（ネイティブクライアントは起動しない） npm run watch -- import-codex status <plan-id> --json
高頻度レート制限のエラー原文対応表（Error Signatures）

ターミナルに次のようなメッセージが出た場合、単一セッションのコンテキスト容量ではなく、アカウント単位の利用上限に達しています： • "You have reached your 5-hour limit for Claude 3.7 Sonnet / Opus. Limit will reset at 14:30." • "Weekly usage limit reached. Your quota resets on Monday at 00:00 UTC." • "Rate limit exceeded for organization. Please wait before retrying." このような場合、Claude Code 内で /compact を実行しても、利用枠はリセットも解放もされません。

Claude Code のセッション記録は ~/.claude/projects/<エンコードされたディレクトリ>/<セッション>.jsonl に保存されます。Watch のインポート時、Claude 形式の tool_use や tool_result といったツール呼び出しイベントは、構造化された読み取り専用のテキストレコードとして Codex の rollout ログに書き込まれます。これにより引き継ぎ先のエージェントは調査の履歴を漏れなく参照でき、Codex の状態機械を壊すようなネイティブ構造の偽造も避けられます。

安全上の制約と免責

1. 無損失の保証はありません。ツール呼び出しの構造は Codex でプレーンテキストに劣化し、モデルによる続行は限定的な検証範囲の外です。 2. 不確実な状態では停止します。処理が中断またはタイムアウトした場合、ロックは保持されます。ロックを強制削除したり再送したりせず、status コマンドで確認してください。 3. ローカル変換は完全なオフラインではありません。Watch は外部サーバーなしで動作しますが、Codex は自身の app-server デーモンを起動し、上流のモデルプロバイダーで認証します。

よくある質問

Watch は Claude Code のレート制限を回避またはリセットしますか。

いいえ。Watch はローカルの引き継ぎツールです。Anthropic アカウントを改ざんしたりクレジットを注入したりせず、ローカルに保存されたセッション成果物を、まだ容量のある別のエージェントへ渡します。

すぐに Codex へ続きのコーディングを依頼できますか。

Codex はインポートされた会話履歴を確認しますが、再開した作業でのモデルの振る舞いは対象エージェントのコンテキスト容量に依存します。新しいコード編集を任せる前に、Codex へ現在の目的を要約させることを勧めます。

インポートを二度送るとどうなりますか。

Watch は永続ロックと計画の冪等性を適用します。同じ元とディレクトリへの重複した prepare 要求は、レコードを複製せず既存の計画を返します。
