resume で開くと空のセッション：0 ターンセッションの見分け方と復元

resume で空のセッションが開くのは、そのセッションファイルに続けられる対話がないためです。watch new が作った正規の空セッション、内容が消えてプレースホルダーのヘッダーだけが残ったもの、0 バイトのファイルが考えられます。watch status のチェーン末尾の行でターン数を確認してください。Watch が履歴を再構築することはなく、バックアップからの復元、別のセッションへの再バインド、新しいチェーンのいずれかになります。

Watch はチェーン末尾のセッションを作業ディレクトリごと対象ツールに渡し、resume コマンド自体は開くだけです。このガイドは status のチェーン末尾の行から始め、読み取り可能な 0 ターンセッションと 0 バイトのファイルを区別し、バックアップからの復元、adopt による再バインド、新しいチェーンの 3 つの方法を示します。

公開日: 2026-11-17 更新日: 2026-11-23 対象バージョン: Watch v0.1.394
主な違い

resume（および各クライアントのネイティブ再開コマンド）がするのは、指定したセッションを開くことだけです。続けられるかどうかは、そのセッションファイルに残っている対話の量で決まります。ファイルがあって読めることは、内容があることを意味しません。これが「正常に見えるのに、開くと何もない」という状態の正体です。Watch は v0.1.84 以降、open / switch / new / status の各入口でこの区別を開示しています。

セッションファイルの「空」には 2 種類あります。ひとつは読み取り可能な 0 ターンで、正しいセッションヘッダー（Claude Code のプレースホルダーの user 行、Codex rollout の session_meta）はあるものの対話のターンがありません。もうひとつは 0 バイトで、プロセスが強制終了された、ディスクが満杯になった、書き込みが途中で止まったなどによりファイル自体が空です。次の手順はそれぞれ異なります。0 ターンはまだ始まっていないだけのことも、内容が消されたこともあります。0 バイトはセッションのメタデータまで失われている可能性があり、Codex の帰属は rollout の先頭行に書かれているため、0 バイトに切り詰めると逆引きも失敗します。

「開いても空」には、ファイルがすでに存在しない場合もあります。Claude Code は cleanupPeriodDays に従って、セッション開始後に期限切れの transcript を削除します。公式のデフォルトは 30 日で、このキーは任意の設定ファイルに書け、プロジェクト設定がユーザー設定を上書きできます。期限切れのセッションは /resume に表示されなくなり、Watch の open や resume でも見つかりません。watch doctor はユーザー設定、カレントディレクトリのプロジェクト設定、通常の Git リポジトリのサブディレクトリではリポジトリルートのローカル設定（scope は repository-local）を読み取り専用で確認し、デフォルトを下回る場合や確認できない場合に警告します。実際に有効な値として提示することはなく、--settings と管理設定は対象外です。保持期間を延ばしても今後の削除が減るだけで、すでに削除されたファイルは戻りません。重要なセッションは事前にバックアップしてください。

  1. ステップ 1：status のチェーン末尾の行を確認する

    watch status を実行します。チェーン末尾の行は v0.1.90 以降、ターン数を表示します（例：「← チェーン末尾（12 ターン）」）。0 ターンと解析された場合は「（0 ターンと解析。理由は上の警告を参照）」と表示し、ファイルが読めない、または存在しない場合はターン数を出しません。JSON では chainTipTurns と chainTipEmpty の 2 フィールドに対応し、chainTipTurns は解析が成功したときだけ存在します。チェーンが複数ある場合、watch chain list のチェーン末尾の行にも同じターン数が付きます（v0.1.93）。判断に迷うときは、watch doctor の store.emptyTips が 0 ターンと解析されたチェーン末尾を一覧します（v0.1.92）。watch new の --json も実際に解析されたターン数を返します（v0.1.94）。claude / pi はプレースホルダーの user 行を 1 つ書き込むため 1 ターン、codex / grok / opencode は 0 ターンです。watch usage は v0.1.95 以降、「0 ターンと解析された空のセッション」と「内容はあるが usage が記録されていないセッション」を分けて扱い、作成直後の空のチェーンが統計の欠落と誤報されなくなりました。v0.1.96 以降、内容ファイルの不正行と Codex の圧縮記録は空のセッションとして扱われません。v0.1.97 以降、サイドカーの usage が読める場合でも、内容ファイルの削除を「対話が失われた」と明示します。v0.1.98 以降、内容の不正行は警告とフィールドで開示され、黙って落とされません。v0.1.99 以降、ターンがあるセッションの不正行は「0 ターンと解析」と表現されません。v0.1.100 以降、テキスト要約は 0 ターンと usage 既読を分けて扱い、不正行のスキャンに失敗した場合は件数が不明であると説明します。v0.1.101 以降、0 ターンの要約に「usage は合計済み」を付けず、v0.1.98 の記述も訂正しています。

  2. ステップ 2：警告の区分ごとに理由を読む

    同じ結果でも、警告は「0 バイト（セッションファイルが空）」「読み取り可能な 0 ターン（0 ターンと解析。続けられる対話がない）」「ファイルが読めない（権限または内容の問題）」「ファイルが存在しない（削除または移動）」「内容の解析に失敗（ファイルは読めるが、セッション形式が壊れている、または OpenCode のデータベースに本文テーブルがないなど。v0.1.279 以降は『内容の解析に失敗し、Watch はターン数と終了状態を確認できなかった』と表示）」を区別します。5 つの区分では次の手順が異なるため、「空」という言葉だけで再バインドしないでください。ファイルが存在しない場合はまずファイルを探し、0 バイトの場合はバックアップの有無を確認します。解析に失敗した区分は「空かどうか」すら分からないため、空のセッションとして扱わず、まず watch switch か watch open で一度開き、プリフライトに具体的な理由を出させてください。

  3. ステップ 3：作成直後の空のセッションかどうかを確認する

    watch new <provider> が作るセッションはもともと空で、最初のチェーンの正常な出発点です。次の switch か open --to がこれを対象にして、ソースの内容を統合します。チェーン末尾がこの新しいセッションで、まだ切り替えていない場合、0 ターンは想定どおりで、破損ではありません。

  4. ステップ 4：原因に応じて復元する

    内容が消えた場合：バックアップからそのファイルを復元し、resume を再試行します（Watch は履歴を再構築しません）。セッションを間違えた場合：watch adopt <provider> --session <別のセッション id> でチェーン末尾を再バインドします。両方を残したい場合：watch chain new <新しい名前> で新しいチェーンを始め、元のチェーンの記録はそのままにします。0 バイトでバックアップもない場合：そのセッションに復元できる内容はないため、新しいセッションとして扱います。

# 1. チェーン末尾のターン数と警告を確認（v0.1.90 以降、チェーン末尾の行にターン数） npm run watch -- status --json # 2. チェーン末尾が空のセッションの場合の 3 つの道 npm run watch -- adopt <provider> --session <another-session-id> # 別のセッションへ再バインド npm run watch -- chain new <new-chain-name> # 新しいチェーンを開始 # 3. バックアップがある場合は先にファイルを復元してから resume を再試行 npm run watch -- switch <provider>
境界と安全上の制限

1. Watch は履歴を再構築しません。0 ターンのセッションはバックアップからしか戻せず、ツールが対話内容を補筆することはありません。 2. Watch が 0 バイトのファイルを自動で削除・修復することはありません。それはユーザーのネイティブなセッションファイルであり、復元するか諦めるかはユーザーが決めます。 3. 読み取り可能な 0 ターンは「消された」とは限りません。watch new が作る正規の空セッションも同じ形なので、ターン数だけでなく文脈で判断してください。 4. これらの開示はローカルファイルを読んだ結論であり、ネイティブクライアントがそのセッションを開けることを保証するものではありません。クライアントの受け入れ状況は、各バージョンとプラットフォームごとに個別に記録します。

よくある質問

resume で何も開かないとき、Watch が履歴を失ったのでしょうか？

ほとんどの場合そうではありません。Watch は引き継ぎ時にソースを読み、書き込み前ガードとアトミック書き込みで対象に追記します。0 ターンのセッションはもともと空だった（watch new が作った空のセッション）か、それ以前に消去・切り詰められたものです。Watch の書き込みが原因かを確かめるには、引き継ぎ結果のターン数と warnings を見て、バックアップのファイルと比較してください。

0 ターンと 0 バイトはどう違いますか？

0 ターンはファイルが読めて正しいセッションヘッダーがあるものの対話がない状態で、新しいセッションか、プレースホルダーのヘッダーだけが残ったものかもしれません。0 バイトはファイル自体が空で、プロセスが強制終了された、ディスクが満杯、書き込みが半分で止まったなどが原因で、セッションのメタデータまで失われている可能性があります。前者はまだ始まっていないだけかもしれませんが、後者はまずバックアップを探してください。

Watch は消されたセッションを自動で復元できますか？

いいえ。Watch はローカルのセッションファイルを読み書きするだけで、履歴のバックアップ機能はなく、対話をでっち上げることもありません。復元はユーザー自身のバックアップ（Time Machine、git の外のコピー、エディタの履歴など）から行い、ファイルを戻してから resume してください。

Claude Code は古いセッションを自分で削除しますか？

はい。公式 settings の cleanupPeriodDays はデフォルト 30 日で、セッション開始後にバックグラウンドで期限を超えた transcript を削除し、期限切れのセッションは /resume に表示されなくなります。このキーは任意の設定ファイルに書けるため、プロジェクト設定がユーザー設定を上書きできます。watch doctor はユーザー設定、カレントディレクトリのプロジェクト設定、リポジトリルートのローカル設定を読み取り専用で確認しますが、--settings と管理設定は対象外で、レポートは実際に有効な値ではありません。値を大きくしても今後の削除が減るだけで、すでに削除されたファイルは戻りません。
