UNDER THE HOOD
中核の仕組み
保護は経路ごとに異なります。狭い検査は普遍的な安全保証ではありません。デスクトップアプリには四つの画面（セッション引き継ぎ、引き継ぎ履歴、対応経路、設定）と、ライト、ダーク、システムの外観があります。
01
元と cwd を特定
ネイティブのセッション ID で保存済みレコードを探し、実際の cwd を保ちます。既存の worktree をリポジトリルートへ黙って置き換えません。
02
公式インポートを確定
Codex 経路は対象ディレクトリと設定を結び、実行記録と永続ロックを持ちます。不確実な結果は照会し、盲目的に再送しません。
03
形式の限界を明示
記録されたメッセージとイベントを対象の形式へ移します。保持の程度は異なり、内部の往復はネイティブ続行の証明ではありません。
04
インポートと起動を分ける
インポート後に起動が失敗したら、起動だけを再試行します。ターミナルの起動に失敗した場合は、再転送せず制御文字を確認したうえでコマンドのコピーに戻ります。

ANSWERS FIRST
ガイド
各ガイドは単独で読める答えから始まり、その後に手順が続きます。Watch は上限を回避せず、モデルを順位付けしません。
Claude Code が使用上限に達した後、Codex で続ける
Claude Code が 5 時間または週間の上限を報告しても、/compact は枠を戻しません。Watch はローカルの ~/.claude/projects/<encoded-cwd>/<session>.jsonl だけを読み、作業ディレクトリを確認し、その記録を Codex にコピーします。元のファイルは変わりません。ツールイベントはテキストになることがあります。
ガイドを読む
OpenCode、Claude、Codex の双方向セッション引き継ぎガイド
OpenCode はセッションを ~/.local/share/opencode/opencode.db に置きます。WATCH_OPENCODE_DB は Watch を別のファイルへ向けます。Watch は sessions、messages、parts を一つの SQLite トランザクションで書き、失敗すればロールバックします。未対応のツールフィールドはテキストになります。その後の応答は設定したモデルに依存します。
ガイドを読む
Claude Code のコンテキストウィンドウ満杯と使用上限: 実践ガイド
コンテキストウィンドウがいっぱいとは、この会話が長すぎるということです。Claude Code 内で /compact または /clear を実行してください。アカウント上限はリセット時刻を示し、そのとき /compact は何もしません。Watch はウィンドウを広げず、枠も戻しません。まだ実行できる別のエージェントへ、保存済みセッションをコピーします。
ガイドを読む
Claude Opus 5.5 が 5 時間上限について変えることと、それでも制限されているときの対処
Opus 5.5 は Pro、Max、Team、シートベースの Enterprise の 5 時間上限を引き上げ、保存できるリセットを一つ追加します。上限自体はなくしません。Watch は Claude の枠を読まず、引き上げもしません。その公式リセットでも足りない場合にだけ、保存済みセッションを Codex へ渡してください。
ガイドを読む
resume で開くと空のセッション：0 ターンセッションの見分け方と復元
resume で空のセッションが開くのは、そのセッションファイルに続けられる対話がないためです。watch new が作った正規の空セッション、内容が消えてプレースホルダーのヘッダーだけが残ったもの、0 バイトのファイルが考えられます。watch status のチェーン末尾の行でターン数を確認してください。Watch が履歴を再構築することはなく、バックアップからの復元、別のセッションへの再バインド、新しいチェーンのいずれかになります。
ガイドを読む
アダプターがないときは watch prompt でセッションを引き継ぐ
対象ツールにアダプターがない、またはネイティブ形式が変わったばかりのときは、watch prompt <session-id> で読み取り専用の Markdown 引き継ぎドキュメントを生成します。セッションファイルを書かず、CLI も起動しません。トリミングの件数と縮退の説明は本文と --json の findings に入り、対象側はこれをネイティブセッションではなく要約として扱う必要があります。
ガイドを読む
Codex のセッションが .jsonl.zst だけになったとき：Watch の読み取り境界と復元経路
Codex がローカルのスレッドを圧縮すると、元の rollout は .jsonl.zst だけになります。Watch は圧縮形式を読まないため、これらのセッションはどの一覧にも現れません。watch doctor で「ディレクトリの帰属を判別できない」件数を確認し、Codex でそのスレッドを続けて再展開を促します。コピーが 0 バイトなら内容は失われており、バックアップから復元するしかありません。.zst ファイルは削除も改名もしないでください。

QUESTIONS & BOUNDARIES
質問
作業の途中で Claude Code が上限に達しました。どう続けますか。
Watch に元のセッション ID を入力し、検出された作業ディレクトリを確認して対象エージェントを選びます。Claude → Codex は公式のプロジェクト優先インポートのプレビューを表示し、確定した後だけ書き込み、対象は別に開きます。他の対象は既存の CLI アダプターを使います。Watch は使用上限を回避せず、コードも移動しません。保存済みのセッション記録を渡すだけです。
Claude Code から Codex に切り替えて、同じセッションを再開するには。
入口は二つです。デスクトップアプリで元セッションを選び OpenAI Codex カードをクリックするか（公式の単一セッションインポート: prepare → confirm → open）、watch import-codex prepare <claude-id> --cwd <project> --desktop-project --experimental を実行してから confirm します。プロジェクトはすでに Codex Desktop に存在している必要があります。ツール記録は Codex 側でテキストになることがあり、モデルによる続行は検証範囲の外です。
Claude Code のコンテキストウィンドウがいっぱいです。Watch は圧縮しますか。
いいえ。コンテキストの圧縮や消去は Claude Code 自身の /compact と /clear です。Watch は保存済みセッション記録をまとめて別のエージェントへ移します。対象セッションはその記録から始まり、元のセッションは変更されません。収まるかどうかは対象ツールのコンテキストウィンドウによります。
Claude Code、Codex、OpenCode のセッションファイルはどこにあり、以前の会話はどう再開しますか。
Claude Code: ~/.claude/projects/<encoded-cwd>/<session-id>.jsonl。claude --resume <id> で再開。Codex: ~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl。codex resume <id> で再開。OpenCode: ~/.local/share/opencode/opencode.db。opencode -s <id> で再開。Watch はセッション ID でこれらを探し、所属する作業ディレクトリを表示し、そのディレクトリの連鎖した引き継ぎを引き継ぎ履歴に一覧します。
watch status に表示されるセッションが、resume 後に空なのはなぜですか？
resume は既存のセッションを開くだけです。空になるのは、そのセッションファイルに続けられる対話が残っていない場合がほとんどです。watch new が作る正規の空セッション、内容が消えてプレースホルダーのヘッダーだけが残ったもの、0 バイトのファイルが該当します。watch status のチェーン末尾の行でターン数を確認してください。0 ターンのときは Watch が理由を開示します。Watch が履歴を再構築することはありません。バックアップからファイルを復元する、watch adopt で別のセッションに再バインドする、watch chain new で新しいチェーンを始める、のいずれかになります。
watch doctor の Claude Code クリーンアップ警告は確実ですか？
チェーン末尾ファイルの更新時刻と、設定の優先順位で採用される cleanupPeriodDays から推定したリスクであり、削除の事実ではありません。明示設定が公式デフォルトの 30 日を下回り、かつチェーン末尾が Claude Code のセッションである場合にだけ表示します。より優先度の高い設定に上書きされた短い値では警告しません。上位の設定が読めない場合も、下位の値で推測しません。ワークツリーとサブモジュールではメインのチェックアウトのリポジトリルート設定を調べないため、推定は保守的になることがあります。実際に有効な値は Claude Code が読み込むすべての設定に依存し、--settings と管理設定は対象外です。チェーン末尾のファイルをバックアップし、保持期間を延ばすか、watch switch で再バインドしてください。--strict は警告も失敗として扱います。
Claude Code と Codex の両方を使っています。コンテキストを失わずに行き来するには。
Watch は両者を順位付けしません。両方をインストールして認証していれば、セッションを渡せます。Claude → Codex は公式インポートのプレビューを、Codex → Claude は CLI アダプター変換を使い、どちらも作業ディレクトリを保ちます。一部のイベントは形式の間で劣化する可能性があり、結果には劣化した内容が列挙されます。
履歴は Watch のクラウドサーバーを通りますか。
Watch に独自の中継サーバーはありません。一部のネイティブセッション作成経路は対象 CLI を起動し、そのネットワークサービスにアクセスすることがあります。モデルによる続行もそのサービスのプライバシーとモデルの規則に従います。ローカル変換は、完全にオフラインの作業を意味しません。
変換は無損失、または無リスクですか。
いいえ。新しいファイルとファイル全体の置換には原子的な書き込みと解析し直しの検査があり、一部の追記経路は保護が異なります。公式の Codex インポートは独自の記録、対象ロック、読み戻し検証を使います。正確な境界はアーキテクチャを見てください。
