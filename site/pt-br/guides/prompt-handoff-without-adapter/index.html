Usar watch prompt quando não há adaptador

Quando a ferramenta de destino não tem adaptador ou seu formato nativo acabou de mudar, execute watch prompt <session-id> para montar uma transferência Markdown somente leitura. Ele não grava arquivos de sessão nem inicia nenhuma CLI; as contagens de corte e degradações ficam no documento e nos findings do --json, e o destino deve tratá-lo como resumo, não como sessão nativa.

watch prompt transforma registros de sessão nativos locais em uma transferência Markdown resumida, sem gravar nenhum arquivo nem iniciar a CLI de destino. O destino não herda a retomada nativa, e cada corte e estado de origem é registrado no documento e nos findings.

Publicado: 2026-11-18 Atualizado: 2026-11-18 Aplica-se a: Watch v0.1.496
Quando usar este caminho

Os três caminhos nativos de transferência (lançador, transferência em cadeia e importação oficial do Codex) exigem um adaptador e um formato de destino verificável. Quando a CLI de destino ainda não tem adaptador, seu formato nativo acabou de mudar, ou você só quer entregar contexto a um assistente web, use watch prompt para produzir um resumo somente leitura. Não é uma sessão nativa, apenas material de transferência copiável e revisável.

watch prompt lê apenas o registro de sessão local do assistente de origem e renderiza turnos, eventos de ferramenta e um manifesto de trabalho em Markdown. O cabeçalho nomeia o assistente de origem, o ID da sessão, o arquivo de origem, o diretório de trabalho, o tipo de worktree e a branch atual; o corpo informa quantos turnos foram cortados, o que foi omitido e se o uso pode estar subcontado. O comando não grava arquivos de sessão, não abre banco de dados e não inicia nenhuma CLI.

  1. Passo 1: identificar a sessão de origem e o diretório

    Passe o ID da sessão explicitamente, ou passe --cwd e omita o ID. Sem ID, o Watch escolhe a sessão legível mais recente no diretório atual e a marca no cabeçalho como escolhida automaticamente; em caso de dúvida, informe o ID para que outra sessão não seja confundida com a origem.

  2. Passo 2: escolher um perfil e uma janela

    --profile minimal|standard|verbose|full controla quanto texto e quantos eventos de ferramenta são expandidos. --last N mantém apenas os N turnos de usuário mais recentes e descarta a descrição original da tarefa, o que o documento declara. --since-compact começa no resumo de compactação mais recente; quando não há resumo utilizável, ele não corta e diz isso.

  3. Passo 3: revisar findings e estado da origem

    --json inclui markdown, findings e warnings no resultado. degraded significa que a degradação foi divulgada, skipped que conteúdo foi omitido pelas suas opções. As linhas de estado da origem, linhas defeituosas, uso e branch no documento dizem se é seguro transferir. Um diretório de trabalho de origem indisponível é retornado como sourceCwd: { state } (missing, not-directory, denied ou unknown, com reason para unknown); um diretório saudável não emite esse campo. Uma raiz de repositório normal retorna sourceBranch ({ branch, repoRoot }; um HEAD destacado retorna { detached: true, repoRoot }) e um worktree vinculado retorna sourceWorktree ({ mainWorktree, branch }). Se o tamanho ou o horário de modificação do arquivo de origem mudar entre as verificações, sourceDrift ({ from, to, growth }) relata bytes e a direção do crescimento. Isso não estabelece quais registros chegaram ao documento. Chamadas de ferramenta explicitamente falhas são retornadas como failedAttempts (ferramenta, caminho ou comando e contagem, nunca a saída da ferramenta), com a seção 「Falhas e interrupções (Failures and interruptions)」 no documento. No momento da renderização, a visão geral de mudanças também verifica se os arquivos listados ainda estão no diretório da sessão: um arquivo confirmado como sumido é marcado como não estando mais no disco, um que não pode ser confirmado como não verificado, um arquivo excluído ou movido pelo patch da sessão é rotulado como tal, e caminhos fora do diretório da sessão são contados à parte; o cabeçalho da seção diz quantos foram verificados, ou por que a verificação não rodou. --json acrescenta manifestDisk (checked, missing, unverified, outside, removed) para que scripts nunca leiam um campo ausente como 「tudo presente」. Chamadas de ferramenta não concluídas e uma última mensagem do usuário sem resposta são informadas por stats.danglingToolCalls, stats.unansweredTail e findings correspondentes; a primeira conta a sessão inteira e a segunda só se aplica quando o último turno do usuário tem texto real. Ambas aparecem nos metadados e na seção Continue working do documento, com os mesmos campos em --json.

  4. Passo 4: declarar que é uma transferência resumida

    Cole o Markdown ou salve como arquivo e diga ao assistente de destino no primeiro turno que se trata de uma transferência resumida, não de uma sessão nativa. O destino não consegue retomar nativamente, e chamadas de ferramenta, raciocínio e anexos podem ter sido cortados; o que foi omitido não pode ser recuperado do documento.

# 1. Escolher automaticamente a sessão mais recente do diretório atual no perfil standard npm run watch -- prompt --cwd /abs/project # 2. Nomear a sessão e manter apenas os 5 turnos de usuário mais recentes npm run watch -- prompt <session-id> --cwd /abs/project --last 5 # 3. Emitir JSON para revisar os findings junto com o documento npm run watch -- prompt <session-id> --cwd /abs/project --json
Limites

1. Somente leitura: não grava arquivos de sessão, não abre banco de dados local e não inicia CLI de destino; você decide como entregar o Markdown. 2. Um resumo não é uma sessão nativa: chamadas de ferramenta, raciocínio e anexos podem ser cortados, e partes omitidas não podem ser recuperadas do documento. 3. Cortes são contados: omissões por perfil, --last e --since-compact entram no corpo e nos findings; sem resumo, ele não corta e diz isso. 4. Uma origem com 0 turno ou danificada não é relatada como sucesso: o corpo declara origem vazia ou linhas defeituosas, e uso ou contagem de linhas ilegíveis são marcados como possivelmente subcontados ou não confirmados.

Perguntas frequentes

O watch prompt grava na sessão da ferramenta de destino?

Não. Ele apenas lê o registro de origem e imprime Markdown; não grava arquivo de sessão de destino, não abre banco de dados e não inicia CLI. Quando você precisa de retomada nativa no destino, use o lançador ou o caminho em cadeia para esse adaptador; o único caminho oficial de importação é Claude Code para o Codex Desktop.

Por que o documento diz que a descrição original da tarefa não foi mantida?

Com --last N, o Watch começa no N-ésimo turno de usuário a partir do fim, então turnos anteriores, incluindo a descrição original da tarefa, ficam de fora. Remova --last para ter todo o contexto, ou use --since-compact com um perfil maior; o corpo lista cada corte que realmente ocorreu.

O assistente de destino consegue continuar exatamente como uma sessão nativa?

Não. Ele recebe um documento resumido sem retomada nativa e não vê detalhes cortados da execução das ferramentas. Peça no primeiro turno que ele repita o objetivo da tarefa e a branch atual, e só então atribua edições.
