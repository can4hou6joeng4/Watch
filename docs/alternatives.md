## 中文

按交接产物和使用场景选择工具。第三方条目依据项目公开说明，Watch 的支持范围以[兼容性记录](COMPATIBILITY.md)为准。

| 需要什么 | 可参考的项目 |
| --- | --- |
| 把本机记录转成目标工具的原生格式 | [cross_agent_session_resumer](https://github.com/Dicklesworthstone/cross_agent_session_resumer)、[session-migrate](https://github.com/xhluca/session-migrate) 提供原生会话格式转换。[catchup](https://github.com/wilbeibi/catchup) 侧重转录文本，也提供 `fork` 和 `fork --into`。 |
| 在桌面端同步，或在额度用尽前自动接班 | [ccx](https://github.com/AaronWong1999/ccx) 用 macOS 菜单栏在 Claude Code、Codex 与 Antigravity 桌面端之间同步会话，并提醒额度。[Sno Station](https://github.com/sno-ai/sno-station) 通过 `rotate-agent` 生成交接记录，让另一 Agent 从同一提交继续。 |
| 生成可阅读或可分享的交接材料 | [continues](https://github.com/yigitkonur/cli-continues) 读取 16 家 CLI 的本地记录，生成结构化交接文档并在目标工具中继续，`--debug-prompt` 可只查看交接提示词。[ai-session-to-md](https://github.com/avbel/ai-session-to-md) 把 Claude Code、Codex、OpenCode 的会话转成 Markdown 交接文档。[context-ledger](https://github.com/PricePepel/context-ledger) 导入选定的 JSONL 记录后生成标注原始行号的 Markdown 交接，本地服务只绑定回环地址。[ThreadPort](https://github.com/Frankie-Xu/threadport) 用可校验的 Capsule 记录可观察的工作状态。[ACDC](https://github.com/awithi-co/acdc) 以 Skill 交接结构化摘要，支持按名称或 UUID 找回历史。[handoff](https://github.com/rosehgal/handoff) 为项目维护人类可读的交接文档。[session-handoff](https://github.com/yuzushi-dev/session-handoff) 是 Claude Code / Codex 双端插件，生成可校验的交接文档，也支持迁移两端可移植的会话历史；其恢复指标为合成评测，不能当成原生格式写回保证。[claude-handoff](https://github.com/REMvisual/claude-handoff) 的交接文档固定保留失败尝试、被否定的决策与证据，写入前做字段自校验，不达标就不替换原上下文。[Relayvora](https://github.com/Dagimassefa/Relayvora) 先跑项目检查，再生成带来源标注的摘要，并支持通过 Git 仓库分享。[codex-session-handoff-skill](https://github.com/Liu-Bot24/codex-session-handoff-skill) 为 Codex 单独整理本机交接快照与索引，新会话按提示词读取快照；交接目录不写进项目。 |
| 回溯交接、索引历史或审计存储 | [Möbius](https://github.com/TardisBooo/Mobius) 用交接图回溯来源会话和消息范围。[agent-sessions](https://github.com/jazzyalex/agent-sessions) 分开显示索引、刷新、失败、筛选无结果与真正空库。[deja-vu](https://github.com/vshulcz/deja-vu) 只读审计本地 Agent 存储，并提示 `cleanupPeriodDays` 对会话记录的影响。[sessionFlow](https://github.com/HarryHeYu/sessionFlow) 把多家 CLI 的记录增量索引进本地 FTS5，并编译带目标、文件、命令与停点的上下文包。[ai-session-hub](https://github.com/VangelisHaha/ai-session-hub) 以 Rust CLI / MCP 索引本地日志，生成 Markdown 交接包与恢复命令，源会话只读。 |
| 用统一契约跟踪跨会话目标与完成审计 | [Agent Handoff Toolkit](https://github.com/redducklabs/agent-handoff-toolkit) 用带版本的交接契约保存目标与下一步，完成审计必须单独执行，跳过的检查只能标为「未运行」。[SessionFlow](https://github.com/HarryHeYu/sessionFlow) 与 [ai-session-hub](https://github.com/VangelisHaha/ai-session-hub) 的交接包都明确不传输隐藏的工具状态。[project-continuity](https://github.com/seriousz158/project-continuity) 用单一 `.relay/CURRENT.md` 保存项目状态，写入需 revision CAS、writer lease 与幂等回执，`done` 必须有当前代际的验收证据，并区分「完成」与「合并 / 发布 / 部署」；它不解析 transcript，也不写目标原生会话。 |
| 从完整记录重建续接状态 | [agent-session-resume](https://github.com/hacktivist123/agent-session-resume) 是只读 Skill：按证据重建目标、DONE / PARTIALLY DONE / NOT DONE、停点与用户明确搁置的范围，并在转录与当前 Git / 文件冲突时披露；不写原生会话。[repo-context-ledger](https://github.com/gviiisen/repo-context-ledger) 维护按分支 / 工作树隔离的仓库账本与 Resume Capsule，用 tracked-file SHA-256 提示陈旧；它不是 transcript 导入器，也不要与 [context-ledger](https://github.com/PricePepel/context-ledger) 混淆。 |
| 把长期记忆与决策带到下一会话 | [PowerContext](https://github.com/oceanbase/powercontext) 把决策、约束、证据与进度存成带版本的 Scope 工件，交接按 Work Contract → Prepared Handoff → Acknowledgement → Task Outcome 流转；可本地 SQLite / 容器部署，也提供 HTTP / MCP 接入。 |
| 通过 Git 分支交接工作状态 | [agent-skills](https://github.com/n9hat/agent-skills) 的 `/bridge-handoff` 把目标、选择、未决问题与下一步写进 `.bridge/HANDOVER.md` 的短期 bridge 分支，队友拉取后运行 `/bridge-takeover` 核对并接管；交接只经已推送内容，不进主分支。 |
| 把项目和会话换到另一台 Mac | [Agent Handoff](https://github.com/pierback/agent-handoff) 先配对两台受信任的 Mac，同步 Git 项目快照，并移动 Codex 与 Claude Code 的会话上下文；目标已有本地改动时恢复到独立工作树。[baton](https://github.com/sukamenev/baton) 读取本地日志而非重写摘要，跨机 `push` 打包会话、改动文件与规则文件并端到端加密，冲突文件备份为 `.baton.bak`。[bb-plugin-handoff](https://github.com/vburojevic/bb-plugin-handoff) 生成与 provider 无关的转录加工作区状态，可预览文档、截取到指定消息，并把未提交改动打成补丁。Watch 只在本机接力，不传输项目或跨设备会话。 |

Watch 从本机原生会话记录和工作目录出发，由用户发起接力。各写入路径有独立的防护措施，具体取决于走启动器、链式接力还是 Codex 官方导入。目标缺少适配器时，可用 `watch prompt` 导出只读 Markdown 摘要。`status --json` 可从切换记录回溯会话血缘，桌面接力记录显示同一份计数。桌面近期列表区分扫描中、读取失败和空列表。各路径的防护范围见[架构说明](ARCHITECTURE.md)。

[herdr-agent-handoff](https://github.com/sanirudh17/herdr-agent-handoff) 从 Herdr 的源窗格定位会话，在另一个 Agent 的新窗格交接。完整转录放不进提示词时，它提供来源路径、行范围和 SHA-256 供核对。Watch 的 `prompt` 交付 Markdown 摘要，并比较读取前后的文件大小和修改时间来提示来源有变化。

[ccompactor](https://github.com/ccompactor/ccompactor) 从 Claude Code、Codex 和 Pi 的本机记录生成带事件引用的交接包。`verify` 检查交接包的结构，并对照源转录核验引用。Watch 的 `prompt` 提供可复制的 Markdown 摘要和裁剪披露。

Choose by the handoff output and workflow you need. Third-party entries describe what each project documents publicly. See the [compatibility records](COMPATIBILITY.md) for Watch's validated scope.

| What you need | Projects to look at |
| --- | --- |
| Convert local records into the target's native format | [cross_agent_session_resumer](https://github.com/Dicklesworthstone/cross_agent_session_resumer) and [session-migrate](https://github.com/xhluca/session-migrate) convert native session formats. [catchup](https://github.com/wilbeibi/catchup) focuses on transcripts and also offers `fork` and `fork --into`. |
| Sync desktop sessions or rotate agents before a usage limit | [ccx](https://github.com/AaronWong1999/ccx) syncs sessions across Claude Code, Codex and Antigravity desktop apps from the macOS menu bar and warns about usage limits. [Sno Station](https://github.com/sno-ai/sno-station) uses `rotate-agent` to write a handover so another agent can continue from the same commit. |
| Generate readable or shareable handoff notes | [continues](https://github.com/yigitkonur/cli-continues) reads local records from 16 CLIs, builds a structured handoff document and continues in the target tool; `--debug-prompt` shows just the handoff prompt. [ai-session-to-md](https://github.com/avbel/ai-session-to-md) turns Claude Code, Codex and OpenCode sessions into Markdown handoff documents. [context-ledger](https://github.com/PricePepel/context-ledger) imports selected JSONL transcripts and builds Markdown handoffs that cite original line numbers, with its local server bound to the loopback address. [ThreadPort](https://github.com/Frankie-Xu/threadport) captures observable work state in a verifiable Capsule. [ACDC](https://github.com/awithi-co/acdc) passes structured summaries through a Skill and retrieves history by name or UUID. [handoff](https://github.com/rosehgal/handoff) maintains a human-readable handoff document per project. [session-handoff](https://github.com/yuzushi-dev/session-handoff) is a dual Claude Code / Codex plugin that builds a validated handoff document and can migrate portable conversation history between the two clients; its recovery figures come from a synthetic pilot, not a guarantee of native-format writeback. [claude-handoff](https://github.com/REMvisual/claude-handoff) keeps failed attempts, rejected decisions and evidence in its handoff, and self-validates the document before replacing the original context. [Relayvora](https://github.com/Dagimassefa/Relayvora) runs project checks, labels the sources in its summaries and supports sharing through Git repositories. [codex-session-handoff-skill](https://github.com/Liu-Bot24/codex-session-handoff-skill) is Codex-only: it writes a local handoff snapshot and index outside the project, then gives the next session a prompt to read them. |
| Trace handoffs, index history, or audit local storage | [Möbius](https://github.com/TardisBooo/Mobius) traces handoffs to source sessions and message ranges. [agent-sessions](https://github.com/jazzyalex/agent-sessions) distinguishes indexing, refresh, failures, filtered-out results and an empty library. [deja-vu](https://github.com/vshulcz/deja-vu) offers a read-only audit of local agent stores and highlights how `cleanupPeriodDays` affects transcripts. [sessionFlow](https://github.com/HarryHeYu/sessionFlow) incrementally indexes records from many CLIs into a local FTS5 index and compiles context packages with goal, files, commands and stopping point. [ai-session-hub](https://github.com/VangelisHaha/ai-session-hub) indexes local logs through a Rust CLI / MCP server and builds Markdown handoff packages with resume commands while keeping source sessions read-only. |
| Track cross-session goals with a shared contract and completion audit | [Agent Handoff Toolkit](https://github.com/redducklabs/agent-handoff-toolkit) keeps the goal and next action in a versioned handoff contract; completion must be audited separately, and skipped checks can only be marked as not run. [SessionFlow](https://github.com/HarryHeYu/sessionFlow) and [ai-session-hub](https://github.com/VangelisHaha/ai-session-hub) both state that their handoff packages do not transfer hidden tool state. [project-continuity](https://github.com/seriousz158/project-continuity) keeps project state in one `.relay/CURRENT.md` with revision CAS, a writer lease and idempotent receipts; `done` requires current-generation verification evidence and is distinct from merged / released / deployed. It parses no transcript and writes no native target session. |
| Rebuild resume state from the full record | [agent-session-resume](https://github.com/hacktivist123/agent-session-resume) is a read-only Skill that reconstructs goals, DONE / PARTIALLY DONE / NOT DONE, stopping points and explicitly deferred scope from cited evidence, and discloses conflicts between the transcript and current Git / files; it writes no native session. [repo-context-ledger](https://github.com/gviiisen/repo-context-ledger) maintains branch / worktree-isolated repository ledgers and Resume Capsules with tracked-file SHA-256 freshness checks; it is not a transcript importer and is distinct from [context-ledger](https://github.com/PricePepel/context-ledger). |
| Carry long-term memory and decisions into the next session | [PowerContext](https://github.com/oceanbase/powercontext) stores decisions, constraints, evidence and progress as revisioned artifacts in isolated Scopes; handoff moves through Work Contract → Prepared Handoff → Acknowledgement → Task Outcome and can run on local SQLite, containers, HTTP or MCP. |
| Hand over work state through Git branches | [agent-skills](https://github.com/n9hat/agent-skills) provides `/bridge-handoff`, which writes the goal, choices, open questions and next actions into `.bridge/HANDOVER.md` on a short-lived bridge branch; a teammate pulls it and runs `/bridge-takeover` to verify and continue. Watch starts from local native session records and the working directory. The user initiates each handoff. The launcher, chained handoff and official Codex import have separate entry points and write protections. Use `watch prompt` for a read-only Markdown summary when the target lacks an adapter. `status --json` traces lineage from recorded switches, with the same counts in desktop handoff history. The desktop recent list distinguishes scanning, read failures and an empty list. See the [architecture](ARCHITECTURE.md) for the protection each route provides.

[herdr-agent-handoff](https://github.com/sanirudh17/herdr-agent-handoff) locates a session from its source pane and hands it off to a fresh agent pane in Herdr. If the full transcript exceeds the prompt budget, the plugin provides the source path, line bounds and SHA-256 for verification. Watch `prompt` produces a Markdown summary and compares file size and modification time before and after reading to flag source changes.

[ccompactor](https://github.com/ccompactor/ccompactor) creates handoff packages with event references from local Claude Code, Codex, and Pi records. Its `verify` command checks package structure and checks quotes against the source transcript. Watch `prompt` provides a Markdown summary with disclosures about trimmed content.
